## D. 설계 판정 (구조·해석)

### D-1. 반경 시뮬 — 프로토타입 방식이지 OnePitch 확정이 아니다

`00_개요.md`(리그팀) §4-1이 "현재 전 리그가 예외 적용: 전부 풀 시뮬 확정"이라 못박았고 `07_매치_엔진.md` §11도 "배경 경기도 풀 연산"이라 재확인. **배경 경기를 승률 시그모이드로 퉁치면 안 되고 모든 경기가 최소 타석 단위로 실제 시뮬돼야 한다**(화면에 안 보여줄 뿐). (§6-5)

> ⚠ **02.SvelteElectron 통합 시 핵심 대조점** — SvelteElectron의 `DESIGN.md` §2는 정반대로 반경 시뮬이 핵심 원칙이다. 172팀 채택 결정에 따라 이 항목이 SvelteElectron 쪽에서 폐기·재정의 대상이 된다.

### D-2. 배경 엔진 vs 인터랙티브 엔진의 이원 구조

- 배경(NPC vs NPC)은 **타석 단위 확률 판정**(`simulate_plate_appearance`), 주인공 등판은 **1구 단위 볼카운트 시뮬**.
- 두 엔진이 갈라지지 않게 하는 방법: **인플레이 이후 세분화 로직(`resolve_in_play_result`)을 공유 원시 함수로 추출**해 양쪽이 같은 함수를 호출.
- 그럼에도 K/BB 배분은 구조적으로 갈린다(1구 단위 볼카운트 특유). 안타율은 거의 일치 → **득점에 직결되는 축만 맞추고 K/BB 격차는 허용폭으로 관리**하는 게 현실적.
- 주인공 팀이 타석에 설 때는 1구 단위로 쪼갤 이유가 없어 **배경 하프이닝을 통째로 재사용**(주인공은 DH라 절대 타석에 안 섬).

### D-3. 순수 함수 / DB 접근 분리

`sim::*` 모듈은 **DB에 접근하지 않는 순수 함수**로 두고, DB 읽기·쓰기는 전부 repository 계층. 부상 이벤트도 매치 엔진은 `InjuryEvent`를 반환만 하고 실제 `npc.injury` UPDATE는 repository 책임. 이 규율이 테스트 가능성과 결정성을 지탱했다.

### D-4. 완봉 확률이 S등급 비율을 지배한다 (등급 경계로는 못 낮춘다)

`grade_outing`은 **실점/기대실점 비율**로 판정하는데 `runs_allowed = 0`이면 기대실점이 무엇이든 `ratio = 0`이라 **항상 S**. 따라서:
- 등급 경계 수치를 아무리 재설계해도 **완봉 확률(=볼카운트 공식이 결정) 이하로 S등급 비율을 낮출 수 없다.**
- 실제로 K/BB 격차를 완전히 정합시켰더니 볼넷이 줄어 완봉이 흔해져 **S등급 6.5% → 29%로 폭등**했고, 기대실점 base를 조정해도 F/D 비율만 이동했을 뿐 S는 그대로였다.
- 최종 절충: 정합을 포기하고 **존 안 헛스윙 기준치만 0.15→0.19**(K 격차 9.1→7.0%p 개선, S등급 6.5→10%).

### D-5. 결정적 RNG 규약

`league_sub_seed(world_seed, "네임스페이스:키")` 패턴으로 **용도별 RNG 스트림을 완전히 분리**. 예: `match:{game_id}` · `weather:{game_id}` · `steal:{game_id}:{pitch_seq}` · `growth:{npc_id}:{day}` · `event_body:{id}:{day}` · `digest:{day}` · `draft:` vs `redraft:`. 스트림이 섞이면 한쪽 변경이 무관한 쪽 결과를 바꾼다.

### D-6. 스키마리스 JSON 컬럼의 효용

`season_stats.line`·`practice_stats`·`npc_season_history`를 **키-값 JSON**으로 두니, 수비 기록(기회·실책) 같은 새 지표를 **마이그레이션 없이** 추가할 수 있었고 시즌 아카이브(전체 키 합산)도 자동으로 따라왔다. 반대로 SQL로 직접 필터링해야 하는 값(`military_return_day`, `retired`, `handedness`)은 **plain 컬럼**으로 둬야 한다.

### D-7. 172팀 균등 원칙

어떤 신규 코드도 팀을 "특별/배경"으로 차등 취급하지 않는다. 로스터 생성·특성 배정·재정 계산 전부 전 172팀 동일 절차. 하드코딩 팀군 예외 금지.

### D-8. 세이브 슬롯

**파일 = 슬롯**, 고정 3슬롯(`slot_1.db` ~ `slot_3.db`). 타임스탬프 파일명은 무한 증식 문제를 낳는다. 마이그레이션은 파일을 열 때마다 자동 적용(별도 `migrateSlot` 커맨드 불필요).
