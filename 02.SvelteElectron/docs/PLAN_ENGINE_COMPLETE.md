# 경기 엔진 완성 — 엔진과 화면을 짝지어

> 실측 2026-08-30 · 엔진 28,347줄(경기 2,827줄) · vitest 1,372건 · cargo 250건 통과

빠진 야구 사건을 **엔진에 제대로** 넣고, **그 값이 화면까지 이어지게** 한다.

🔴 **엔진만 채우면 절반이다.** 이 저장소에서 반복된 결함이 정확히 그
형태였다 — 값은 만들어지는데 쓰는 데가 없다:

- 피홈런: "엔진은 처음부터 홈런을 따로 만들었는데 안 세고 있었다"
- 장타: "안타 하나로 뭉개서 SLG가 근사였다"
- 수비 기록: "선수별로 한 건도 안 쌓이고 있었다"
- 선발 여부: "화면 넷이 GS를 표시하는데 전원 0이었다"
- 스카우팅: "Rust·preload·타입까지 다 있는데 TS가 한 번도 안 불렀다"
- 애니메이션 큐: **지금도 그렇다** — 6종을 보내는데 화면이 하나만 쓴다

**그래서 단계마다 엔진과 화면을 한 쌍으로 묶는다.** 화면에 안 닿는
단계는 없다.

---

## 지금 상태

### 엔진이 이미 주는데 화면이 안 쓰는 것

```
AnimationCue 6종
  BallPitch      투구            ← 화면이 쓴다(tweenBall)
  BallBatted     타구 from·to·arc·hitType·duration
  FielderMove    수비수 이동
  BallThrow      송구
  RunnerAdvance  주자 진루 runnerId·toBase
  ShowResult     결과 표시

FieldingResult
  fielder        누가 잡았나
  threwTo        어디로 던졌나
  isError        실책인가
  runnerExtraAdvance
```

⚠ **화면은 `tweenBall`(공 이동) 하나만 쓴다.** 나머지는 받아서 버린다.
수비 9명은 고정된 알(`stoneMark`)이고 송구선도 없다.

### 경기 화면 구성

```
MatchPage.svelte              경기 진행·투구 선택·로그
  BaseballField.svelte  345줄  구장 그림 + 알 + 존 미리보기
  GameStatusModal.svelte       경기 중 기록표
```

로그는 `narrativeLogs`를 그대로 찍는다 — **문자열이라 집계는 못 한다.**
"견제사"·"히트앤런 실패"도 거기 문자열로만 들어간다.

## 빠진 것 — 열둘

| 사건 | 엔진 | 화면 | 규모 |
|---|---|---|---|
| 도루자 기록 `cs` | 판정은 돈다 · **기록 칸 없음** | 기록표에 칸 | 작음 |
| 구종별 기록 | 없음 (`pitch_type`은 있다) | 투수 상세 | 작음 |
| 이닝별 투수 기록 | 없음 (현재 이닝은 안다) | 경기 화면 | 작음 |
| 삼중살 | 없음 | 연출 3동작 | 작음 |
| 보크 | 없음 | 로그 + 주자 이동 | 작음 |
| 폭투 | 없음 | 공이 빠지는 연출 | 중간 |
| 포일 | 없음 | 포수가 놓치는 연출 | 중간 |
| 낫아웃 | 없음 | 타자가 뛰는 연출 | 중간 |
| 태그업 | 없음 | 주자 대기 → 출발 | 중간 |
| 수비·주루 방해 | 없음 | 로그 | 중간 |
| **타구 물리** | 없음 | **궤적·낙하** | 큼 |
| 대타·대주자 | 없음 (타자 큐 없음) | 교체 표시 | 큼 |

## 단계

### 0단계 — 화면이 있는 큐를 다 쓴다

🔴 **이걸 먼저 해야 나머지 단계가 눈에 보인다.** 삼중살을 만들어도
화면이 못 그리면 확인할 방법이 없다.

**엔진** 안 건드림.

**화면**
- 타구가 포물선을 그린다 (`arc`가 이미 온다 · 지금 직선)
- 수비수가 공 쪽으로 움직인다 (`FielderMove`)
- 송구선이 보인다 (`BallThrow`)
- 병살이 두 동작으로 보인다 (큐 순서가 이미 다르다)
- 번트·실책 연출 (`hitType: Bunt` · `isError`)

⚠ **알(바둑알) 그대로 간다** (사용자 확정). 스프라이트 14장이
`resource/sprites/field-overview/`에 있지만 안 쓴다.

**검증** 알이 실제로 움직이는지 · 큐 종류별로 다른 연출이 나오는지

---

### 1단계 — 기록 확장

**엔진**
- 타자 줄에 `cs`(도루자) — 판정은 이미 돈다
- 투수 줄에 구종별 카운터 (`decision.pitch_type`이 매 투구에 있다)
- 투수 줄에 이닝별 배열

**화면**
- 기록표에 도루자 칸 (`GameStatusModal` · `StatusPage` · `LeaguePage`)
- 투수 상세에 구종별 표 (`PlayerDetailModal`)
- 경기 화면에 이닝별 투구수

⚠ **밸런스에 안 닿는다** — 세기만 하고 판정을 안 바꾼다.

**검증** 리그 도루자 합계 > 0 · 구종별 합이 총 투구수와 같은가

---

### 2단계 — 단순 사건 넷

**엔진** (결과 코드 추가 + 판정 + 기록 + 진루)
- 삼중살 — 병살 옆. 주자 둘 + 무사
- 보크 — 견제 자리 옆(이번에 견제사를 만든 그 자리). 주자 한 칸씩
- 폭투 — Phase A. 착탄이 크게 빗나감 + 주자 진루
- 포일 — 포수 능력치가 이미 있다(도루에 쓰임)

**화면**
- 삼중살 3동작 연출
- 폭투·포일에서 공이 포수를 지나치는 연출 + 주자 이동
- 로그 문구

⚠ 폭투와 포일은 **누구 책임인지가 다르다** — 투수 기록과 포수 기록이
갈린다. 실제 야구가 그렇다.

**검증** 각 사건이 한 시즌에 몇 건 나오나 (실제 KBO와 대조)

---

### 3단계 — 🛑 밸런스 고정

**여러 씨앗으로 지금 지표를 못박는다.** 이번 세션에 감독·작전이
들어가면서 지표가 움직였는데 **씨앗 편차와 아직 못 갈랐다**:

```
리그 ERA   5.94 → 5.51
평균 OPS   0.942 → 0.915
9이닝당BB  3.6 → 3.7
```

⚠ 이 상태로 타구 물리를 넣으면 홈런이 는 게 **물리 때문인지 앞선
작업 때문인지 영영 못 가린다.**

**할 일** 씨앗 3~5개 × 리그 전체 · 타율·ERA·홈런·장타율·도루 분포를
문서에 못박는다.

---

### 4단계 — 타구 물리

**엔진**

① 구장 데이터 — `stadiums.csv`에 27개가 `park_factor`(타자친화·중립·
투수친화)로 이미 분류돼 있다. **담장 거리를 그 성격에 맞춰 채운다** —
지어내는 게 아니라 이미 있는 설정을 숫자로 푸는 일이다.

```
지금   id, name, park_factor
필요   + 좌·중·우 담장 거리 + 펜스 높이      27 × 4 = 108개 값
```

② 타구 속도·발사각

```
지금   hardness: u8            1~5 정수
필요   exit_velocity: f64      타구 속도
       launch_angle: f64       발사각
       spray_angle: f64        좌우 (지금은 zone으로 뭉뚱그림)
```

입력은 그대로다 — 컨택 품질과 파워로 `hardness`를 만들던 자리에서
세밀한 값을 낸다.

③ 비행 계산 — 속도·각도 → 낙하 지점. 담장 거리를 대면 홈런·펜스직격·
뜬공이 갈린다. 날씨(바람)가 이미 경기 상태에 있어 얹을 수 있다.

**화면**
- 타구가 실제 거리만큼 날아간다
- 담장에 맞는 게 보인다
- 비거리 표시 ("128m")

⚠ **여기가 리그 홈런·장타율을 통째로 움직인다.** 3단계 기준선과
대조해서 얼마나 움직였는지 반드시 잰다.

**검증** 구장별 홈런 수가 `park_factor`와 같은 방향인가

---

### 5단계 — 물리에 딸린 것

**엔진** 그라운드 홈런(담장 안 낙하 + 주력) · 펜스 직격 · 수비 시프트

**화면** 주자가 다 도는 연출 · 펜스 맞고 튀는 공 · 시프트된 수비 위치

---

### 6단계 — 나머지 사건

**엔진** 낫아웃 · 태그업 · 수비·주루 방해

**화면** 타자가 1루로 뛰는 연출 · 주자 대기 후 출발 · 로그

---

### 7단계 — 대타 · 대주자

**엔진** 타자 큐. **`PitcherQueue`가 이미 같은 일을 한다** — 교체 판정·
기록·상태 갈아끼우기가 다 있어서 그 패턴을 옮기면 된다.

⚠ **TS도 벤치를 넘겨야 한다.** 지금 `buildTeamRoster`가 라인업 9명만
만들고 벤치를 안 준다.

**화면** 교체 표시 · 라인업에 반영

---

## 각 단계 공통

1. **재현부터** — 지금 그런지 3회 재고 시작
2. **엔진 → 화면 → 검사** 순. 화면 없이 단계를 닫지 않는다
3. **변이 검증** — 배선을 빼면 검사가 실패해야 한다
4. **전후 실측 + 회귀** — vitest · cargo · tsc · svelte-check
5. **커밋**

⚠ Rust를 고치면 `npm run build:native` 후 **바이너리를 확인한다**
(`grep -a`로 새 문자열 · `strings`는 이 `.node`에서 안 통한다).
`Finished in 0.10s`는 캐시다.
