## 2. 도달률은 **경로를 안 밝히면 뜻이 없다**

단계 조건만으로 커리어 경로별 도달 가능 종수를 세면 이렇다:

```
  고교→독립            272 / 589   (46%)   ← measure:eventfunnel --nodraft 가 쓰는 경로
  고교→대학→독립        385 / 589   (65%)
  고교→프로            401 / 589   (68%)
  고교→프로→해외        416 / 589   (71%)
  고교→대학→프로        514 / 589   (87%)
```

**어느 경로로도 못 가는 것은 0종이다.** "구조적 도달 불가"는 종의 속성이
아니라 **경로의 속성**이다.

`--nodraft` 는 가장 좁은 경로를 강제한다. 그 경로에서 잰 값:

```
  뜬 종수 172.7 / 정의 589         = 29.3%
  뜬 종수 172.7 / 도달 가능 272    = 63.5%
```

⚠ 앞으로 도달률을 적을 때 **분모를 같이 적는다.** 안 그러면 29%·48%·52%·63%가
같은 문서에 섞인다 (이미 섞여 있다).

## 4. 영구 손실의 원인 — 주인공 시작 OVR 이 콘텐츠 사다리 위에 있다

고1 이벤트 셋이 영영 못 뜨는 이유를 재니 **미디어 알림 둘이 W1·W2 를 먹고**
있었다.

```
  p745  EVT_HS_MEDIA_OVR65_ALERT   pitching_ovr >= 65
  p740  EVT_HS_MEDIA_OVR60_ALERT   pitching_ovr >= 60
```

🔴 **주인공 시작 OVR 이 68~70 이다** (프리셋 넷 전부). 고교 단계
`pitching_ovr_gte` 조건 **16개 전부**가 첫 주부터 통과한다.

### 문턱을 올리는 안은 실측으로 버렸다

```
  measure:growth  →  주인공 고교 1년: OVR 70 → 71  (+1.00)
```

`generation_rules.json` 의 `"목표 곡선(시즌당 OVR): ~18 +4.5"` 는 **NPC 값**이다.
주인공은 그 4.5분의 1이라 고교 3년에 68 → 약 71~73 밖에 안 큰다. 문턱을
시작값 위로 올리면 **안 뜨거나(75+) 여전히 곧 뜨거나(71~72)** 둘 중 하나다.

### 🔴 A 에게 — 이건 B 가 못 고치는 자리다

```
  고교 NPC OVR 범위     45~70   generation_rules.json   (A 소유)
  주인공 시작 OVR       68~70   NewGamePage.svelte      (C 소유)
  고교 콘텐츠 사다리     48~65   events/**               (B 소유)
```

**주인공이 입학 첫날부터 리그 최상위권이다.** 콘텐츠 사다리는 훨씬 낮은
데서 시작하는 주인공을 가정하고 짜였다. B 는 사다리만 갖고 있어서 증상
처치밖에 못 한다 — 셋 중 어느 쪽이 맞는지는 A 가 정해야 한다.

⚠ `EVT_HS_Y1_SLOW_GROWTH` (`pitching_ovr_lte 52`, "성장이 더디다")는
**어떤 프리셋으로도 영영 못 뜬다.**

## 5. 이번 주 고친 것

### 5-1. priority — 일반 미디어 기사가 입학 서사를 밀어냈다

```
  EVT_HS_MEDIA_OVR65_ALERT   745 → 42
  EVT_HS_MEDIA_OVR60_ALERT   740 → 40
```

문턱(60·65)은 그대로 뒀다. 문안이 「구종 분석 기사」·「스카우트 카메라」라
이정표가 아니라 **바닥선**이고, 그건 시작부터 통과하는 게 맞다.
`once_per_season` 이라 51주 중 언젠가는 뜬다 — 잃는 게 없다.

### 5-2. 문안 오배선 셋

`MSG_COND_STAT_MILESTONE` 「시즌 5승 달성!」 하나를 규칙 넷이 공유했다.
라이벌·드래프트·스카우트가 전부 "5승 달성" 으로 떴다.

```
  EVT_HS_Y1_RIVAL_NOTICE       또래가 이름을 외웠다       탈삼진 30↑
  EVT_HS_Y3_DRAFT_STOCK_CHECK  지명 순위 이야기가 돈다    탈삼진 80↑
  EVT_HS_Y3_SCOUT_FOCUS        스카우트가 자리를 옮겼다   OVR 55↑
```

⚠ 공유 문안 32종 중 대부분은 정상이다 — 중간고사·시즌개막이 학년별로
나뉘어 같은 글을 쓰는 것. **내용이 안 맞는 건 이 셋이었다.**

### 5-3. 고1 초반 창을 어긋나게 폈다

W1~W6 에 `once_per_career` 넷이 창을 포개고 있었다. 자리는 주당 1칸이라
priority 로는 못 푼다 — **창이 겹친 게 문제**다.

```
                    전      후
  FIRST_TRAINING   1~3  →  1~3   (그대로)
  DORM_NIGHT       1~2  →  1~5
  WELCOME_DINNER   1~4  →  1~7
  POSITION         1~6  →  3~8   ← W1·W2 를 비웠다
```

⚠ 넷 다 `week_gte` 조건이 **원래 없었다.** 창을 여는 쪽은 `week_lte` 만
있었으니, 앞으로 창을 다룰 때 그 전제를 먼저 확인해라.

### 5-4. 아무 일도 안 하는 조건 6개 제거

```
  EVT_HS_LIFE_FATIGUE_ALERT   week_gte 1 · week_lte 156
  EVT_HS_LIFE_PEAK_FORM       같음
  EVT_HS_LIFE_SLUMP_CHECK     같음
```

156 = 52×3 으로 "고교 3년" 을 의도했지만 `week_lte` 는 `currentWeek`(1~52,
시즌마다 리셋)과 비교한다. **항상 참이라 읽는 사람만 속인다.**
`career_stage: highschool` 이 이미 그 일을 한다. 동작 변화 없음.


### 5-5. 🔴 창 조정은 절반만 들었다 — 순서로 짜낼 수 있는 건 여기까지다

3회씩 잰 값이다. **목표 지표(끝내 못 뜬)는 안 내려갔다.**

```
                    끝내 못 뜬          밀린 규칙 종수
  전 (원본)          6 · 6 · 6  = 6.0      54.3
  후1 (priority)     4 · 4 · 5  = 4.3      50.0
  후2 (창 조정)      5 · 6 · 3  = 4.7      48.0  (폭 0)
```

**총량은 그대로고 구성만 바뀌었다:**

```
  전     WELCOME_DINNER · DORM_NIGHT · HOMESICK
  후1    WELCOME_DINNER · DORM_NIGHT
  후2    DORM_NIGHT · HOMESICK          ← WELCOME_DINNER 는 살고 HOMESICK 이 밀렸다
```

창을 넓히면 그 이벤트가 **더 오래 후보로 남아 다른 것을 밀어낸다.**
`WELCOME_DINNER`(p70)가 1~7 로 늘면서 `HOMESICK`(p55, 1~10)을 3주 더 눌렀다.
자리가 주당 1칸이라 **제로섬**이다.

되돌리지 않았다 — 나쁘게 하지 않았고 `밀린 규칙 종수`가 50 → 48 로
고정(폭 0)됐다. 되돌리면 그것도 잃는다.

### 🔴 A 에게 — 남은 길 둘, 둘 다 B 소유가 아니다

고1 첫 8주에 `once_per_career` 넷이 들어가야 하는데 칸이 8개이고
그 8칸을 `repeatable` 상위권과도 나눠 쓴다.

| 길 | 내용 | 소유 |
|---|---|---|
| **주당 상한** | 시즌 초 몇 주만 conditional 을 2칸으로 | 밸런스 — A |
| **시작 OVR** | 68~70 을 낮추면 미디어 계열이 후보에서 빠져 칸이 는다 | C(프리셋)·A(범위) |

⚠ track-B 문서는 반대 자리에 도달해 있었다 — *"그 주에 뽑을 새 이야기가
아예 없었다"*. **지금은 옮길 대상은 있는데 칸이 없다.** 같은 상한의
양쪽 끝이다.

## 6. 계측할 때 데인 것 — 다음 사람이 안 겪게

### 🔴 `--runs N` 은 회차마다 데이터를 다시 읽는다

`measure-eventfunnel.cjs:65` 가 `spawnSync` 로 자기를 자식으로 띄운다.
자식은 부팅하며 `events/**` 를 새로 읽는다.

**회차 사이에 이벤트 JSON 을 고치면 3회 평균이 무의미해진다.** 실제로
회차 2·3 사이에 고쳐서 한 번 통째로 버렸다.

→ **계측이 도는 동안 데이터를 건드리지 마라.**

### 전후 비교는 `trap` 으로 되돌린다

```bash
trap 'git checkout $FIX -- $FILES' EXIT INT TERM
```

중간에 죽으면 저장소가 옛 상태로 남는다. 되돌리기를 `trap` 에 걸어야 안전하다.

### 분모를 확인해라

`measure-eventfunnel` 의 "정의" 는 `_manifest.json` 의 **파일 수**다
(`:224~228`). 단계로 거른 도달 가능 수가 아니다.
