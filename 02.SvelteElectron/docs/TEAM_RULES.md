# 세 트랙 공통 규칙 (2026-09-01)

> **A · B · C 세 세션이 같은 저장소에서 동시에 돈다.**
> 이 문서가 그 규칙의 정본이다. 어기면 하루가 병합과 재측정에 녹는다.
>
> 규칙은 전부 **실제로 당한 것**에서 나왔다. 근거를 같이 적었다 —
> 근거 없는 규칙은 지켜지지 않는다.

---

## 0. 통신 — **A 가 허브다**

```
B ──┐
    ├──→ A ──→ (판단 · 배분)
C ──┘
```

- **질문은 언제든 A 에게 보낸다.** 턴이 끝나기를 기다리지 마라.
  `SendMessage` 로 보내면 상대의 다음 도구 호출 때 도착한다.
- **B ↔ C 직접 대화 대신 A 를 거친다.** 셋이 각자 다른 판단을 하면
  같은 자리를 두 번 고치거나, 서로 반대로 고친다.
  ⚠ 급하면 직접 보내도 된다 — 다만 **A 에게도 같이 알려라.**
- **사용자를 거치지 마라.** 사용자에게 전달을 부탁하는 건 왕복이 두 배다.
  사용자 판단이 필요한 것(밸런스 수치 · 기획)만 A 가 모아서 묻는다.

### 무엇을 A 에게 보내나

```
막혔다            소유가 아닌 파일이 필요하다 · 답이 없으면 못 간다
찾았다            결함 · 문서가 틀린 것 · 계측이 거짓말하는 것
끝났다            그 트랙 일감이 비었다 → A 가 다음을 준다
틀렸다            A 가 준 지시나 숫자가 실측과 다르다  ← 이게 제일 값지다
```

**가르는 기준: 표시는 C, 계산은 A, 데이터는 B.**
⚠ 경계가 애매하면 **먼저 물어라.** 되돌리는 것보다 싸다.

### 남의 파일에 한 줄이 필요할 때

**직접 고치지 말고 요청해라.** 셀렉터 한 줄, 타입 한 칸이면
소유자가 같은 턴에 넣어 준다. 병합을 푸는 것보다 훨씬 싸다.

⚠ **예외 하나** — 그 한 줄을 안 고치면 `tsc` 나 `svelte-check` 가
**깨진 채로 남는** 경우. 그때는 고치고 **반드시 알려라.**

## 2. 🔴 `npm run build:native` 는 **A 만** 돌린다

Rust 빌드는 `.node` 파일 하나를 덮어쓴다. 둘이 동시에 돌리면
**파일 잠금으로 조용히 실패**하고, 고친 줄 알았는데 옛 바이너리를 잰다.

⚠ **이 저장소에서 네 번 걸렸다.** 마지막은 2026-09-01, A 가 측정이 도는
중에 빌드해 **전 측정을 통째로 버렸다**(파일 시각으로 알아챘다).

- B·C 는 Rust 가 바뀌면 A 가 알린다. 그때 `.node` 를 **복사해 쓴다.**
- **A 도 측정이 도는 중에는 안 빌드한다.** 전후를 잴 때는 빌드 대신
  **상수를 중립값으로 두고 재는** 쪽을 쓴다(되돌림 실수가 없다).

## 3. 🔴 회귀 — **커밋과 나눠서 돌린다**

```
① npx vitest run          ← 출력을 **읽는다**
② npx tsc --noEmit
③ cargo test (Rust 를 만졌으면)
④ 초록을 확인한 뒤 git commit
```

⚠ ①~④를 한 명령에 묶지 마라. A 가 2026-09-01 에 그렇게 했다가
**빨간불인 줄 모르고 커밋했다.** 순서는 지켰는데 출력을 안 봤다.

### 미커밋 변경을 오래 두지 마라

트리에 남의 미커밋 변경이 있으면 **다른 트랙이 회귀를 판정할 수 없다** —
빨간불이 자기 것인지 남의 것인지 매번 확인해야 한다.

- 하루 일감이 끝나면 커밋해라
- 중간이면 그 검사를 `.skip` 하고 **이유를 적어라**. 빨간불로 두지 마라

## 4. 🔴 검사 — 변이로 검증한다

**고친 곳을 되돌렸을 때 그 검사가 실패해야 한다.** 실패하지 않으면
그 검사는 아무것도 안 보고 있다.

⚠ 2026-09-01 하루에 **두 번** 반쪽 검사를 냈다:

```
계단↔연속 구분 못 함   26↔75 만 봐서 계단(0.92→1.10)도 같은 폭이 나왔다
                       26↔45 · 45↔49 를 보게 고치자 죽었다
상수만 보고 갈래를 안 봄  갈래에서 조건을 빼도 상수는 그대로라 통과했다
                       include_str! 로 갈래 자체를 보게 하나 더 붙였다
```

⚠ **`include_str!` 은 검사 자신도 담는다.** 문자열을 세면 자기 몫을 빼라.

## 5. 🔴 계측 — 거짓말하는 방식이 정해져 있다

이 저장소의 계측은 **조용히** 틀린다. 오류도 로그도 안 난다.

```
① 없는 경로를 읽으면 기본값이 된다
   `player.fielding.arm` 을 봤는데 실제는 `player.batting.arm` 이었다
   → 포수 500명이 전부 50 으로 보였고 "어깨는 문제없다"로 읽을 뻔했다

② 시점을 틀리면 0 이 나온다
   롤오버 **뒤**에 읽어 `leagueState.stats` 가 비었다 → 도루 0/0
   → "도루가 안 돈다"로 읽을 뻔했다. 시즌 종료 **앞**에서 잡아라

③ 모수를 틀리면 중앙이 달라진다
   포수를 **전 리그 506명**으로 셌다 → 중앙 63
   KBL 1군만 보면 74 다. 기준점을 엉뚱한 데 맞출 뻔했다

④ 중앙값과 전체 비율은 다른 질문이다
   선수별 타율 중앙 .256 ←→ 9이닝당 피안타 10.5 는 **성립하지 않는 조합**
   리그 전체(총안타/총타수)로 재니 .272 였다

⑤ 시즌 수를 안 보면 0 으로 보인다
   `--seasons` 기본값이 3 이라 프로 이벤트가 0종으로 나왔다 (B 가 겪음)
   **결과를 볼 때 시즌 수를 먼저 봐라**
```

### 규칙

- **3회씩 잰다.** 씨앗 하나로 판단하지 마라
- **적용 전후를 잰다.** 전을 안 재고 후만 보면 아무것도 모른다
- **가설을 세웠으면 그것부터 재라.** 이 저장소에서 가설이 틀린 적이 훨씬 많다
- **모수를 봐라.** 몇 명 중 몇인지 없는 비율은 뜻이 없다

```
"리그 타율 .307~.311"        실제 .274      계획 2주차를 통째로 잘못 배정했다
"타율 중앙 .319~.342"        실제 .246~.271
```

- 고친 뒤 낡은 문서에 **배너를 달아라.** 지우진 마라 —
  같은 증상이 다시 나면 그 계측이 필요하다
