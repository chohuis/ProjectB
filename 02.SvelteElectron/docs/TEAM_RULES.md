# 세 트랙 공통 규칙 (2026-09-01)

> **A · B · C 세 세션이 같은 저장소에서 동시에 돈다.**
> 이 문서가 그 규칙의 정본이다. 어기면 하루가 병합과 재측정에 녹는다.
>
> 규칙은 전부 **실제로 당한 것**에서 나왔다. 근거를 같이 적었다 —
> 근거 없는 규칙은 지켜지지 않는다.

---

## 0. 통신 — **A 가 허브다**

```
B ──┐
    ├──→ A ──→ (판단 · 배분)
C ──┘
```

- **질문은 언제든 A 에게 보낸다.** 턴이 끝나기를 기다리지 마라.
  `SendMessage` 로 보내면 상대의 다음 도구 호출 때 도착한다.
- **B ↔ C 직접 대화 대신 A 를 거친다.** 셋이 각자 다른 판단을 하면
  같은 자리를 두 번 고치거나, 서로 반대로 고친다.
  ⚠ 급하면 직접 보내도 된다 — 다만 **A 에게도 같이 알려라.**
- **사용자를 거치지 마라.** 사용자에게 전달을 부탁하는 건 왕복이 두 배다.
  사용자 판단이 필요한 것(밸런스 수치 · 기획)만 A 가 모아서 묻는다.

### 무엇을 A 에게 보내나

```
막혔다            소유가 아닌 파일이 필요하다 · 답이 없으면 못 간다
찾았다            결함 · 문서가 틀린 것 · 계측이 거짓말하는 것
끝났다            그 트랙 일감이 비었다 → A 가 다음을 준다
틀렸다            A 가 준 지시나 숫자가 실측과 다르다  ← 이게 제일 값지다
```

### 🔴 A 가 승인할 수 없는 것 — **사용자가 확정한 동작** (2026-09-01)

A 는 트랙을 조율하지만 **기획 결정을 대신할 수 없다.** 실제로 틀렸다:

```
B 가   훈련 소식이 소식함의 30% 를 먹는다 — 4주마다 묶겠다
A 가   "승인한다. 방식은 네 판단이다"        ← 여기가 틀렸다
       (대회 소식만 사용자에게 물었다)
사용자 "훈련도 그대로 둬"                    ← 둘 다 하지 말라는 것
```

B 가 로직을 다 짜고 C 가 화면 문구까지 조사한 뒤에 뒤집혔다. **세 트랙의
시간을 버렸다.**

- **"줄이면 좋겠다"는 A·B 의 판단이지 요구가 아니다.** 묻고 나서 승인한다
- 사용자가 날짜와 함께 확정한 동작(문서·커밋에 근거가 있는 것)은
  **A 도 못 바꾼다**
- 애매하면 **작업을 시작하기 전에** 묻는다 — 다 만든 뒤에 물으면
  답이 무엇이든 한쪽이 버려진다

⚠ 밸런스 수치는 원래부터 사용자 몫이다(`02/CLAUDE.md`). **동작·UX 도
같다**는 걸 이번에 배웠다.

소유자가 같은 턴에 넣어 준다. 병합을 푸는 것보다 훨씬 싸다.

⚠ **예외 하나** — 그 한 줄을 안 고치면 `tsc` 나 `svelte-check` 가
**깨진 채로 남는** 경우. 그때는 고치고 **반드시 알려라.**

## 2. 🔴 `npm run build:native` 는 **A 만** 돌린다

Rust 빌드는 `.node` 파일 하나를 덮어쓴다. 둘이 동시에 돌리면
**파일 잠금으로 조용히 실패**하고, 고친 줄 알았는데 옛 바이너리를 잰다.

⚠ **이 저장소에서 네 번 걸렸다.** 마지막은 2026-09-01, A 가 측정이 도는
중에 빌드해 **전 측정을 통째로 버렸다**(파일 시각으로 알아챘다).

- B·C 는 Rust 가 바뀌면 A 가 알린다. 그때 `.node` 를 **복사해 쓴다.**
- **A 도 측정이 도는 중에는 안 빌드한다.** 전후를 잴 때는 빌드 대신
  **상수를 중립값으로 두고 재는** 쪽을 쓴다(되돌림 실수가 없다).

### ⚠ **자기 측정도 자기 빌드를 막는다** (2026-09-01 · 다섯 번째)

A 가 `.node` 를 못 덮어 "B 가 잡고 있다"고 알렸는데, **A 자신의
`measure:batting` 이 아직 돌고 있었다.** 남 탓부터 하면 원인을 못 찾는다.

```
EPERM: unlink 'engine-native.win32-x64-msvc.node'
  → tasklist 로 electron 개수를 먼저 센다
  → 자기 백그라운드 작업 목록부터 본다
```

🔴 **긴 계측을 배경으로 돌리면 세 트랙에 알린다.** 누가 무엇을 잡고 있는지
모르면 서로를 의심하며 시간을 쓴다.

### ⚠ 빌드 뒤에 **바이너리를 확인한다**

```
파일 시각이 갱신됐나          ls -la packages/engine-native/*.node
EPERM · EBUSY 가 없었나       빌드 출력을 실제로 읽는다
`Finished in 0.10s` 는 캐시다  그것만 보고 넘어가지 마라
```

⚠ 크기는 안 바뀔 수 있다 — 작은 로직 변경이면 바이트 수가 같다.
**시각과 오류 유무**로 본다. 진짜 확인은 **실측**이다.

## 3. 🔴 회귀 — **커밋과 나눠서 돌린다**

```
① npx vitest run          ← 출력을 **읽는다**
② npx tsc --noEmit
③ cargo test (Rust 를 만졌으면)
④ 초록을 확인한 뒤 git commit
```

⚠ ①~④를 한 명령에 묶지 마라. A 가 2026-09-01 에 그렇게 했다가
**빨간불인 줄 모르고 커밋했다.** 순서는 지켰는데 출력을 안 봤다.

### 미커밋 변경을 오래 두지 마라

트리에 남의 미커밋 변경이 있으면 **다른 트랙이 회귀를 판정할 수 없다** —
빨간불이 자기 것인지 남의 것인지 매번 확인해야 한다.

- 하루 일감이 끝나면 커밋해라
- 중간이면 그 검사를 `.skip` 하고 **이유를 적어라**. 빨간불로 두지 마라

### 🔴 병합은 **양방향이다** — 이걸 놓쳐서 옛 데이터로 쟀다 (2026-09-01)

A 가 트렁크지만 **B·C 의 커밋을 받아 가는 것도 A 몫이다.** 실제로 한쪽만
흘렀다:

```
B → A   한 번도 안 일어났다      B 커밋 4개 · 이벤트·문안 파일 120개가 A 트리에 없었다
A → B   B 가 여러 번 merge 했다
```

🔴 그 상태로 A 가 **대학 축 고침의 전후를 재고 있었다.** 이벤트 데이터는
번들이 아니라 **런타임에 파일에서 읽으므로**, 남의 데이터가 없으면 다른
세계를 재는 것이다.

⚠ 그리고 같은 결론에 **둘이 따로 도달해 일을 두 번 했다** — B 가 지운
`week_lte 156` 세 건을 A 의 새 검사가 다시 찾아냈다.

- **측정 전에 `git merge` 로 세 트랙을 맞춘다.** 안 맞추면 남의 데이터
  없이 잰다
- ⚠ **측정이 도는 중에는 병합하지 마라.** 소스는 boot 때 번들되어 안전하지만
  `resource/data/master/events` 는 런타임에 읽는다 — 병합이 그 자리에서
  데이터를 갈아치운다
- 남에게 "받아 가라"고 말하는 것도 커밋한 쪽 몫이다

### ⚠ 워크트리가 갈리면 이 규칙의 범위가 달라진다 (2026-09-01)

위 규칙은 **같은 트리를 전제**한다. B 는 `ProjectB-events` 워크트리에서
돈다 — 그러면 **B 의 미커밋 변경은 A 에게 애초에 안 보인다.**

```
같은 트리   미커밋이 남의 회귀·계측을 오염시킨다   →  빨리 커밋해라
다른 트리   미커밋은 서로 안 보인다               →  제약은 **커밋 시점에만**
```

🔴 그래서 **"고쳐 두되 커밋하지 마라"는 다른 트리에는 무의미한 지시다.**
A 가 실제로 그렇게 지시했고 B 가 §3 을 근거로 거절했는데, 결과는 맞았지만
이유는 달랐다. **남에게 대기를 걸기 전에 같은 트리인지부터 확인해라** —
아니면 상대가 할 수 있는 일을 못 하고 기다린다.

⚠ 다만 **측정이 도는 중에 커밋을 받는 것**은 여전히 위험하다. 두 변수가
동시에 움직이면 원인을 못 가린다. 대기를 걸어야 할 때는 **커밋 시점에**
건다.

## 4. 🔴 검사 — 변이로 검증한다

**고친 곳을 되돌렸을 때 그 검사가 실패해야 한다.** 실패하지 않으면
그 검사는 아무것도 안 보고 있다.

⚠ 2026-09-01 하루에 **두 번** 반쪽 검사를 냈다:

```
계단↔연속 구분 못 함   26↔75 만 봐서 계단(0.92→1.10)도 같은 폭이 나왔다
                       26↔45 · 45↔49 를 보게 고치자 죽었다
상수만 보고 갈래를 안 봄  갈래에서 조건을 빼도 상수는 그대로라 통과했다
                       include_str! 로 갈래 자체를 보게 하나 더 붙였다
```

⚠ **`include_str!` 은 검사 자신도 담는다.** 문자열을 세면 자기 몫을 빼라.

### 🔴 규칙을 주석이 아니라 **검사**로 바꿔라 (2026-09-01)

`is_out_in_play` 위에 이렇게 적혀 있었다:

```
"이 셋을 각각 나열하는 matches! 를 새로 쓰지 말 것.
 코드가 하나 늘 때마다 빠뜨린 자리가 조용히 생긴다"
```

**그리고 정확히 그 일이 났다.** 삼진 코드(`StrikeoutLook`/`StrikeoutSwing`)를
새로 만들면서 읽는 자리 **셋**을 안 고쳐, 주인공 탈삼진이 9시즌 내내 0이었다.

주석은 다음 사람이 그 자리를 **볼 때만** 읽힌다. 검사는 안 봐도 막는다:

```rust
// 소스에서 그 패턴이 남아 있는지 센다
let bad = body.matches("matches!(code, PitchResultCode::StrikeLook").count();
assert_eq!(bad, 0, "`is_strikeout` 을 써라");
```

⚠ **경고를 주석으로 적고 있다면 그건 검사로 바꿀 수 있다는 신호다.**

### ⚠ 조건이 **짝처럼 보이는데 아닌 경우**

```json
{ "type": "num_gte", "path": "school.universityWeek", "value": 157 }
{ "type": "num_lte", "path": "scoutScore",            "value": 45  }
```

`gte`/`lte` 가 나란히 있어 **범위를 거는 짝처럼 보이는데 `path` 가 다르다.**
`universityWeek` 의 상한이 빠져 있었고(졸업 후에도 참), 아무도 못 봤다.

- **`path` 가 같은 것끼리만 짝이다.** 타입이 짝을 이룬다고 짝이 아니다

## 5. 🔴 계측 — 거짓말하는 방식이 정해져 있다

이 저장소의 계측은 **조용히** 틀린다. 오류도 로그도 안 난다.

```
① 없는 경로를 읽으면 기본값이 된다
   `player.fielding.arm` 을 봤는데 실제는 `player.batting.arm` 이었다
   → 포수 500명이 전부 50 으로 보였고 "어깨는 문제없다"로 읽을 뻔했다

② 시점을 틀리면 0 이 나온다
   롤오버 **뒤**에 읽어 `leagueState.stats` 가 비었다 → 도루 0/0
   → "도루가 안 돈다"로 읽을 뻔했다. 시즌 종료 **앞**에서 잡아라

③ 모수를 틀리면 중앙이 달라진다
   포수를 **전 리그 506명**으로 셌다 → 중앙 63
   KBL 1군만 보면 74 다. 기준점을 엉뚱한 데 맞출 뻔했다

④ 중앙값과 전체 비율은 다른 질문이다
   선수별 타율 중앙 .256 ←→ 9이닝당 피안타 10.5 는 **성립하지 않는 조합**
   리그 전체(총안타/총타수)로 재니 .272 였다

⑤ 시즌 수를 안 보면 0 으로 보인다
   `--seasons` 기본값이 3 이라 프로 이벤트가 0종으로 나왔다 (B 가 겪음)
   **결과를 볼 때 시즌 수를 먼저 봐라**

⑥ **총량이 같아도 목록이 다르면 변한 것이다**
   대학 축을 고쳤는데 "못 닿음 28 → 28" 이라 아무것도 안 변한 것처럼 보였다
   실제로는 **넷이 나가고, 전 측정에서 잘려 있던 넷이 드러난 것**이다
   → **총량만 비교하지 마라. 목록을 대조해라**

⑦ 무대를 안 적으면 같은 숫자로 다른 얘기를 한다
   폭투 "8.5~10.3" 이 KBL 인지 고교인지 안 적혀 있어 오귀속이 났다
   (실측: KBL 팀당 20.3 · 고교 9.8 — **두 배 넘게 다르다**)
   → 값을 적을 때 **무대 · 시즌 수 · 씨앗**을 같이 적어라

⑧ **모수를 안 적으면 같은 이름의 다른 값이 된다**
   "고교 9이닝당피안타 13.9"  주인공 1명 · 4경기 · 22이닝
   "고교 9이닝당피안타 11.8"  102팀 전체
   **둘 다 맞는 값**인데 그걸로 전후를 비교하면 결론이 뒤집힌다
   → 무대·시즌 수에 더해 **누구를 몇 명 셌나**를 적어라

⑨ **한 시즌만 재면 누적 결함이 안 보인다**
   KBL 1군을 6시즌 훑으니 홈런 1504 → 3458 · 규정투수 60 → 177 이었다
   (경기 수는 오히려 156 → 127 로 줄었다)
   기준선이 **1시즌 값**이라 이걸 못 봤다 — 2026·2027 은 맞는 값이다
   → **플레이어가 겪는 건 3시즌차 이후다.** 시즌별로 남겨라
```

### 🔴 모수가 다르면 **같은 가설이 한쪽에선 참이고 한쪽에선 거짓**이다

B 가 "삼진이 0이면 아웃을 인플레이로만 잡으니 안타가 는다"고 예측했다.

```
리그 지표(NPC 지배)   9피안타 11.9 → 11.8   안 움직였다   → A: "예측이 틀렸다"
주인공 개인            9피안타 13.9 → 11.7   내려갔다      → B: "맞았다"
```

**둘 다 맞다.** 결함이 주인공 경기에만 있었으니 리그 총량은 안 움직이고
개인 기록만 움직인다. B 가 리그 결과 하나로 **자기 가설을 접은 게 성급했다.**

- 한쪽 결과로 가설을 접기 전에 **그게 어느 모수의 답인지** 확인해라
- 결함의 **적용 범위**(누구에게 걸리나)를 먼저 정하면 어느 모수를 볼지 정해진다

### 규칙

- **3회씩 잰다.** 씨앗 하나로 판단하지 마라
- **적용 전후를 잰다.** 전을 안 재고 후만 보면 아무것도 모른다
- **가설을 세웠으면 그것부터 재라.** 이 저장소에서 가설이 틀린 적이 훨씬 많다
- **모수를 봐라.** 몇 명 중 몇인지 없는 비율은 뜻이 없다
