## 2. 무엇이 안 보이나

1920x1080에서 보이는 viewBox 세로 범위는 **0~758**이다 (전체 920).

```
  티어         홈플레이트   포수    타자    잘린 깊이
  ────────────────────────────────────────────────
  pro              800     809     778      42px
  university       825     834     803      67px   ← 가장 깊다
  highschool       799     813     777      41px
```

세 티어 모두 **홈플레이트·포수·타자 셋이 다 잘림선 아래**다.
1366x768에서만 타자가 절반 걸치고(pro·highschool), 그보다 넓으면 전부 사라진다.

### 🔴 "구장마다 잘림이 다르다"는 정확히는 이렇다

**잘리는 px는 구장 28종이 전부 같다** (해상도별 값이 1종뿐 — 위 표에서 확인).
다른 건 **무엇이 잘려나가는지**다. 티어마다 홈플레이트 y가 달라서
(pro 800 · university 825 · highschool 799) **대학 구장이 26px 더 깊게 잘린다.**

그래서 화면상으로는 "구장마다 잘림이 다르게" 보인다.

## 3. 왜 잘리나 — 사슬 네 마디

1920x1080에서 각 요소를 실측한 값이다.

```
  요소                  폭 x 높이       height      max-height   overflow
  ───────────────────────────────────────────────────────────────────────
  match-engine-empty   1920 x 1080     1080px      none         hidden
  engine-grid          1896 x  918      918px      none         visible
  left-column          1101 x  918      918px      none         visible
  scene-panel          1101 x  670.4    670.4px    none         hidden    ← 여기서 자른다
  scene-layout         1075 x  622.4    622.4px    none         visible
  field-stage-wrap      843 x  622.4    622.4px    none         visible   ← 여기까진 맞다
  wrapper               843 x  775.5    775.5px    auto         visible   ← 여기서 터진다
  viewport              843 x  775.5    775.5px    100%         hidden
```

**① `.field-stage-wrap { align-items: start }`**
→ 자식 `.wrapper`가 늘어나지 않고 **내용 높이**를 갖는다.

**② `.wrapper { width: 100%; display: block }` — 높이가 `auto`다.**
`height: 100%`를 뺀 게 의도였다("부모가 auto면 그 값이 풀린다").

**③ 그래서 `.viewport { max-height: 100% }`가 안 먹는다.**
백분율 `max-height`는 **담는 상자의 높이가 확정일 때만** 적용된다.
`.wrapper`가 `auto`라 확정이 아니고, CSS는 이럴 때 `max-height`를
**`none`으로 친다.** 실측이 그대로 보여준다 — 칸은 622.4인데 775.5가 됐다.

```
   .viewport 높이 = 폭 843 × (920/1000) = 775.5px      ← aspect-ratio가 정한다
   쓸 수 있는 높이 = 622.4px                            ← 칸이 준 높이
   넘친 148px                                          ← 아무도 안 막는다
```

**④ `.scene-panel { overflow: hidden }`이 넘친 148px을 자른다.**

> ⚠ **주석에 적힌 안전망이 실제로는 없다.**
> `max-height`가 없으면 좁고 높은 창에서 반대로 넘친다 — 라고 적혀 있는데,
> 그 `max-height`가 지금 한 번도 적용된 적이 없다.

## 4. 어느 창 크기부터 잘리나

```
  창 폭    안 잘리는 최소 높이   그때 화면비   16:9 높이   16:9에서 잘리는 양
  ─────────────────────────────────────────────────────────────────────────
  1280              716          1.79:1          720          없음
  1366              880          1.55:1          768          83px
  1536             1003          1.53:1          864         103px
  1600             1049          1.53:1          900         111px
  1707             1127          1.51:1          960         124px
  1920             1281          1.50:1         1080         149px
  2048             1375          1.49:1         1152         165px
  2560             1745          1.47:1         1440         226px
  3840             2674          1.44:1         2160         380px
```

🔴 **창이 대략 3:2(1.5:1)보다 세로로 길어야 안 잘린다.**
16:9(1.78:1)는 **전부 잘린다.** 그리고 모니터는 거의 다 16:9다.

**1280 폭만 예외인 이유**는 화면비가 아니라 미디어 쿼리다 —
`@media (max-width: 1280px)`가 `.left-column`을 `1/8`에서 `1/7`로 줄여
구장 폭이 843 → 388로 좁아진다. 좁아지니 필요한 높이도 줄어 우연히 들어맞는다.

⚠ Electron은 `fullscreen: true`에 `minWidth: 1600, minHeight: 900`이다.
그런데 **Windows 배율이 CSS 픽셀을 나눈다** — FHD @150%는 1280x720이 되어
`minWidth`보다도 작다. 위 표를 해상도가 아니라 **CSS 픽셀**로 읽어야 하는 이유다.

## 5. 곁가지 — 이건 원인이 아니다

계측하면서 같이 확인해 배제한 것들이다.

**구장 그림 비율은 문제없다.** 30장을 다 재봤다.

```
  1306 x 1204  (비율 1.0847)   28장 — viewBox 1000x920(1.0870) 대비 -0.2%
  1308 x 1203  (1.0873)         highschoolbaseball.gif        +0.0%
  1317 x 1194  (1.1030)         universitybaseball.gif        +1.5%
```

`<image preserveAspectRatio="xMidYMid meet">`라 잘리지 않고 여백이 생기는데,
그 여백이 -0.2%면 1000px 폭에서 **2px**이다. 무시할 값이다.

⚠ `universitybaseball.gif`만 +1.5%(약 14px 상하 여백)다. **다만 이 그림은
대학 구장 9곳이 전부 전용 PNG를 갖고 있어 실제로는 안 쓰인다** — 티어를
모르는 구장(해외 ABL·JBL)이 `probaseball.gif`로 떨어질 때만 쓰는 폴백이다.

**`min-height: 280px`도 원인이 아니다.** 잰 열 해상도 어디서도 안 걸렸다
(가장 좁은 1280에서도 구장 높이가 357px).

**오른쪽 칸 내용도 무관하다.** 자연 높이를 90px과 260px 두 가지로 넣어
280쌍을 비교했고 **왼쪽 기하가 한 건도 안 달라졌다.**

## 6. 계측을 어떻게 했나

`.match-engine-empty`가 `position: fixed; inset: 0`이라 경기 화면은
**창 그 자체**다. 바깥 셸에 안 매인다 — 그래서 재현 하네스로 잴 수 있다.

```
  scratchpad/park/
    build-harness.mjs   진짜 소스에서 CSS·구조를 기계적으로 뽑아 붙인다
                          styles.css · MatchPage <style> · BaseballField <style>
                          좌표는 parkAnchors.ts를 그대로 import (node --experimental-strip-types)
    measure.mjs         해상도 10 × 구장 28 × 오른쪽칸 2 = 560건
    diagnose.mjs        사슬 한 마디씩
    threshold.mjs       폭마다 안 잘리는 최소 높이를 이분 탐색
    shots/              증거 갈무리 6장
```

브라우저는 **Edge(Chromium 151)**를 playwright-core로 몰았다.
A가 쓰는 dev 서버(5174)를 안 건드린다 — 서버를 아예 안 띄우고 `file://`로 연다.

### 하네스가 진짜와 다를 수 있는 곳

- **오른쪽 칸**은 Svelte 제어문이 53개라 그대로 못 옮겨 단순화했다.
  → §5에서 영향 없음을 실측으로 확인했다.
- **스코어보드 높이**는 9이닝 + 2팀 실제 마크업이되 `TeamMark`는 16px 자리만
  잡았다(원본도 `size={16}`). 이 높이가 달라지면 §1의 잘림 px가 그만큼 움직인다 —
  **다만 방향은 안 바뀐다.** 구장이 요구하는 높이(폭×0.92)는 그대로다.

## 7. A 트랙에 넘길 것

원인은 **`.viewport`의 `max-height: 100%`가 담는 상자 높이가 확정이 아니라
적용되지 않는 것** 하나다. 고치는 방향은 A가 정한다. 판단 재료만 적는다:

- `.wrapper`에 높이가 서면 `max-height: 100%`가 산다
- `.field-stage-wrap`의 `align-items: start`가 그걸 막고 있다
- 폭이 아니라 **높이에서 구장 크기를 뽑으면** 16:9에서도 안 잘린다.
  대신 좌우 여백이 생긴다 — 지금 좌우엔 타순 패널이 붙어 있어 여백이 어색할 수 있다
- `1280` 미디어 쿼리에서만 안 잘리는 건 **우연**이다. 폭을 좁혀 맞추는 건
  근본이 아니다

⚠ 고친 뒤에는 **16:9 여러 크기에서 다시 재야 한다.** 2026-08-28 고침이
안 들은 게 이 계측 없이 넘어갔기 때문이다. `threshold.mjs`가 그 회귀 검사를
그대로 한다.
