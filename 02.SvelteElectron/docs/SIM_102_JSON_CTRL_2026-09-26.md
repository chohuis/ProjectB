# `matchToSimResultNative` JSON 제어문자 예외 — 경로 추적 (2026-09-26 · A)

> **한 줄**: 데이터 가설은 **틀렸다**(실측). 진짜 형태는 **JSON 을 손으로 이은
> 자리**였고 그런 자리가 **열여섯** 있었다 — 걷었다. 09-25 의 그 한 건은
> **재현하지 못했다.** 다시 나면 메시지가 **어느 칸이었는지** 말한다.

## 0. 무엇이 있었나

09-25 24판 다섯 번째 묶음 2 의 **#8(safe / control / 20260802 · 12시즌)** 이
2033년 8/12시즌째에 삼킨 예외 1건과 함께 끊겼다.

```
matchToSimResultNative: control character (U+0000~U+001F) found while parsing a string
```

같은 씨앗·성향·프리셋으로 `PB_ONLY=8 PB_FORCE=1` 재실행하니 47분에 완주(예외 0).
머리말은 `docs/SIM_REPORT_2026-09-25_final24e.md`, 백로그는
`docs/BALANCE_BACKLOG.md` 09-25 D 절.

⚠ 그때 남은 것은 **위 한 줄뿐**이었다. 워커 stderr 는 `probe-a-simrun.cjs` 가
콘솔로만 흘리고(파일로 안 남긴다 · 실측 · 135~143줄), 판 JSON 은 재실행이
덮었다(`#08.json` 은 지금 예외 0 인 재실행 값이다). **그래서 이 조사는 코드에서
경로를 세우고 재현을 시도하는 일이 됐다.**

## 1. 가설 — 셋을 세웠다

| # | 가설 | 결과 |
|---|---|---|
| ① | 자유 문자열 칸(선수 이름 · 팀 id · 로그 문안 · 구장 이름)에 제어문자가 들어 있었다 | 🔴 **틀렸다** |
| ② | 마스터 데이터·이름 풀에 제어문자가 이미 박혀 있다 | 🔴 **틀렸다** |
| ③ | 그 문자열을 **이스케이프 없이 손으로 이은 자리**가 있다 | ✅ **맞았다 — 열여섯 자리** |

🔴 **왜 ①을 먼저 의심했고 왜 틀렸나.** 예외를 낸 쪽은 **파싱**이다
(`lib.rs` 의 `match_to_sim_result_native` 가 받은 문자열을
`serde_json::from_str` 로 펴다가 낸 것 — `parse_err` 첫 인자가 그 이름이다).
그런데 그 문자열을 만드는 것은 `gameSimulator.ts` 의 `JSON.stringify` 이고,
`JSON.stringify` 와 `serde_json::to_string` 은 **U+0000~U+001F 를 반드시
이스케이프한다.** 그러니 데이터에 제어문자가 있어도 그 예외는 안 난다 —
**예외가 났다는 것 자체가 「stringify 를 안 거친 문자열이 있다」는 뜻이다.**

## 2. 잰 방법

### ⑴ 경로 전수 — 무엇이 무엇을 만드나

```
gameSimulator.ts  simulateGame
  → simulateWithMatchEngine (FULL_ENGINE_LEAGUES 7개 리그 전부가 탄다)
      startMatchNative(JSON.stringify(opts))          TS  → Rust
      simToGameEnd(startRaw)                          Rust → Rust(문자열 그대로)
      JSON.parse(finRaw)                              Rust → TS
      matchToSimResultNative(JSON.stringify({state: fin, …}))   TS → Rust  ← 여기서 났다
```

payload 의 **자유 문자열 칸**과 그 출처(실측으로 센 개수는 아래 ⑵):

| 칸 | 출처 |
|---|---|
| `state.homeLineup[].name`·`.id` · `awayLineup` · `homeBench` · `awayBench` | **선수 id** — `toEngineBatter` 가 `name: b.id` 로 넣는다(기록이 id 로 돌아와야 순위표에 붙는다). id 는 Rust `roster_gen` 이 만들고 slot.db `npc` 가 정본 |
| `state.myQueue.pitchers[].name` · `opponentQueue` | 같음 — `toEnginePitcher` 가 `name: p.id` |
| `state.fielders[].name`·`.playerId` · `opponentFielders` | 같음 — 타순에서 파생 |
| `state.homeBatLines[]` · `awayBatLines[]` · 큐의 `lines[]` | 같음(엔진이 채운다) |
| `state.logs[]` · `preEntryLogs[]` | **Rust `format!` 이 만든 문안** — `match_engine.rs` 1712·2013·694 |
| `state.matchId` | Rust 생성 |
| `homeTeamId` · `awayTeamId` | `refs.json`(팀 ID 정본) |
| `conditions` 의 **키** | 선수 id |
| 이름 풀 · 문안 | `resource/data/master/players/name_pool_{kr,en,jp,abl_en}.json` · `events/` · `refs.json` |
| 사용자 입력 | 주인공 이름(`NewGamePage.svelte` `playerName`, `maxlength=20` · `.trim()`) — **이 경로에는 안 실린다**(엔진에 가는 것은 id 다) |

⚠ **선수 이름(사람 이름)은 이 payload 에 아예 안 들어간다** — 엔진이 받는
`name` 은 전부 **id** 다. 그것만으로도 ①은 약한 가설이었다.

### ⑵ 실측 — `scripts/probe-a-jsonctrl.cjs`

`measure-league-games-real.cjs` 의 진짜 KBL 로스터로 실제 경로를 돌린다.

```
npm run probe:a:jsonctrl -- --games 1000
```

```

   logs 줄 최대    462
   생 제어문자     0건
   파싱 예외       0건
② 자유 문자열 칸에 제어문자 + JSON.stringify (6가지: U+0000·001F·000A·000D·0009·0008)
   심은 칸 410개 × 6가지 → 생 제어문자 0건 · 전부 ✅ 통과

```

**③이 09-25 의 메시지와 글자까지 같다.** 즉 그 입력은 **stringify 를 안 거친
문자열**이었다.

### ⑶ 마스터 데이터 전수 — 바이트 단위(정규식 안 씀)

`resource/data` 아래 **898 파일**을 바이트로 훑어 JSON 문자열 안의
0x00~0x1F 를 셌다 → **JSON 은 0건.** 걸린 셋은 `events.toml` 2 ·
`staff_rules.toml` 1 로 **TOML 여러 줄 문자열의 개행**이다(문법상 정상).

⚠ **이 자리에 상시 게이트를 두지 않았다.** `master:fetch` 가 `JSON.parse` 로
읽으므로 마스터 JSON 에 생 제어문자가 들어가면 **읽는 순간 죽는다** — 검사를
더 만들면 같은 것을 두 곳에서 보는 꼴이다(정본 하나).

## 3. 찾은 것 — 손으로 이은 자리 열여섯

```rust
// lib.rs — 고치기 전
Err(e) => format!(r#"{{"error":"{}"}}"#, e),
```

`napi_team!` 매크로(14개) + `apply_scouting_noise_native` +
`update_player_loyalty_native` = **열여섯 자리**가 오류 JSON 을 손으로 이었다.

🔴 **serde 의 오류 메시지는 깨진 데이터를 그대로 물고 온다.** 프로브 ②가
그걸 찍었다 — `unknown variant \`P<개행>제어\``. 그 메시지에 `"` 나 제어문자가
있으면 위 `format!` 은 **JSON 이 아닌 문자열**을 내고, TS 쪽 `JSON.parse` 가
「Bad control character in string literal」로 죽는다. **엔진이 보낸 진짜 이유가
그 자리에서 사라진다.**

⚠ 같이 걷은 것: `unwrap_or_default()` — 직렬화 실패에 **빈 문자열**을 돌려줘
TS 가 「Unexpected end of JSON input」을 봤다(어느 함수인지 한 글자도 안 남는다).

⚠ **TS·Svelte 쪽에는 손으로 이은 자리가 없다**(전수 확인). 엔진 호출 payload 는
전부 `JSON.stringify` 다.

## 4. 고친 것

| 자리 | 무엇 |
|---|---|
| `lib.rs` `parse_err_at` (새 함수) | 파싱 실패에 **어느 칸이었는지** 붙인다 — 가장 가까운 앞쪽 `"키":` · 바이트 위치 · 그 앞뒤 창. **제어문자는 `\uXXXX` 로 적는다**(메시지에 생 바이트를 안 남긴다) |
| `lib.rs` 파싱 실패 자리 **121곳** | `parse_err` → `parse_err_at`. 이제 `parse_err` 는 **입력이 없는 자리**(`/serialize`) 전용이다 |
| `lib.rs` 손 이음새 **16곳** | `format!(r#"{{"error"…"#)` → `parse_err_at` · `unwrap_or_default()` → `parse_err(…/serialize)`. 서식은 한 곳에서만 만든다 |

**메시지가 이렇게 바뀐다**(프로브 ③ 실측):

```
[engine-native] matchToSimResultNative: control character (U+0000~U+001F) found
while parsing a string at line 1 column 40865 · 칸 `homeTeamId` ·
40864바이트째(전체 40952) · …"rngSeed":2208003824822684000},"homeTeamId":"TEAM_⟪여기⟫\u001fHOME","awayTeamId":…
```

⚠ **입력에서 제어문자를 거르는 필터는 안 넣었다.** 실측(②)이 「이름·id·문안에
제어문자가 있어도 이 경로는 안 깨진다」를 보였으니, 그 필터는 이 결함을
막지 않는다 — 안 부르는 갈래를 하나 더 두는 일이 된다.

## 6. 결론 · 남은 것

- **09-25 의 그 한 건은 재현하지 못했다.** 실제 경로 **1000경기**(payload 합
  약 42MB) + 자유 문자열 칸 410개 × 제어문자 6가지에서 **0건**이다.
- **후보 경로**: 그 예외가 나려면 payload 에 **stringify 를 안 거친 바이트**가
  있어야 한다. 코드에서 그런 생산자는 **위 열여섯 자리뿐이었고 전부 걷었다.**
  그 열여섯은 `team_engine`·`player_agent`·`scouting_engine` 쪽이라
  **경기 경로와 함수 이름이 다르다** — 그래서 「이게 그 원인이었다」고는
  **적지 않는다.** 남은 후보는 프로세스 수준(V8 문자열 · 네이티브 애드온
  메모리)이고, 90분 재실행이 이미 한 번 못 잡았다.
- **심어 둔 방어**: 다시 나면 메시지가 **어느 칸 · 몇 바이트째 · 앞뒤 글자**를
  말한다. 그 한 줄이 곧 증거다.
- ⚠ **밸런스 값은 한 글자도 안 건드렸다.**
