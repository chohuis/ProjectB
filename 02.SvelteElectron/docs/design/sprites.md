# 경기 화면 선수 스프라이트

## 왜 다시 만드는가 — 실측

화면이 쓰던 스프라이트 4장(`apps/ui/src/shared/assets/sprites/`)은 이랬다.

| 파일 | 크기 | 용량 | 투명 픽셀 |
|---|---|---|---|
| `field_batter_l.png` | 1254×1254 | 1,095KB | **0.0%** |
| `field_batter_r.png` | 1254×1254 | 958KB | **0.0%** |
| `field_defender.png` | 1254×1254 | 1,063KB | **0.0%** |
| `field_runner.png` | 1254×1254 | 1,006KB | **0.0%** |

알파 채널이 아예 없다. 그래서 48px로 줄여 그리면 **선수마다 흰 상자가 따라다녔다.**
누끼가 "덜 된" 게 아니라 처음부터 없었다.

한편 `resource/sprites/field-overview/`에는 **누끼가 된 24×32 세트가 포지션별로
이미 있었다**(투명 39%). 아무도 안 쓰고 있었을 뿐이다. M5-a에서 그쪽으로 갈아
끼워 흰 상자는 사라졌고 용량도 4.0MB → 21KB가 됐다.

남은 문제는 **품질과 팀 색**이다. 24×32 도트는 화면에서 39×52로 확대되어 거칠고,
전 팀이 같은 파란 유니폼을 입는다.

## 방식 — 키 컬러 마스크

색깔별로 20벌씩 그리면 역할 5종 × 20색 = **100장**이고, 그래도 238팀은 "가장
가까운 색"밖에 못 입는다.

대신 **치환용 색으로 1벌만** 그리게 하고 런타임에 팀 색으로 갈아끼운다.
이 프로젝트는 이미 238팀의 주색·보조색을 갖고 있고 `check:teamcolors`가
전수로 보증한다(주색 명도 상한 · 보조색 대비 4.5:1 · 색상차 60°).
그러면 **238팀 전부 정확한 팀 색**이 나오고 그림은 5장이면 된다.

### 키 컬러 표

유니폼은 한 색이 아니라 **명암 3단계**로 칠해야 도트가 납작해지지 않는다.
아래 색은 그리기용 표식일 뿐이고, 실제 화면에는 이 색이 절대 나오지 않는다.

| 영역 | 키 컬러 | 런타임 치환 |
|---|---|---|
| 유니폼 밝은 면 | `#FF00FF` 마젠타 | 주색 + 명도 18% |
| 유니폼 기본 면 | `#C800C8` 진마젠타 | 주색 |
| 유니폼 그림자 | `#800080` 자주 | 주색 − 명도 22% |
| 모자·양말(보조색) | `#00FFFF` 시안 | 보조색 |
| 등번호·로고 자리 | `#FFFF00` 노랑 | 보조색 위 흰색 |
| 피부 | `#FFC8A0` | 그대로 |
| 글러브·배트·신발 | `#7A4A28` | 그대로 |
| 외곽선 | `#101820` | 그대로 |

**정확히 이 여덟 색만** 쓴다. 중간색이 섞이면 치환할 때 어느 영역인지 판별이 안 된다.

## GPT 요청 사양

### 공통 (모든 요청에 넣는다)

```
2D 픽셀아트 야구 선수 스프라이트. 게임 필드 부감 뷰용.

■ 캔버스
- 96 x 128 픽셀, 배경 완전 투명 (알파 채널 필수)
- 실제 도트 해상도는 24 x 32. 즉 한 "도트"는 4x4 픽셀 블록이다.
  블록 경계가 정확히 맞아야 한다.
- 안티에일리어싱 금지. 반투명 픽셀 금지. 알파는 0 또는 255만.
- 그라데이션·블러·그림자 효과 금지 (그림자는 게임이 따로 그린다)

■ 시점과 자세
- 카메라는 홈플레이트 뒤 상단, 부감 약 35도. 관중석에서 내려다보는 각도.
- 다섯 종류 전부 **같은 시점·같은 키·같은 몸 비율**. 나란히 놓았을 때
  머리 높이와 발 위치가 일치해야 한다.
- 머리는 전체 높이의 약 1/3 (2등신 반). 발은 캔버스 맨 아래에서 2도트 위.

■ 색 — 아래 8색만 사용. 중간색·혼합색 금지
- 유니폼 밝은 면   #FF00FF
- 유니폼 기본 면   #C800C8
- 유니폼 그림자    #800080
- 모자·양말        #00FFFF
- 등번호 자리      #FFFF00
- 피부            #FFC8A0
- 글러브·배트·신발  #7A4A28
- 외곽선          #101820
(마젠타·시안은 게임이 팀 색으로 바꿀 자리 표식이다. 실제 색이 아니다.
 유니폼은 반드시 밝은면·기본·그림자 세 단계를 다 써서 입체감을 만들 것.)

■ 외곽선
- 실루엣 바깥 전체에 #101820 1도트 외곽선. 끊김 없이.
```

### 요청 1 — 5종 한 번에

```
위 사양으로 다섯 장을 만들어줘. 각각 별도 파일.

1) pitcher — 와인드업 직전, 정면을 보고 글러브를 가슴에 모은 자세
2) batter_right — 우타석. 몸이 왼쪽을 향하고 배트를 어깨 뒤로 세운 대기 자세
3) batter_left  — batter_right의 좌우 반전 자세 (좌타석)
4) fielder — 수비 준비. 무릎을 살짝 굽히고 글러브를 앞으로 내린 자세
5) runner — 베이스 위 리드오프. 몸을 살짝 앞으로 기울인 자세

다섯 장 모두 같은 시점·같은 키·같은 비율이어야 한다.
```

> GPT는 한 번에 10장까지 만든다. 5장이라 **1회차면 끝난다.**

### 검수 — 받으면 바로 돌린다

`npm run check:sprites`가 아래를 전수로 본다 (M5-b 구현 시 추가).

1. 96×128인가
2. 투명 픽셀이 있는가 (0%면 알파가 없는 것 — 지금 문제의 원인)
3. 반투명 픽셀이 0인가 (안티에일리어싱이 들어갔으면 치환이 뭉갠다)
4. 색이 정확히 8종인가 (중간색이 섞이면 영역 판별 불가)
5. 마젠타 3단계가 다 있는가 (한 단계만 쓰면 납작해진다)
6. 다섯 장의 **발 높이·머리 높이가 일치**하는가

## 런타임 치환

SVG `<image>`로는 색을 못 바꾼다. 두 가지 길이 있다.

- **캔버스 프리렌더** — 팀별로 한 번 그려 `ImageBitmap`으로 캐시. 경기당 두 팀
  뿐이라 10장이면 된다. 색 정확도 100%.
- **CSS 필터** — 배선은 쉽지만 `hue-rotate`는 색상만 돌려 주색이 정확히 안 나온다.
  238팀 색을 전수 검사로 보증해 놓고 화면에서 어긋나면 그 보증이 무의미해진다.

**프리렌더를 쓴다.** 필터는 이 프로젝트가 이미 가진 색 보증을 버리는 선택이다.

## 미결

- 등번호를 스프라이트에 그릴지, 게임이 텍스트로 얹을지. 24×32 도트에 두 자리
  숫자는 읽히지 않을 가능성이 높다 — 실물을 보고 정한다.
- 홈/원정 유니폼 구분. 지금 데이터에는 팀당 색이 2종뿐이라 원정용 흰 유니폼을
  쓰려면 데이터가 늘어야 한다. 1차 출시 범위 밖으로 둔다.
