# NPC 세계 검증 — 조사 기록 (2026-08-02)

`advanceWeek` 실제 경로를 타는 테스트가 **3개뿐**이었다(`test-careerpaths`,
`test-growth` G3, `test-savebatch`). 드래프트·승강·병역·FA·트레이드·은퇴는
전부 Rust 함수를 직접 부르는 단위 테스트라, **게임을 실제로 굴렸을 때
그것들이 도는지는 아무도 안 봤다.** 여기 적힌 결함은 전부 그 공백에서 나왔다.

## 진단 도구 (Phase 1 산출물)

집계만 봐서는 원인을 못 짚는다. 성장 조사에서 "시즌당 −3.1"이라는 평균
하나로는 아무것도 알 수 없었고, 나이별·동일선수 델타로 갈라서야 원인이 나왔다.

| 프로브 | 용도 |
|---|---|
| `npcTrajectory` / `pickTrajectorySample` | NPC 한 명의 인생을 연도순으로. 능력 상·중·하 표본 |
| `careerEventTally` | 연도별 전체 사건 — 드래프트·이적·FA·병역·은퇴 |
| `draftOutcomeByYear` | 진로 분포 + 리그별 유입/유출 |
| `leagueCapacity` | 리그별 인원·팀수 |
| `retirementProbe` | 은퇴·연령 분포. 세대교체가 도는가 |
| `faTradeProbe` | 1군·2군 프로 연차 분포, FA 자격자 |
| `gradeAgeProbe` | 학년제 리그의 나이·학년 정합 |

## 고친 것

### ① 연도 기록을 네 곳이 각자 썼다

Rust 학년 진급·은퇴, TS `applySeasonHistory`, TS `processAllLeaguesSeasonEnd`.
방어는 마지막 한 곳에만 있어서 고교생은 같은 해가 **두 줄**로 남았다.
경력 화면뿐 아니라 **드래프트 경로 판정**(`career_history.last()`로 고졸/대졸을
가른다)이 이 배열을 읽으므로 중복은 그대로 진로 오판이 된다.
→ `push_year_once` 도입.

### ② 연도 채우기에서 2군이 빠졌다

`processAllLeaguesSeasonEnd`의 `proIndLeagues`에 `LEAGUE_KBL_FARM`이 없어서
2군에 있던 해가 통째로 비었다. → 추가.

### ③ `Placer`가 부상자를 로스터에서 뺐다

`career_status != "active"`로 걸러 그만큼 빈자리로 착각하고 정원을 넘겨
배치했다 — 독립리그 정원 300인데 **410명(41/팀)** 까지 불어났다.
→ 은퇴만 제외.

이번 조사에서 **네 번째로 나온 같은 패턴**이다. 부상자를 없는 사람 취급하는
`!== "active"` 필터: 부상 회복, 신입생 인원, 학년 진급, 로스터 집계.

### ④ NPC 은퇴가 경력 사건으로 안 남았다

`NpcCareerEventType`에 `retirement`가 정의돼 있는데 쓰는 곳은 주인공 경로뿐.
NPC는 경력 화면에 은퇴가 안 뜨고, 사건 집계로 세대교체를 확인할 방법도 없었다
(그래서 "나이 은퇴가 한 번도 없다"고 잘못 읽기까지 했다). → Rust 은퇴에 추가.

### ⑤ `seasonPerfOf`의 null이 승강을 전면 중단시켰다

엔진 `RosterPerf`는 전부 `i32`/`f64`인데 `#[serde(default)]`는 **키가 없을
때만** 동작한다. 명시적 `null`이 오면 페이로드 전체가 거부되고 그 팀 승강이
죽는다. 실측: 프로 7년차부터 한 팀에서 매주 실패했고, 그 예외가 주간 루프를
끊어 뒤따르는 처리까지 안 돌았다. `buildRosterRef`에는 같은 방어가 있었는데
perf만 빠져 있었다. → 숫자가 아니면 0으로.

## 수정 완료 — 2차

### A. 진로 결정 해의 세계 처리가 통째로 사라진다

```
연도 2028 나이 19 W40 highschool
  결정 careerChoiceHub    → 2028 (19세)
  결정 careerResults      → 2028 (19세)
  결정 careerChoice(draft)→ 2028 (19세)
  결정 draftNotification  → 2029 (19세)   ← 롤오버 없이 연도가 넘어감
```

`acceptDraftOffer` → `openProSeason`이 `runSeasonRollover`를 거치지 않고
현재 시즌 +1로 새 시즌을 직접 연다.

```ts
const year = seasonYear ?? (get(seasonStore).seasonYear || 2026) + 1;
seasonStore.initSeason(leagueId, year, 52, teamIds);
```

그 해의 `processNpcDraft`·`processAllLeaguesSeasonEnd`·`applySeasonHistory`가
전부 건너뛰어진다. 실측: 2028 사건이 `fa_signed 6`뿐. 주인공 나이도 안 오른다.

**수정**: `runWorldSeasonEnd(year)`로 분리하고 연도 가드를 붙였다.
세계 오프시즌은 원래 **세 분기에 각각** 적혀 있었고(military·프로·학생)
그중 어디도 안 타는 경로가 있었다. 이제 정본은 하나이고, 롤오버와
`acceptDraftOffer` 양쪽에서 부른다.

같이 발견: **military 분기는 `processAllLeaguesSeasonEnd`만 불러
복무 2년 동안 드래프트가 안 돌았다.** 신인이 한 명도 안 들어왔다.

**실측 (2028 = 주인공 지명 해)**

| | 수정 전 | 수정 후 | 정상 시즌 |
|---|---|---|---|
| `retirement` | 0 | 5 | 9~14 |
| `quit_baseball` | 0 | 116 | 759~968 |

⚠ **아직 부분 수정이다.** 정상의 12%만 돈다. 진로 결정 시점에는
`processSeasonEnd`(NPC 학년 진급·졸업)가 아직 안 돌아 **졸업생이 드래프트
풀에 없다**. `processSeasonEnd`가 NPC 진급과 주인공 진급을 한 함수에서
처리하고 커밋해서, 세계 부분만 떼어내려면 구조를 더 봐야 한다.

### D. 팀 프로필이 전부 기본값이었다 → 트레이드 소멸

`calc_win_now_pressure_update`(우승 −20 / 2위 −5 / 중위 +2 / 하위 +8)가
구현돼 있는데 **아무도 안 불렀다.** `initProTeamProfiles`·
`patchProTeamProfile`도 호출부가 없고 refs.json에도 `proTeamProfile`이 없어
**전 팀이 `DEFAULT_TEAM_PROFILE`(전 항목 50)** 로 떨어졌다.

buyer 조건이 `rank_pct <= 0.30 && win_now_pressure > 60`인데 모두가 정확히
50이라 **buyer가 구조적으로 0팀**이었다. seller만 남으면 거래 상대가 없다.
계약 만료 예정자는 93·38·63명으로 **재료는 충분했다 — 동기가 없었다.**

같은 프로필을 승강 임계값(`10.0 - win_now_pressure * 0.05`)·방출·FA 입찰도
읽으므로 그쪽 판단도 전부 중립이었다.

**수정**: `runWorldSeasonEnd`에 `updateProTeamProfiles()`를 배선. 초기값을
새로 만드는 대신 이미 있던 성적 기반 갱신을 살렸다 — 하위권은 시즌당 +8이라
두 시즌이면 문턱을 넘는다.

### C. FA 시장이 5년 주기로만 열린다

실측 `fa_signed`: 264 → 30 → 8 → 4 → 4

| | 초기 | 2026 종료 후 |
|---|---|---|
| 1군 평균 연차 | 7년 (7+ 157명) | **1.8년** (7+ 12명) |
| 2군 평균 연차 | 3년 | **2.9년** |
| 자격 5년+ | 300명 | 114명 |

두 원인이 겹친다.

1. **2군이 프로 연차 적립에서 빠져 있다.** Rust 오프시즌이 KBL·ABL·JBL만
   `pro_service_years`를 올린다(`npc_sim.rs:866`). 프로 인원의 절반이 2군인데
   그동안 시계가 멈춘다.
2. **FA 취득 시 연차가 0으로 리셋된다.** 1군 평균이 7년 → 1.8년으로 폭락하고
   1~2년 구간에 223명이 몰렸다. 현실 야구는 누적 연차를 유지하고 재취득
   기간을 따로 둔다.

`LEAGUE_KBL_FARM`이 프로 리그 집합에서 빠지는 곳이 여럿이다 —
`npc_sim.rs:866`(연차), `npc_sim.rs:968`(현역 팀 목록),
`game.ts:916`(프로 NPC 동기화), `game.ts:2019`(FA 추적).

## 조사 중

### D. 트레이드가 연 1~4건

실측 `trade`: 11 → 2 → 2 → 4 → 3 → 2 → 1

파이프라인은 제안 생성 → 가치 평가(`acceptProbability < 0.35` 거절) →
메디컬 3단계이고 단계별 카운터 로그가 이미 있다. 어디서 걸러지는지 확인 중.

가설: **제안 생성 자체가 마른다.** 제안의 주 소스가 계약 만료 예정자
(`contractYears <= 1`)인데 오프시즌마다 `estimate_salary_and_contract`가
계약을 갱신해 리셋된다. 그리고 buyer 조건이 `rank_pct <= 0.30 &&
win_now_pressure > 60`이라 0팀일 수 있다.

⚠ `game.ts:2100`은 **FA 이동** 기록이지 트레이드가 아니다 — 한 번 혼동했다.
트레이드 사건은 `market.ts`의 `[트레이드성사]` 경로이고, 연 1~4건은
기록 누락이 아니라 **실제 성사 건수**다.

### F. 은퇴 사건 수정이 반영 안 됐던 이유 → 해결

빌드가 **EPERM으로 실패**하고 있었다.

```
EPERM: operation not permitted, unlink '...engine-native.win32-x64-msvc.node'
```

백그라운드 측정이 DLL을 잡고 있어 Windows가 파일 교체를 거부했다.
그런데 내 확인 명령이 `grep -E "^error|error\[|-->" | head -5`라 **경고의
`-->`가 먼저 5줄을 채워 에러를 가렸고**, `BUILD_DONE`은 `echo`라 무조건
찍혔다. 이 세션에서 결함 ⑥("빌드가 깨진 채 방치")을 잡아놓고 같은 실수를 했다.

**교훈: 빌드 성공은 종료 코드로 판정한다.** grep 필터로 보지 않는다.
그리고 측정이 도는 중에는 DLL을 못 바꾼다 — 끝난 뒤 빌드한다.

검증: 2026 retirement 9건 · 2027 9건 · 2029 14건.

### E. 야구 포기율 54% → 69%

| 연도 | 진로 대상 | 지명 | 대학 | 독립 | 야구 포기 |
|---|---|---|---|---|---|
| 2026 | 1,406 | 110 | 484 | 47 | 765 (54%) |
| 2027 | 1,458 | 110 | 414 | 0 | 934 (64%) |
| 2029 | 1,548 | 110 | 380 | 0 | 1,058 (68%) |
| 2030 | 1,551 | 110 | 369 | 0 | 1,072 (69%) |
| 2031 | 1,612 | 110 | 358 | 0 | 1,144 (71%) |

정원 구조상 고교 졸업 1,020명에 자리가 약 510~560개뿐이라 **비율 자체는
설계**일 수 있다(현실 야구도 비슷하다). 문제는 **줄어드는 추세**다 —
대학 유입이 484 → 358로 마르는데 대학 인원은 1,600 → 1,670으로 오히려 는다.
제때 졸업하지 못하고 쌓인다.

관련: 드래프트 점수의 나이 항이 `youth = 14 − (age−19)×3`이라 19세 고졸이
22세 대졸보다 **9점** 유리하다. 대학 4년의 보상이 없으면 대학 경로를
선택할 이유가 없어진다.

| 잘못 읽은 것 | 실제 |
|---|---|
| "나이 은퇴가 한 번도 없다" | 정상 작동. 프로 평균 나이 26.6 → 25.9로 젊어진다. `careerEvents`에 안 남을 뿐 |
