# 경기 엔진 밸런스 — 설계와 감사 (2026-08-03)

**수치 정본은 `packages/engine-native/src/tuning.rs`다.** 이 문서는 그 값이
왜 그렇게 생겼는지, 무엇을 재서 정했는지를 적는다.

## 경기 모델은 두 벌이다

| 모델 | 쓰는 곳 | 방식 |
|---|---|---|
| `npc_sim.rs` `sim_at_bat` | **리그 720경기 전부** | 볼/스트라이크 확률 → 인플레이 판정 |
| `match_engine.rs` `step_pitch_core` | **주인공이 뛰는 경기** | 착탄 좌표 → 스윙 판정 → 컨택 품질 표 |

⚠ **둘은 계수도 구조도 다르다.** 그런데 수상·승강·드래프트 평가는 **같은 규칙
파일**을 읽는다. 한쪽만 맞춰두면 주인공이 상대적으로 과대·과소 평가된다.

## 감사 — `npm run audit:engine`

게임 루프·스토어·IPC·파생계산을 전부 걷어내고 **엔진만 직접 부른다.**
시즌을 굴려 나온 숫자는 엔진·집계·파생이 뒤섞여 어디가 틀렸는지 못 가리기
때문이다(실제로 "주인공 ERA 14.78"이 나왔을 때 셋 중 무엇인지 알 수 없었다).

두 모델을 나란히 놓고 **원시 사건만** 센다. 마지막 절이 "두 모델이 같은 야구를
하는가"이고, 피안타 비중 차 0.1 이내를 요구한다.

⚠ **감사가 통과해도 리그 밸런스는 별도로 재야 한다.** 감사는 OVR 70 대 70
균일 입력이고 실제 로스터는 능력치 분포가 다르다. 같은 계수에서
감사 ERA 4.39 · K/9 7.8 → 실제 KBL 1군 ERA 5.56 · K/9 6.2였다.
리그 수치는 `npm run measure:batting`으로 잰다.

## 찾은 결함 6건 (2026-08-03)

전부 **밸런스가 아니라 구조** 문제였다.

### 1. 투수 AI가 스트라이크 존 밖을 겨냥하지 않았다

`auto_pick_decision`의 목표 좌표가 카운트와 무관하게 전부 존 안(|x|,|y| ≤ 1.0)
이었고, 착탄 분산도 control 70 기준 sigma 0.09라 볼 판정선(1.2)까지 4.4시그마였다.

**실측 200경기 볼넷 3개.** 밸런스가 나쁘면 "적게 나온다"지 "0"이 되지 않는다.
그게 결함과 튜닝을 가르는 신호였다.

### 2. 코스 선택 함수가 두 벌이었다

`auto_pick_decision`(자동진행)과 `random_decision_for_sim`(`runSimpleGame`)이
각자 좌표를 만들고 **둘 다** 존 밖을 못 겨냥했다. `pick_target` 하나로 합쳤다.

### 3. `resolve_contact` 표가 세 축에서 어긋났다

contact_q 56 기준 헛스윙 15% · 파울 15% · BABIP 50%
(현실 대략 25% / 35% / 30%). 헛스윙·파울이 적어 삼진이 안 쌓이고 BABIP은
1.7배라 피안타/삼진 비가 **4.67**이었다(같은 조건 `npc_sim` 1.17).

표를 다시 짰다 — 구간이 올라갈수록 헛스윙이 늘고 인플레이가 줄며 그 안의
안타 비율도 함께 떨어진다. 파울은 어느 구간이든 22~35%로 둔다(파울이 적으면
승부가 너무 빨리 끝나 삼진도 볼넷도 안 나온다).

### 4. 병살타·주루사 아웃이 주인공 이닝에 안 잡혔다

```rust
let is_out_result = is_k_out || result_code == InplayOut;   // 불리언
```

병살타는 한 타석에 아웃이 둘이고 안타 때 주루사도 아웃이다. 그게 빠져
`ip = outs/3`이 작아졌고 **9이닝 환산값이 전부 부풀었다.**
실측 주인공 6.7이닝 → **43.4이닝**, 9이닝당 피안타 45.7 → 7.7.

⚠ 3아웃 전환이 `next_outs`를 0으로 되돌리므로 **되돌리기 전에** 재야 한다.

### 5. 자책점이 시뮬 결과가 아니라 곱셈이었다

`applyGameOutcome.ts`에 `er = 피안타 × 0.35`. 피안타가 부풀면 ERA가 자동으로
따라 올라갔다 — **ERA 14.78은 시뮬이 아니라 이 곱셈이 만든 숫자다.**
엔진에 `er_since_entry`를 추가해 실제 실점을 전달한다.

### 6. 승패가 팀 결과 그대로였다

`won ? "W" : isDraw ? "ND" : "L"` — 등판만 하면 승패가 붙어 **0.6이닝 던진
불펜이 매 경기 승패를 기록**했다(실측 12경기 6승 6패).

`npc_sim.rs`의 `pitcher_decision`에 **이미 제대로 된 규칙이 있었다.** 그대로
옮겼다 — 선발 5이닝+승리 → W, 마무리 3점차 이내 → SV, 불펜 1이닝+ → HD.
주인공만 다른 규칙을 쓰면 같은 수상 부문에서 서로 다른 기준으로 경쟁한다.

리그 합산이 맞아도 **전원이 평균이면 능력치가 안 먹는 것**이다.
`abilitySpreadProbe`로 개별 편차를 본다.

| | 2026 (57명) | 2027 (65명) |
|---|---:|---:|
| OVR–ERA 상관 | **−0.65** | −0.52 |
| OVR–K9 상관 | +0.67 | +0.58 |
| 상위 25% ERA (OVR 89) | 3.79 | 3.70 |
| 하위 25% ERA (OVR 70) | 5.41 | 5.07 |

상관이 −0.9처럼 나오면 오히려 운이 없는 결정론적 시뮬이라는 뜻이다.
한 시즌 표본에는 운이 크게 섞이는 게 정상이다.

## 성격(clutch) 반영 — 배선이었지 새 기능이 아니었다

`clutch`·`mentality`·`battingClutch`는 **이미 생성·저장되고 있었다**
(`make_pitching`이 `ovr − 8 ± 6`으로 만든다). 저장 타입 주석에도 용도가
적혀 있었다 — "위기 집중력: 후반 접전/득점권 압박 시 quality 보정".

막힌 곳은 `gameSimulator.ts`가 능력치를 **골라 담는** 자리 하나였다.
`SimPitcher`에 여섯 필드만 담고 나머지를 버렸다.

`npc_clutch_mod`는 `match_engine`의 `clutch_modifier`·`jam_pressure_modifier`와
같은 개념이다. 득점권·2아웃·만루·후반접전이 압박을 만들고, 투수 기질이 덜어내며,
승부처에 강한 타자가 키운다. 결과는 투수 실효 능력에 곱하는 배율이다.

### 여기서 배운 것 — 검사를 어디에 두는가

| 결함 | 잡은 도구 | 다른 도구로 잡을 수 있었나 |
|---|---|---|
| 효과가 노이즈보다 작음 | 감사 ④ | — |
| **클램프 포화** (최고 위기에서만 성격 무의미) | `cargo test` | **감사로는 불가능** (평균에 희석) |
| `random_decision_for_sim`이 카운트를 안 받음 | 감사 ③ | — |
| **볼넷만 얻은 타자 기록 소실** | 감사 ① 투타 대사 | 합계만 보면 불가능 |

⚠ **감사 ④(성격 효과)는 게이트가 아니다.** 기대 효과가 ERA 0.07~0.10인데
400경기 노이즈가 ±0.14다. 같은 설정에서 **0.57 · 0.05 · 0.19 · 0.22 · −0.48**이
나왔다 — 부호까지 바뀐다. 게이트로 두면 정상인데도 무작위로 실패하고,
더 나쁘게는 0.57을 보고 "효과가 크다"고 잘못 결론 내린다(실제로 한 번 그랬다).
정확성은 `clutch_tests`가 결정론적으로 본다.

⚠ **밸런스를 고치면 그 뒤에 숨어 있던 집계 결함이 드러난다.** 볼넷만 얻은
타자 기록 소실은 원래 있었지만 볼넷이 1.2/9밖에 안 돼 안 보였다. 3.6으로
정상화하자 투타 대사가 어긋나기 시작했다.

## 리그 기록 버킷 오염 — 해결 (2026-08-03)

**`season.stats`는 리그 버킷이 아니다.** 주인공이 이번 시즌 뛴 기록이고,
1군에서 뛰다 2군에 내려가도 **합산**된다(개인 성적으로는 그게 맞고,
계약 협상·상태 화면이 그 값을 쓴다).

그런데 리그 집계가 이런 관용구를 쓰고 있었다:

```ts
s.leagueId === lid ? s.stats : leagueState[lid].stats
```

`s.leagueId`는 `initSeason` 때만 정해져 시즌 중 안 바뀐다. 그래서 주인공이
승강으로 오르내리면 **2군 경기 기록이 1군 버킷으로 읽혔다.**

| | 수정 전 | 수정 후 |
|---|---:|---:|
| 규정투수(40이닝+) | **94명** | 60~66 |
| OVR–ERA 상관 | −0.20 | −0.39~−0.50 |
| 이상 타석 | 6건 | 0 |

쓰기(`applyMatchResult`)는 이미 `leagueState[leagueId]`에 정확히 넣고 있었다 —
**읽기만 바로잡으면 됐다.** `season-helpers.ts`의 `leagueStatsOf`·
`leagueStandingsOf`가 정본이고, 관용구를 복사하지 않는다.

⚠ `getLeagueStandings`의 `?? s.standings` 폴백도 뺐다. 버킷이 비었을 때
**엉뚱한 리그 순위를 그 리그 것으로 쓴다.** 비었으면 빈 채로 두는 게 맞다.

## 로스터 보직 배분 — `fill_first_teams`

⚠ **두 겹의 결함이었다.**

1. **보직을 안 봤다.** 능력치 순으로만 승격해서 2군 상위권이 투수에 몰리면
   투수만 올라와 로스터를 잠식했다 — 실측 야수 **7명** · 투수 27명 · 총 34명.
2. **총원 가드 안에 있었다.** `if have >= min { continue; }`로 시작하는데,
   보직 배분이 깨지는 팀은 **대개 총원이 차 있다**(야수 3·투수 34·총 37).
   정확히 필요한 상황에서만 함수가 안 돌았다.

야수 하한을 총원 가드 밖으로 빼고, 정원이 찼으면 **능력치 낮은 투수를 2군으로
내려 자리를 만든다.** 하한 14의 근거는 `tuning.rs`에 있다 —
`rosterSize` 30 × `pitcherRatio` 0.45 = 야수 16이고 KBO 1군도 야수 15~17이다.

⚠ 처음엔 10으로 뒀다. "타순 한 바퀴(9) + 여유 1"이라는 좁은 근거였고,
**생성 시점 값과 현실이 이미 일치하는데 그걸 안 봤다.**

## 포지션 균형 — 부분 해결 (2026-08-03)

**공통 원인: 충원이 "몇 명"만 보고 "어느 자리"를 안 본다.**

회귀는 `npm run test:rosterbalance`다. 4시즌을 굴려 **시즌마다 최악값을
누적**한다 — 마지막 한 시점만 보면 중간에 무너졌다 회복된 구간을 놓친다.

### 고친 것 셋

| | 내용 |
|---|---|
| 신입생 포지션 배정 | 무작위 → **부족한 자리부터**. `neededPositions`(rosterEngine)가 정본이고 여러 충원 경로가 같이 쓴다 |
| 포지션 전환 | `fix_position_gaps` — 정원이 찬 팀은 충원 대상이 아니라 공백이 유지된다. 남는 자리(3명+, 없으면 2명)에서 **능력치 낮은 순으로** 돌린다 |
| 라인업 9명 보장 | 야수가 모자라면 타격 좋은 투수로 채운다 |

⚠ 신입생은 **투수 여부도 `rand < 0.3` 고정 확률**이었다. 포지션과 같은 이유로
팀 단위 편차가 누적돼 고교 최소 투수가 4명까지 떨어졌다. 이제 배정된
포지션에서 파생한다 — 둘이 따로 정해지면 서로 어긋난다.

⚠ **라인업이 9명 미만이면 통계가 왜곡된다.** Rust는 `lineup[lpos % n]`으로
타순을 돌리므로 n=6이면 타석이 1.5배가 되고, **능력치가 아니라 출전량이
성적을 만든다**(실측 경기당 7.1타석 · OVR–ERA 상관 −0.5 → −0.25).
예전엔 야수가 **0명일 때만** 폴백해서 8명이면 8명짜리 라인업이 그대로 나갔다.

### 남은 것 — 두 계열로 갈린다

**① 인원 부족 (심각)**
```
TEAM_KBL_CHANGWON_STARS_1  야수 7 / 투수 30  공백[1B,LF,CF]
```
야수 7명으로는 8자리를 못 채운다. 전환은 **있는 사람을 재배치**할 뿐이다.
Phase 1에서 야수 하한 14를 넣었는데도 7명이 나온다 — `fill_first_teams`는
오프시즌에만 도는데 시즌 중 트레이드·부상으로 다시 무너지는 것으로 보인다.
⚠ **오프시즌 직후와 시즌 종료 시점을 각각 재야 갈린다.** 아직 안 했다.

**② 포지션 공백 (경미)**
```
TEAM_KBL_SUWON_KNIGHTS_2   야수 25  공백[LF]
```
사람은 충분한데 한 자리가 빈다. 라인업은 9명으로 채워지므로 **경기는 정상
진행된다.** 검사 기준을 0 → 소수 허용으로 조정하는 게 맞을 수 있다.

다른 리그는 유입 경로(고교 신입생·대학 진학·드래프트·2군 충원)가 포지션을
안 본다.

`rosterCompositionProbe`가 9개 리그 구분을 한 번에 잰다. 생성 시점은
`test-roster-gen`이 이미 검사하지만 **그건 새 게임 시점뿐**이다.

## (구) 미결 — 리그 기록 버킷 오염

⚠ **1군 기록 버킷에 2군 선수가 섞인다.** 시즌이 갈수록 심해진다.

| | 2026 | 2027 | 2029 |
|---|---:|---:|---:|
| 규정투수(40이닝+) | 62 | 62 | **94** |
| OVR–ERA 상관 | −0.54 | −0.35 | **−0.20** |
| OVR–K9 상관 | 0.56 | 0.40 | **0.11** |

10팀 리그에서 규정투수 94명은 나올 수 없다(정상 60~65). 실제로 그 버킷에
2군 소속 선수가 있다:

```
PLY_KB26_KBL_DAEGU_SABERS_1_030  팀=TEAM_KBL_SEOUL_ROYALS_2
                                 리그=LEAGUE_KBL_FARM  g126 pa765
```

**능력치 풀이 다른 두 집단을 한 버킷에 섞으면 OVR·성적 상관이 무너진다.**
2029의 −0.20은 성격 때문이 아니라 측정 대상이 오염된 결과로 보인다.

⚠ 이 오염은 **성격 도입 전부터 있었다.** 앞선 측정의 `pa_최대` 1084·1140이
같은 현상이고, 그때는 "타격 인플레이션"으로 잘못 읽었다(밸런스를 정상화한
지금도 남아 있다). `batterSampleProbe`의 `이상타석상세`가 그 선수의 소속을
직접 찍는다 — 집계만 보면 원인을 못 찾는다.

## 무엇이 경기에 반영되고 무엇이 안 되는가

| | NPC 리그 경기 | 주인공 경기 |
|---|---|---|
| 능력치 (구속·제구·커맨드·무브 / 컨택·파워·선구·규율) | ✅ | ✅ |
| 보직 (선발·불펜·마무리) | ✅ | ✅ |
| 스태미나·피로 | ✅ | ✅ |
| **성격 (clutch·mentality)** | ✅ (2026-08-03 배선) | ✅ |
| **구종** | ❌ | ✅ |

구종은 성격과 다르다. `npc_sim`은 투구 단위 모델이 아니라 구종 선택 개념 자체가
없어서 모델을 다시 짜야 한다. 기존 설계 주석도 의도적 단순화로 못박고 있다
("`SimPitcher`가 구종을 안 본다 — 화면과 성장에만 쓴다"). Phase 8(성능)이
미결인 상태에서 리그 시뮬 부하를 늘리는 건 순서가 거꾸로다.

측정기가 **무엇을 안 보는지** 확인하지 않아 세 번 오독할 뻔했다.

| 잘못된 검사 | 실제 |
|---|---|
| `이닝×3 = 타수 − 안타` | 병살타는 타수 1에 아웃 2, 주루사도 아웃. 정상 동작이 154차로 찍혔다 |
| 볼넷 비중을 **절대 차이**로 비교 | NPC 0.07 vs 주인공 0.00의 차이가 0.07이라 느슨한 기준을 통과했다. **배율로 보니 101.9배** |
