# 경기 엔진 밸런스 — 설계와 감사 (2026-08-03)

**수치 정본은 `packages/engine-native/src/tuning.rs`다.** 이 문서는 그 값이
왜 그렇게 생겼는지, 무엇을 재서 정했는지를 적는다.

## 경기 모델은 두 벌이다

| 모델 | 쓰는 곳 | 방식 |
|---|---|---|
| `npc_sim.rs` `sim_at_bat` | **리그 720경기 전부** | 볼/스트라이크 확률 → 인플레이 판정 |
| `match_engine.rs` `step_pitch_core` | **주인공이 뛰는 경기** | 착탄 좌표 → 스윙 판정 → 컨택 품질 표 |

⚠ **둘은 계수도 구조도 다르다.** 그런데 수상·승강·드래프트 평가는 **같은 규칙
파일**을 읽는다. 한쪽만 맞춰두면 주인공이 상대적으로 과대·과소 평가된다.

## 감사 — `npm run audit:engine`

게임 루프·스토어·IPC·파생계산을 전부 걷어내고 **엔진만 직접 부른다.**
시즌을 굴려 나온 숫자는 엔진·집계·파생이 뒤섞여 어디가 틀렸는지 못 가리기
때문이다(실제로 "주인공 ERA 14.78"이 나왔을 때 셋 중 무엇인지 알 수 없었다).

두 모델을 나란히 놓고 **원시 사건만** 센다. 마지막 절이 "두 모델이 같은 야구를
하는가"이고, 피안타 비중 차 0.1 이내를 요구한다.

⚠ **감사가 통과해도 리그 밸런스는 별도로 재야 한다.** 감사는 OVR 70 대 70
균일 입력이고 실제 로스터는 능력치 분포가 다르다. 같은 계수에서
감사 ERA 4.39 · K/9 7.8 → 실제 KBL 1군 ERA 5.56 · K/9 6.2였다.
리그 수치는 `npm run measure:batting`으로 잰다.

## 찾은 결함 6건 (2026-08-03)

전부 **밸런스가 아니라 구조** 문제였다.

### 1. 투수 AI가 스트라이크 존 밖을 겨냥하지 않았다

`auto_pick_decision`의 목표 좌표가 카운트와 무관하게 전부 존 안(|x|,|y| ≤ 1.0)
이었고, 착탄 분산도 control 70 기준 sigma 0.09라 볼 판정선(1.2)까지 4.4시그마였다.

**실측 200경기 볼넷 3개.** 밸런스가 나쁘면 "적게 나온다"지 "0"이 되지 않는다.
그게 결함과 튜닝을 가르는 신호였다.

### 2. 코스 선택 함수가 두 벌이었다

`auto_pick_decision`(자동진행)과 `random_decision_for_sim`(`runSimpleGame`)이
각자 좌표를 만들고 **둘 다** 존 밖을 못 겨냥했다. `pick_target` 하나로 합쳤다.

### 3. `resolve_contact` 표가 세 축에서 어긋났다

contact_q 56 기준 헛스윙 15% · 파울 15% · BABIP 50%
(현실 대략 25% / 35% / 30%). 헛스윙·파울이 적어 삼진이 안 쌓이고 BABIP은
1.7배라 피안타/삼진 비가 **4.67**이었다(같은 조건 `npc_sim` 1.17).

표를 다시 짰다 — 구간이 올라갈수록 헛스윙이 늘고 인플레이가 줄며 그 안의
안타 비율도 함께 떨어진다. 파울은 어느 구간이든 22~35%로 둔다(파울이 적으면
승부가 너무 빨리 끝나 삼진도 볼넷도 안 나온다).

### 4. 병살타·주루사 아웃이 주인공 이닝에 안 잡혔다

```rust
let is_out_result = is_k_out || result_code == InplayOut;   // 불리언
```

병살타는 한 타석에 아웃이 둘이고 안타 때 주루사도 아웃이다. 그게 빠져
`ip = outs/3`이 작아졌고 **9이닝 환산값이 전부 부풀었다.**
실측 주인공 6.7이닝 → **43.4이닝**, 9이닝당 피안타 45.7 → 7.7.

⚠ 3아웃 전환이 `next_outs`를 0으로 되돌리므로 **되돌리기 전에** 재야 한다.

### 5. 자책점이 시뮬 결과가 아니라 곱셈이었다

`applyGameOutcome.ts`에 `er = 피안타 × 0.35`. 피안타가 부풀면 ERA가 자동으로
따라 올라갔다 — **ERA 14.78은 시뮬이 아니라 이 곱셈이 만든 숫자다.**
엔진에 `er_since_entry`를 추가해 실제 실점을 전달한다.

### 6. 승패가 팀 결과 그대로였다

`won ? "W" : isDraw ? "ND" : "L"` — 등판만 하면 승패가 붙어 **0.6이닝 던진
불펜이 매 경기 승패를 기록**했다(실측 12경기 6승 6패).

`npc_sim.rs`의 `pitcher_decision`에 **이미 제대로 된 규칙이 있었다.** 그대로
옮겼다 — 선발 5이닝+승리 → W, 마무리 3점차 이내 → SV, 불펜 1이닝+ → HD.
주인공만 다른 규칙을 쓰면 같은 수상 부문에서 서로 다른 기준으로 경쟁한다.

## 능력치가 실제로 성적을 가르는가

리그 합산이 맞아도 **전원이 평균이면 능력치가 안 먹는 것**이다.
`abilitySpreadProbe`로 개별 편차를 본다.

| | 2026 (57명) | 2027 (65명) |
|---|---:|---:|
| OVR–ERA 상관 | **−0.65** | −0.52 |
| OVR–K9 상관 | +0.67 | +0.58 |
| 상위 25% ERA (OVR 89) | 3.79 | 3.70 |
| 하위 25% ERA (OVR 70) | 5.41 | 5.07 |

상관이 −0.9처럼 나오면 오히려 운이 없는 결정론적 시뮬이라는 뜻이다.
한 시즌 표본에는 운이 크게 섞이는 게 정상이다.

## 무엇이 경기에 반영되고 무엇이 안 되는가

| | NPC 리그 경기 | 주인공 경기 |
|---|---|---|
| 능력치 (구속·제구·커맨드·무브 / 컨택·파워·선구·규율) | ✅ | ✅ |
| 보직 (선발·불펜·마무리) | ✅ | ✅ |
| 스태미나·피로 | ✅ | ✅ |
| **성격 (clutch·mentality)** | ❌ | ✅ |
| **구종** | ❌ | ✅ |

⚠ **`clutch`·`mentality`·`battingClutch`는 이미 생성·저장된다**
(`make_pitching`이 `ovr − 8 ± 6`으로 만든다). 막힌 곳은 `gameSimulator.ts`의
`SimPitcher`/`SimBatter`가 능력치를 **골라서 버리는** 자리 하나다.
성격 반영은 새 기능이 아니라 **배선 작업**이다.

구종은 다르다. `npc_sim`은 투구 단위 모델이 아니라 구종 선택 개념 자체가
없어서 모델을 다시 짜야 한다. 기존 설계 주석도 의도적 단순화로 못박고 있다
("`SimPitcher`가 구종을 안 본다 — 화면과 성장에만 쓴다"). Phase 8(성능)이
미결인 상태에서 리그 시뮬 부하를 늘리는 건 순서가 거꾸로다.

## 검사식이 틀렸던 것들 (같은 실수 반복 방지)

측정기가 **무엇을 안 보는지** 확인하지 않아 세 번 오독할 뻔했다.

| 잘못된 검사 | 실제 |
|---|---|
| `이닝×3 = 타수 − 안타` | 병살타는 타수 1에 아웃 2, 주루사도 아웃. 정상 동작이 154차로 찍혔다 |
| 볼넷 비중을 **절대 차이**로 비교 | NPC 0.07 vs 주인공 0.00의 차이가 0.07이라 느슨한 기준을 통과했다. **배율로 보니 101.9배** |
| 주인공 성적을 `승/패`만 출력 | 불펜이라 0승 0패가 정상인데 "기록 없음"으로 읽었다. 세이브·홀드를 같이 찍으니 12홀드가 드러났다 |
