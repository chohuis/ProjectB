# 1군 ↔ 2군 승강 설계 (Phase 7-2, 2026-07-31 확정)

> **수치는 여기 복제하지 않는다** — 정본은
> `resource/data/master/players/generation_rules.json`의 `promotionRules`,
> 로스터 상한은 `rosterRules[리그].rosterMin/rosterMax`다.
>
> 회귀 `npm run test:promotion` · 출렁임 실측 `npm run measure:promotion`

## 0. 언제 도는가

```
월 첫 주    정기 재편   콜업 + 콜다운. 로스터 전체를 다시 짠다
나머지 주   상시 콜업   빈 자리 메우기만. 팀당 한 명, 콜다운 없음
```

**둘이 같은 일을 하면 매주 로스터가 출렁인다.** 상시 경로는 판정 엔진을 그대로
쓰되 사유가 `injury_replacement` / `slump_replacement`인 후보만 채택한다 —
전력 보강·유망주 노출은 재편이라 정기의 몫이다.

**주인공과 무관하게 국내 10구단 전부 돈다.** 예전엔 `careerStage`가 프로일 때만,
그것도 주인공 리그만 처리해서 — 주인공이 고교생이면 프로 세계의 승강이 통째로
멈췄다. 드래프트가 매년 110명을 2군에 넣는데 아무도 안 올라왔다.

---

## 1. 판정 — 성적이 주, 능력치가 보정

```
비교값 = OVR + form_score × formWeight
```

`form_score`는 시즌 성적을 **−1.0 ~ +1.0**으로 정규화한다.

| | 기준 | 표본 100% |
|---|---|---|
| 투수 | ERA `pitcherEraBaseline` | `pitcherFullInnings` |
| 타자 | OPS `batterOpsBaseline` | `batterFullPa` |

⚠ **표본이 적으면 0쪽으로 당긴다.** 3이닝 던지고 0점대인 선수가 시즌 내내 던진
에이스를 밀어내면 안 된다. 기록이 아예 없으면 0이라 **판정이 자동으로 능력치만
보게 된다** — 안 뛴 선수를 성적으로 벌주지 않는다.

⚠ **`formWeight × formSpan`이 리그 OVR 폭에 근접하면 능력치가 무의미해진다.**
지금은 8점 = 프로 OVR 폭(30)의 4분의 1. 성적이 뒤집되 지우지는 않는다.
`test:promotion`이 이 균형을 지킨다.

1군·2군 기록을 **한 곳에서 찾는다** — 시즌 중 오르내린 선수는 기록이 두 리그에
나뉘어 있어서, 한쪽만 보면 콜업된 선수가 2군 성적을 잃는다.

---

## 2. 정원

**정본은 `rosterRules.LEAGUE_KBL.rosterMin/rosterMax`다.**

- 콜업은 **1:1 교체**라 정원을 안 늘린다 (한 명 올리고 한 명 내린다)
- 콜다운은 **정원 초과분만** 내린다

> 예전엔 콜다운이 `over.max(3)`이라 정원에 여유가 있어도 매번 3명을 후보로
> 내놨고 호출측이 2명을 실제로 내렸다. 콜업이 정원을 안 늘리는데 콜다운만
> 매달 나가서 **한 시즌에 1군이 30명 → 16명으로 말랐다.**
> 실측(`measure:promotion`)에서 잡혔다 — 유닛테스트로는 안 걸린다.

호출측도 하한 아래로는 콜다운을 안 돌린다. 상한 하나만 믿으면 위 결함이 다시 난다.

---

## 3. 강등은 팀과 리그를 같이 바꾼다

```ts
currentTeam:   TEAM_X_1 → TEAM_X_2
currentLeague: LEAGUE_KBL → LEAGUE_KBL_FARM     // ← 이게 빠져 있었다
```

팀만 바꾸면 그 선수가 계속 1군으로 집계된다 — 2군 리그 순위·경기에 안 잡히고
1군 상한에는 계속 포함된다. **같은 결함이 오프시즌 경로에서 프로 소속을
800명까지 부풀렸다** (Phase 7-1 D-3a). 시즌 중 경로에 그대로 남아 있었다.

---

## 4. 주인공

**강등된다** (사용자 확정). 예전엔 코드가 명시적으로 건너뛰어 성적과 무관하게
1군에 남았다.

강등되면 `gameStore.setProtagonistTeam`으로 **소속 리그가 바뀌어 2군 경기를 직접
뛴다.** 2군 일정·순위표는 이미 있으므로 `leagueId`만 맞으면 그대로 붙는다.

⚠ **`applyDraftDecision`을 쓰면 안 된다.** 그건 학적 전이(진학·입단)를 검사하는
경로다. 2군 강등은 같은 구단 안의 이동이라 커리어 단계를 안 건드린다.

## 5. 확정 사항 (2026-07-31)

| | |
|---|---|
| 범위 | 국내 프로 전체 · 주인공 무관 |
| 주기 | 월간 정기 + 상시 콜업 |
| 판정 | 최근 성적 위주 + 능력치 보정 |
| 주인공 | 강등된다 · 2군 경기를 직접 뛴다 |
| 신인 | 1군 직행 없음 — 전원 2군 시작 (7-1) |
| 상시 트리거 | 부상 + 장기 부진 |
| 최소 체류 기간 | 없음 |

> **"장기 부진도 상시 트리거" + "체류 기간 없음"** 조합은 오르락내리락할 여지를
> 남긴다. 실측 결과 정원 결함을 고친 뒤로는 **최다 이동 1회 · 4회 이상 0명**이라
> 문제가 아니었다. 판정을 바꾸면 이 숫자부터 다시 잰다.

## 6. 아직 없는 것

- 성적 기반 승격이 **월 단위**다. 실제 KBO는 거의 매일 엔트리가 바뀐다 —
  더 잦게 만들면 리그 소속이 흔들려 기록이 지저분해진다. 지금 구조에서는
  월간이 상한이다
- 부상 입력은 `seasonStore.npcInjuries` 하나뿐이다. 부상 엔진이 세분화되면
  상시 콜업의 트리거도 같이 넓혀야 한다
- `measure:promotion`의 **성적은 합성이다.** 경기 시뮬을 통째로 돌릴 수 없어
  능력치 + 노이즈로 만든다. 재는 건 성적의 사실성이 아니라 **판정 로직이
  얼마나 자주 사람을 옮기는가**다. 진짜 성적 분포는 하네스(Phase 9)에서 본다

## 7. 이 문서를 고칠 때

수치를 바꾸면 **규칙 파일만** 고친다. 구조를 바꾸면 `npm run test:promotion`이
먼저 깨져야 한다 — 안 깨지면 그 테스트가 실데이터를 안 읽고 있다는 뜻이다.

**분포는 실제 규모로 돌려 숫자를 찍는다.** 1군이 말라가던 결함은 유닛테스트를
전부 통과한 상태에서 한 시즌 실측으로만 드러났다.
