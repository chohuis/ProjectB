# 로스터 생성 설계 (Phase 6.5, 2026-07-30 확정)

> 선수 한 명이 만들어지는 모든 규칙. **수치는 여기 복제하지 않는다** —
> 정본은 `resource/data/master/players/generation_rules.json`이고,
> 문서에 옮겨 적으면 stale해진다(이 프로젝트가 이미 겪은 문제다).

## 0. 규칙이 어디 있나

`generation_rules.json` 한 파일에 5개 섹션이 있다. **손으로 관리하는 master 파일**이고
시드에서 생성되지 않는다 (`seeds/onepitch/generation_rules.toml`은 아무도 안 읽는
OnePitch 시절 고아다 — BACKLOG §5 참고).

| 섹션 | 정하는 것 | 읽는 곳 |
|---|---|---|
| `rosterRules[리그]` | 로스터 크기 · OVR 폭 · 나이 · 계약 유무 | `roster_gen.rs` |
| `salaryRules` | 연봉 곡선 · 연차계수 · 리그배수 · 최저연봉 | `npc_sim.rs` |
| `powerRules` | 전력★ → OVR 이동폭 | `roster_gen.rs` |
| `careerHistoryRules` | 이적 빈도 · FA 주기 · 입단 경로 | `career_history.rs` + `roster_gen.rs` |
| `militaryRules` | 상무 로스터 · 계급 · 복무기간 | `military_roster.rs` |

⚠ **`careerHistoryRules.entry`는 두 곳이 읽는다.** 로스터 생성이 그걸로 연차를
역산하고, 경력 이력이 같은 규칙으로 출신을 읽는다. 따로 두면 어긋난다 —
실제로 그래서 출신 분포가 뒤집혔었다(아래 §6).

## 1. 나이 — 한국 나이

```
고교 1/2/3      17 / 18 / 19     (ageBase 16)
대학 1/2/3/4    20 / 21 / 22 / 23 (ageBase 19)
독립            20 ~ 31
프로 1군        20 ~ 37
프로 2군        20 ~ 29
```

**진로가 끊기면 안 된다.** 고졸 19세 → 다음해 20세 = 대학1·독립·프로 최소 나이.
대졸 23세 → 다음해 24세, 프로 범위 안.

> 고치기 전엔 고3이 18세라 졸업하면 19세인데 프로 최소가 20세였다 —
> **아무도 그 해에 프로에 갈 수 없었다.** 주인공은 이미 17세로 시작하는데
> NPC 고1만 16세이기도 했다.

Rust `나이_체계가_진로를_끊지_않는다`가 실데이터로 이걸 지킨다.

## 2. 능력치 — 전력★ 연동

전력★(1~5)이 로스터 OVR **구간 전체를 민다**. 폭은 그대로다.

```
★5 팀 → 리그 기본 폭 + (5−3) × 3.5 = +7
★1 팀 → −7
```

**폭을 좁히지 않는 게 중요하다.** 좁히면 약팀에 유망주가 영영 안 나오고
드래프트가 심심해진다. 유닛테스트 `전력_보정이_능력치_폭을_좁히지_않는다`가 지킨다.

실측 상관계수: 고교 **0.92** · 프로 **0.97**
(연동 전엔 고교 −0.05로 **명문교와 약팀 로스터가 똑같았다.**
그래서 전국대회 우승팀이 매년 무작위로 바뀌었을 것이다)

---

## 3. 포지션 — 8포지션 두 바퀴

야수는 8포지션을 **두 바퀴** 돈 뒤에야 랜덤으로 넘어간다. 한 바퀴만 돌던 시절엔
나머지가 전부 랜덤이라 특정 포지션이 1명으로 남았고, 그 1명이 다치면 자리가
통째로 비었다.

실측: 국내 182팀 전부 야수 8포지션 최소 2명.

---

## 4. 구종 — 투수만

- **패스트볼은 항상 있다.** grade는 구속이 정한다
- 보유 수 = 목표치 × 성숙도(나이·OVR). 신인은 덜 갖추고 시작
- 변화구/오프스피드를 **다른 계열 우선**으로 섞는다
- 너클볼은 OVR 72+ 에게만 4%, 주무기로만

목표 구종 수는 **성장 로직 `npc_pitch_target`과 같은 규칙**이다. 생성이 목표보다
많이 주면 성장 로직이 할 일이 없고, 적게 주면 신인이 매년 새 구종만 배운다.

⚠ **Rust는 `pitch_catalog.json`을 읽지 않는다** (콘텐츠라서). 구종 ID가 코드
상수다 — 어긋나면 화면이 이름을 못 찾는데 조용하다.
`npm run test:rostergen`이 Rust 상수 ↔ 카탈로그를 대조한다.

경기 결과에는 영향이 없다 (`SimPitcher`가 구종을 안 본다). 화면과 성장에 쓰인다.

## 5. 연봉 — OVR × 연차 × 나이 × 팀예산 × 리그

```
base = ovrBase × ovrGrowth^(OVR − pivot)      ← 선형이 아니라 지수
      × 연차계수 (0~2년 0.40 / 3~6 0.70 / 7~11 1.00 / 12+ 1.10)
      × 나이보정 (34세부터 연 6% 감액, 하한 0.45)
      × 팀지수  (팀 예산 / 리그 평균, clamp 0.80~1.35)
      × 리그배수 (2군 0.30 · 독립 0.14)
      → 리그별 최저연봉으로 바닥
```

실측(프로 1군): 0~2년차 2.04억 / 3~6년차 2.64억 / 7~11년차 4.13억 / 12년+ 4.89억.
최고 24.33억(OVR91 13년차) · 최저 3,000만.
팀 총연봉이 예산의 36~56% — 실제 구단 운영비 비중과 맞는다.

**팀 예산 지수는 TS가 계산해 넘긴다** (`buildSalaryIndex` in `newGameV3.ts`).
2군은 같은 구단 1군 지수를 물려받는다 — 별도 예산이 없고 실제로도 모기업 사정이 정한다.

> 고치기 전엔 `1800 + (OVR−50)×220` 선형이라 **연차가 사실상 무의미했다**
> (0년차 OVR61 = 4,296만 / 12년차 OVR61 = 4,209만).

## 6. 경력 이력 — 과거를 만든다

새 게임 시점에 프로 선수의 과거를 만들어 `transactions`에 넣는다.
리그 화면 "리그 기록" 탭에 바로 뜨고, **Phase 7-1 드래프트·7-4 FA가 같은 테이블에
쓰므로 과거와 미래가 한 줄로 이어진다.**

```
2012  3라운드 지명 (고졸)   대전 팬텀스
2017  방출 후 영입         대전 팬텀스 → 부산 웨이브스
2025  트레이드            부산 웨이브스 → 인천 샤크스
2028  FA 이적             인천 샤크스 → 서울 가디언스
```

- 이적 확률 연차당 9% (사용자 확정 "중간")
- FA는 8년차부터, 재취득 주기 4년
- 입단 경로 고졸 55 · 대졸 30 · 독립 15

**소속팀 사슬을 거꾸로 만든다.** 현재 팀에서 출발해 과거로 거슬러 올라간다 —
앞에서부터 만들면 마지막 팀이 현재 팀과 안 맞아 "지금 없는 팀에 소속"이 된다.

실측(프로 1군 300명): 기록 440건 · 원클럽 66% · 12년차+ 원클럽 28%.

> **실측으로 잡은 것 2건** — 유닛테스트로는 안 걸렸다:
> 1. 출신 분포가 뒤집혀 있었다(대졸 57% / 고졸 28%). 연차를 균등하게 뽑으니
>    입단 나이가 중간값에 몰렸다. **입단 경로를 먼저 뽑고 연차를 역산**하도록 바꿨다
> 2. FA가 2027 → 2028 연속으로 나왔다. 재취득 주기를 넣었다

## 7. 군경팀(상무)

**별도 생성 + 원소속 지정** (사용자 확정). 원팀에서 빼내면 8포지션 백업 보장이 깨진다.
전역하면 원팀 엔트리가 +1 되는데 실제로도 그렇다.

```
강정민 22세 SP OVR76  병장 · 복무 22/24개월 · 2030 전역 · 원소속 서울 가디언스
```

- 전원 `militaryStatus: "현역"`, `careerStatus: "military"`
  (active면 드래프트·FA 후보 풀에 섞인다)
- 연봉 300만 — **군인 봉급이다.** 프로 최저연봉을 쓰면 안 된다
- 계급은 복무 경과 개월로 (이병 → 일병 → 상병 → 병장)
- **복무 경과를 흩뿌린다.** 전원이 같이 입대하면 2년마다 팀이 통째로 갈린다

ID는 `utils/ids.ts`의 `SANGMU_TEAM_ID`/`SANGMU_LEAGUE_ID`를 쓴다.
하드코딩이 세 곳에 흩어져 있어서 v1 ID(`TEAM_SPORTS_UNIT`, refs에 없음)가
살아남았고, **입대자가 존재하지 않는 팀으로 가고 있었다.**

## 8. 결정성

`worldSeed`가 같으면 로스터가 **완전히 동일**하다. 다르면 다르다.
새 게임은 `Date.now()`를 시드로 쓰므로 매번 다른 세계다.

선수마다 **독립 난수 스트림**을 쓴다 — 한 스트림으로 순차 생성하면 앞쪽 인원이
바뀔 때 뒤가 전부 흔들려 디버깅이 불가능하다 (`_ledger.md` P6-4).

---

## 9. 이 문서를 고칠 때

수치를 바꾸면 **`generation_rules.json`만** 고친다. 여기 수치를 옮겨 적지 않는다.
구조를 바꾸면 Rust 유닛테스트가 먼저 깨져야 한다 — 안 깨지면 그 테스트가
실데이터를 안 읽고 있다는 뜻이다(§10).

## 10. 테스트가 실데이터를 읽어야 하는 이유

이번 작업에서 **합성 데이터로는 못 잡는 결함을 세 번** 겪었다:

1. **ID 충돌** — 합성 팀명(`TEAM_UNIV_T00`~`T49`)으로는 우연히 안 겹쳐 통과했다.
   `refs.json` 실제 팀 목록으로 바꾸니 32건이 잡혔다
2. **연봉 0 검사** — 테스트 헬퍼가 인라인 규칙(`with_contract: false`)을 써서
   연봉이 0인 걸 검사하고 있었다. 실데이터 규칙을 읽게 하니 진짜 값이 나왔다
3. **출신 분포 역전** — 유닛테스트는 통과했다. 실제 300명 규모로 돌려
   분포를 찍어봐야 나왔다

→ Rust 테스트는 `generation_rules.json`·`refs.json`을 직접 읽는다.
→ 분포는 **실제 규모로 돌려서 숫자를 찍는다.** 예측하지 않는다
   (6B에서 "감독 생존 45~55%"라고 예측했다가 실측 13%로 틀렸다 — `_ledger.md` P6-6).
