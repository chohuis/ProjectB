## 1. 설계 (사용자 확정 2026-08-01)

### 1-1. 축을 갈라놓는다

| | 고교 (현행 유지) | 대학 (신설) |
|---|---|---|
| 지표 | 석차 9등급 | **학점 GPA 0.0~4.5** |
| 목표 | 대학 입학 요건 | **졸업 학점 충족** |
| 실패 | 학사 경고 → 출전 정지 | **단계화** (아래 1-3) |
| 결과 | 대학 티어 결정 | **졸업 여부 + 진로 안전망** |

고교의 9등급 로직은 건드리지 않는다 — 대학 입학 판정(`universityUtils`의
`minAcademicGrade`)이 그걸 쓰고 있고, 그건 지금 정상 동작한다.

### 1-2. 전공 — 축을 나눈다

지금은 셋 다 "훈련 효율" 하나만 준다. 각각 **다른 것**을 준다:

| 전공 | 주는 것 | 이유 |
|---|---|---|
| **체육교육** | 멘탈·지도 계열 XP 보너스 + 은퇴 후 지도자 경로 | 가르치는 전공 |
| **스포츠과학** | 회복력 보너스 + 부상 확률 감소 | 몸을 아는 전공 |
| **일반전공** | 학점 획득 +50% + **취업 안전망** | 야구 밖의 길 |

⚠ **부상 확률 감소는 기존 부상 엔진(Rust)에 계수를 태워야 한다.** 새 표를
만들지 말고 `generation_rules.json`의 기존 부상 항목에 전공 보정을 더한다.

### 1-3. 학사 경고 — 단계화

지금은 경고가 쌓이면 **바로 출전 정지**라 회복할 틈이 없다.

| 단계 | 조건 | 결과 |
|---|---|---|
| 1차 | 학기 GPA 미달 1회 | **훈련 효율 하락** (경기는 뛴다) |
| 2차 | 연속 2회 | **출전 정지** 1개 학기 |
| 3차 | 연속 3회 | **유급** — 졸업이 1년 밀린다 |

유급은 `universityWeek`을 안 올리는 방식으로 구현한다 — 학년 계수기가 이미
거기 있으므로 정본이 하나로 유지된다.

### 1-4. 졸업 요건

- 4학년 종료 시 누적 GPA가 기준 미달이면 **졸업 불가 → 유급**
- 졸업하면 미지명이어도 **일반 취업 경로**가 열린다 (전공·GPA에 따라 갈림)
- 이 분기는 **Phase 11 엔딩 화면과 묶인다** — 데이터만 먼저 남기고
  화면은 엔딩 설계 때 같이 만든다

## 2. Phase 분해

### 9-C-1. 학업 엔진 확장 (코드)

| | 무엇 |
|---|---|
| a | `types/save.ts` — `universityGpa` · `semesterGpaHistory` · `academicWarningLevel` · `repeatedYears` 추가 (주인공 JSON 블롭이라 마이그레이션 불필요) |
| b | `academicsEngine.ts` — 단계 분기. 고교는 기존 경로, 대학은 GPA 경로 |
| c | 수치를 `generation_rules.json`의 `academicsRules`로 (졸업 GPA·경고 임계·전공 계수) |
| d | 전공 3종의 효과를 각 축에 배선 (XP·회복·부상·학점) |
| e | 유급 처리 — `universityWeek`을 안 올린다 |

### 9-C-2. 진로 연결

| | 무엇 |
|---|---|
| a | 졸업 판정을 `careerTransition`에 추가 (`canGraduate`) |
| b | 미졸업이면 `continueCurrentStage`가 5년차를 허용 (지금은 4학년에서 막는다) |
| c | 졸업 + 미지명 → 취업 경로 데이터 기록 (화면은 Phase 11) |

### 9-C-3. 이벤트 42 → 90

| 갈래 | 현재 | 목표 | 소재 |
|---|---:|---:|---|
| 달력 | 20 | 24 | 개강·중간·기말·계절학기·졸업 |
| **조건부** | **8** | **44** | **학점·경고·유급 위기·전공별·팀 내 위치·드래프트 압박** |
| 랜덤 | 14 | 22 | 강의·과제·동기·MT·조교·도서관 |
| 계 | 42 | **90** | 선택지 약 50% |

조건부가 핵심이다 — 고교의 무게중심이 거기(75개)인데 대학은 8개뿐이라
"경기는 도는데 서사가 얇다"가 여기서 나온다.

## 3. 순서와 의존

```
9-C-1 엔진 ──→ 9-C-2 진로 연결 ──→ 9-C-4 검증
      └────────→ 9-C-3 이벤트 (엔진의 상태를 조건으로 쓴다)

Phase 11 엔딩 ← 취업 분기 화면 (데이터는 9-C-2에서 남긴다)
```

**9-C-3은 9-C-1 뒤에 와야 한다** — 이벤트 조건이 `universityGpa`·
`academicWarningLevel`을 읽어야 하는데, 그 필드가 먼저 있어야 한다.

⚠ 조건 평가기(`conditionEvaluator`)에 **새 조건 타입을 추가**해야 한다
(`gpa_gte`/`gpa_lte`/`academic_warning_gte`). 지금 30종에는 학업 축이 없다.
