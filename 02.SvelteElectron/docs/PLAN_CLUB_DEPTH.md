**왜 이 순서인가**

- **0이 먼저다.** 3단계(로스터 자리 넷)가 전부 "명단에 몇 명이 있나"를 전제하는데
  지금 고교 6팀이 야수 9명 미만이다. **깨진 바닥 위에 얹으면 원인을 못 가린다.**
- **1·2를 앞에 둔 건 파급이 0이기 때문이다.** 있는 데이터를 읽어 그리는 일이라
  뒤 단계의 측정을 안 흔든다. 손을 푸는 자리로도 맞다.
- **3이 가장 크다.** 로스터 자리를 다루는 넷을 한 덩어리로 본다 — 하나만 넣으면
  나머지가 구멍이 된다.
- **4가 3 뒤에 온다.** 의료팀은 **부상자 명단이 있어야** 의미가 생긴다.
  자리를 비울 수 없으면 회복 속도가 팀에 안 와닿는다.
- **6이 맨 뒤다.** 팬 수는 관중 산식을 바꾸므로 **재정 밸런스를 다시 재야 한다.**
  앞 단계들이 끝난 뒤에 한 번만 재는 게 싸다.

## 3단계 — 로스터 자리 넷 (1 · 2 · 3 · 4)

**가장 크다.** 넷이 같은 것을 다룬다 — *누가 1군 자리를 차지하는가*.

### 넣을 것

|---|---|---|

### 순서 — 안에서도 순서가 있다

**2 → 3 → 1 → 4**

- **2(IL)가 먼저다.** "자리를 비운다"는 개념이 서야 나머지가 얹힌다

- **1(엔트리)은 2·3이 선 뒤에** — 34명 중 28명, 그중 26명이라는 층이 생긴다
- **4(웨이버)는 독립적**이지만 방출 경로를 건드리므로 마지막

### ⚠ 꼬이는 자리 — 미리 적어 둔다

1. **상시 콜업이 이미 "부상 빈자리를 메운다"고 돈다.**
   IL이 들어오면 **같은 일을 두 곳이 한다.** 하나로 합쳐야 한다
2. **FA 미계약 뒤 처리**(원소속 재계약 → 은퇴)가 웨이버와 같은 자리를 건드린다.
   CLAUDE.md에 "정교화" 항목으로 이미 적혀 있다 — **같이 본다**
3. **`buildTeamRoster`·`matchLineupBuilder`가 "전원 출전 가능"을 전제한다.**
   5단계에서 정리한 `rotationSize`·`restGames`가 여기 물린다
4. **2군 로스터가 1군 엔트리 밖 선수를 받아야 한다** — 28명 밖 6명이 갈 곳
5. **경기 수·성적 분포가 바뀐다.** 26명만 뛰면 출전 기회가 집중된다 —
   **밸런스 재측정 대상**

**재는 것** 팀당 1군 인원 분포 · IL 등재율 · 콜업 빈도 · 출전 기회 집중도
