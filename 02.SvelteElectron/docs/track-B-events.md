# 트랙 B — 이벤트·소식함

## 🔴 닫힌 축 — "소식 유실"은 문제가 아니었다 (2026-08-24 사용자 판단)

이 트랙은 **"이야기 이벤트 87% 유실"**에서 시작했다. 그 축을 닫는다.

87%는 `밀려남 / 생산`이었다. 그런데 `trimMailbox`가 지우는 순서가
**① 미결 선택지 보존 → ② 안 읽은 것 → ③ 읽은 것**이라,
**읽은 소식이 먼저 버려진다.** 그건 결함이 아니라 **상한을 둔 이유**다 —
소식함은 흐르는 피드고 지난 훈련 보고·경기 결과는 지나가도 된다.

사용자 판단: *"사용자가 읽고 놔둬서 사라진 건데 그게 왜 유실이야?
그게 자연스럽게 사라지게 하는 게 메시지 크기를 정해놓은 이유 아니야?"*

### 계측도 못 믿는다

"안 읽은 채 밀려남"만 세면 될 것 같지만 **그것도 하네스 인공물**이다.
자동 진행은 `pendingAction`으로 올라오는 **미결 선택지만** 연다
(`advanceWeek.ts:1995`). 훈련 보고·경기 결과·랭킹 같은 정보성 소식은
**한 번도 안 열어서 전부 "안 읽음"으로 남는다** — 실측에서 `안읽음 500/500`이
나온 게 그 증거다. 실제 플레이어는 소식함을 훑고 "모두 읽음"도 누른다.

### 그래서 이 숫자들을 근거로 쓰지 마라

| 폐기 | 왜 |
|---|---|
| "이야기 이벤트 87% 유실" | 밀려남을 유실로 읽었다 |
| "안읽음 유실 447 → 290 → 0" | 하네스가 안 읽어서 생긴 수치 · 게다가 2시즌 값 |
| `mailboxTrimStats.dropped` | **설계대로 도는 것**을 세고 있다 |

### 굳이 다시 열려면 지표부터 바꿔라

"사라졌나"가 아니라 **"볼 기회가 있었나"**다 — 소식이 소식함에 **몇 주
머무는가**가 핵심이고, 지금 계측은 그걸 안 잰다.

⚠ 참고로 상한을 500으로 올렸는데도 **5주차에 찬다.** 생산량이 주당 100통
넘는다는 뜻이라, 상한을 더 올리는 것보다 **덜 만드는 게** 답일 수 있다.

### ⓒ 적용 — 두 띠로 고른다 + `once_per_stage_year` 수정 (2026-08-22)

#### 파고 드니 결함이 하나 더 있었다

`once_per_stage_year`가 **첫 스테이지-연도에서만 동작했다.**
`careerStageYear !== Math.floor(lastWeek / 52)`로 판정했는데 `lastWeek`는
`ctx.currentWeek`이고 **주차는 시즌마다 1로 리셋된다** — 1~51주는 몫이 항상 0이다.
고교 1학년(0)은 막혔지만 **2·3학년(1·2)은 매주 통과**했다. 대학 2~4학년도 같다.

실측이 이미 보여주고 있었다 — 연 1회여야 할 `EVT_HS_Y2_COACH_TRAIN`이 14번 떴다.
`RESUME_NEXT.md`의 함정 그대로다: **`currentWeek()`는 누적이 아니다.**

`triggeredEvents`는 `startNewSeason()`이 `makeEmptySeason`으로 갈아서 시즌마다
비워진다. 스테이지-연도도 시즌마다 오르니 "시즌에 한 번" = "스테이지-연도에 한 번"이다.
→ `triggeredEvents[id] === undefined` 하나로 정리했다.

(`season.ts`의 `clearTriggeredEvents()`는 **부르는 곳이 0인 죽은 코드**다.
초기화는 되지만 그 함수가 아니라 상태 교체로 된다.)

#### 굶주림의 형태

```
repeatable 144건 중 89건이 priority 700 이상   ← 매주 앞자리
once_per_*  114건 중 60건이 priority 100 미만   ← 영원히 진다
```

절대 우선순위라 **높고 반복되는 것이 영원히 이긴다.** 그래서 고르는 규칙을 바꿨다:

1. **이번 시즌 아직 안 뜬 것** 먼저 (`triggeredEvents[id] === undefined`)
2. 그다음 나머지 — 띠 안에서는 **예전처럼 priority 내림차순**

새 상태도 세이브 형식 변경도 없다. 이미 있는 `triggeredEvents`만 읽는다.

## 🔴 "버려지는 양"을 잘못 세고 있었다 (2026-08-23)

이월 큐를 권하면서 근거로 **"밀림 930건"**을 들었다. **틀렸다.**

`crowdedOut`은 **규칙 × 주차** 단위다. `EVT_IND_SMALL_CROWD`가 114번 밀렸다면

그 규칙은 `repeatable`이라 결국 떴다.

진짜 물어야 할 건 **"후보엔 올랐는데 끝내 한 번도 못 뜬 종수"**다:

```

  once_per_career      4종   ← 커리어가 끝이다. 영구 손실
  once_per_stage_year  2종
  repeatable           1종   ← 다시 온다
```

**930건이 아니라 7종이었다.** 그래서 **이월 큐 권고를 철회했다** — 세이브 필드

### priority가 정책과 거꾸로였다

못 뜬 7종을 보니 6종이 고교 1·3학년 이야기였다. `conditional` 258건의

| 정책 | 건수 | 최소 | **중앙** | 최대 |
|---|---:|---:|---:|---:|
| `repeatable` — 매주 또 온다 | 144 | 580 | **710** | 900 |
| `once_per_season` | 44 | 600 | **740** | 810 |
| `once_per_stage_year` — 그 해 한 번 | 36 | 45 | **60** | 85 |
| `once_per_career` — **평생 한 번** | 34 | 55 | **85** | 785 |

`once_per_stage_year` 36건은 **최대 85가 `repeatable` 144건의 최소 580에도
못 미친다** — repeatable이 하나라도 조건을 통과하면 **구조적으로 절대 못 이긴다.**
게다가 못 뜬 것들은 기회 창이 `week_lte 2~5`로 짧아 **두 겹으로 불리했다.**

### 고른 규칙에 띠를 하나 더 (ⓑ)

```

② 처음 뜨는 반복물
③ 이미 떴던 것
```

띠 안에서는 예전처럼 priority. **총량은 여전히 주당 1건.**

⚠ priority를 데이터에서 다시 매기는 안(70개 파일)도 있었는데 이쪽을 골랐다 —
**새 이벤트가 추가돼도 자동 적용**되고, 사람이 priority를 잘못 매겨도 같은
일이 안 생긴다.

⚠ `once_per_*`는 한 번 뜨면 정책이 막으므로 **후보에 남아 있다는 건 아직 안

## 🔴 소식 id 규칙 — 어기면 세이브가 안 열린다

`CLAUDE.md`가 경고하는 그 함정이다. 소식 목록이 `{#each sorted as msg (msg.id)}`로
id를 키로 잡아서, **중복이 하나만 생겨도 Svelte가 `each_key_duplicate`로 죽고
세이브가 아예 안 열린다** — 로드 화면에서 멈춘 채 단서가 없다.

```
msg-digest-w13               ✗ weekNum은 시즌마다 1로 리셋 → 해마다 겹친다
msg-digest-2027-w13          ○ 연도를 넣는다
msg-tour-open-TOUR_HS_X-2027 ○ 대상 ID + 연도
```

**커밋 전에 반드시 `npm run check:msgdup`을 돌린다.**

## 이 저장소에서 되풀이되는 함정 — 남의 트랙에서 배운 것

1. 🔴 **고치기 전에 재현부터 확인한다.** "이벤트 로더 0건"처럼 **낡은 기록이
   그대로 남아 있다.** 문서를 근거로 고치지 말고 **먼저 재라.**
2. 🔴 **계측기부터 의심한다.** 2026-08-22 세션에서 계측기가 **여덟 번** 틀렸다.
   음성 결과("0건이다", "안 돈다")가 나오면 **계측이 그 갈래를 보고 있는지**부터
   확인한다. 층 경계(TS↔Rust, 스토어↔저장소 행, 래퍼 이름↔export 이름)에서 주로 났다.
3. 🔴 **같은 판정을 하는 자리를 먼저 센다**(`grep -c`). 한 경로만 고치고
   "됐다"고 읽은 게 여섯 번이다.
4. 🔴 **적용 전후를 잰다.** 검사가 통과해도 효과가 없을 수 있다.
5. ⚠ **계측이 아직 완전히 재현되지 않는다.** 세계 생성은 결정적이지만
   시즌 진행에 흔들림이 남아 있다(A 트랙이 추적 중). **작은 차이는 3회 평균을
   쓰고, 큰 차이(0 → 수십)만 한 번으로 믿는다.**
