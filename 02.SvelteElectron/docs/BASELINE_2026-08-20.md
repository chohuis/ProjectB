### 남은 판단 (사용자에게 물을 것)

1. **스모크가 무엇을 재야 하나** — 존 중앙만 노리는 지금 방식으로는
   `bbRate 1~25` 게이트를 영영 못 넘는다. `target`을 넣어 실제 경로에
   맞추든지, 게이트를 "주인공이 존 중앙만 노렸을 때"에 맞게 다시 잡든지
   골라야 한다. **둘 다 밸런스에 닿는다 — 지어내지 않는다.**
2. **`kRate` 이름이 틀렸다** — `STRIKE_LOOK + STRIKE_SWING`은 **스트라이크
   하나**지 삼진이 아니다. 42%는 삼진율이 아니라 스트라이크 비율이다.

# 리그 경기 분포 기준선 (2026-08-20 · 씨앗 넣기 전)

`npm run measure:leaguegames -- --games 3000` 두 번. 두 번의 평균 차가

| | 1회차 | 2회차 |
|---|---|---|
| 합계 득점 평균 | 9.883 | 9.926 |

| 홈 승률 | 65.4% | 66.1% |

**씨앗을 넣은 뒤 이 표와 견준다.** 평균·분산이 움직이면 배선이 틀린 것이다 —
씨앗 고정은 "매번 다른 결과 중 하나"를 "정해진 하나"로 만들 뿐이다.

## 🔴 경로를 두 번 잘못 짚었다

① "리그 경기는 `calc_npc_fallback`이 점수만 뽑는다"고 단정했는데 **틀렸다.**
그건 **폴백**이다 — 로그가 `[폴백SIM] 주인공리그 엔티티없음`이고
엔티티가 없을 때만 탄다(`games.ts:66`).

② 리그 경기의 실제 경로는 `gameSimulator.ts:360`의
**`startMatchNative` → `simToGameEnd` → `matchToSimResultNative`**다.
즉 **리그 경기와 주인공 경기가 같은 엔진을 쓴다.**

→ 그래서 씨앗을 넣을 자리는 `start_match_native`와 `sim_to_game_end`이고,
`MatchStartOptions`(`types.rs:639`)는 `#[serde(default)]`라 필드를 더해도
옛 호출부가 안 깨진다. **`MatchState`에도 씨앗을 실어야** 여러 번 호출해도
흐름이 이어진다.

⚠ 홈 승률 65%가 실제 야구(54%)보다 높은데, 이 계측은 **엔진이 만든 합성
라인업**(`batterMean: 55`)을 쓰고 `protagonistSide: "home"`이다. **절대값을
논할 자리가 아니다** — 전후 비교용이다. 절대 분포는 실제 로스터로 재야 한다.

## 씨앗을 넣은 뒤 — 분포는 안 움직였다 (2026-08-20)

`--games 3000`을 다섯 번씩:

| | 5회 평균 | 범위 (폭) |
|---|---|---|
| 씨앗 없음 (`thread_rng`) | 10.021 | 9.95~10.095 (**0.145**) |
| 씨앗 있음 | 10.073 | 10.059~10.083 (**0.024**) |

**두 집단의 차이(0.052)가 씨앗 없음의 자체 변동 폭(0.145)보다 작다** —
분포가 안 바뀌었다는 뜻이다.

⚠ **씨앗 있음의 변동 폭이 훨씬 좁다**(0.024). 경기마다 `seed + index`로
결정적이라 표본 변동이 줄어든 것이다 — 밸런스가 바뀐 게 아니라 **재는
자가 정밀해졌다.** 앞으로 A/B가 훨씬 예민해진다.

재현 확인:
```
같은 씨앗 두 번  → 9.75 · sd 4.666 · 홈 승률 69.5%   (완전히 같다)
다른 씨앗        → 10.535 · sd 5.407 · 홈 승률 66.0%
```
