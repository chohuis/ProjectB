### 통합의 실제 작업량 — 투수 교체와 전 선수 기록

`match_engine`은 이미 **양쪽 반이닝을 다 시뮬한다.** `protagonist_side`는

`npc_starter_pitcher`도 받는다. 그래서 NPC 대 NPC도 원리적으로는 돌아간다.

진짜 격차는 이것이다:

```
match_engine   투수 **한 명**을 깊게 (스태미나·구종·폼·멘탈·로케이션)
sim_game       투수진 **전체**를 (선발→불펜→마무리 교체 · 등판 한계 · 컨디션)
               + 전 선수 기록 누적(PitAccum/BatAccum) → 리그 순위표·성적표
```

`sim_game`이 돌려주는 것: `MatchResult`(playerLines 포함) ·
`next_home_rot_idx` · `next_away_rot_idx` · `pitcher_conditions`.
**이 계약을 그대로 만족해야** 순위표·성적·로테이션이 안 깨진다.

생성도 정상이다. **48경기 중 7번만 던지고 선발은 0이다.**

⚠ **스케줄은 `seasonStore.schedule` 최상위에 있다.** 리그 맵
(`leagueState[리그].schedule`)을 읽었더니 전체 0으로 나왔다 — 그대로 믿었으면
"경기가 아예 안 잡힌다"는 없는 결함을 보고했다.

### ✅ 하네스는 결백하다 (2026-08-10)

`runAutoAdvance`의 `conditionWarning` 갈래는 경고를 **소비한 뒤 `game`
액션을 다시 밀어넣는다** (`runAutoAdvance.ts:361`). 경기는 실제로 치러진다.
48경기 전부 결과가 있는 것과도 맞다.

### 등판 여부는 `entryReached` 하나로 갈린다

`handleGame`이 엔진에 `role: (p.position as "SP"|"RP"|"CP") ?? "SP"`를 넘기고
(`runAutoAdvance.ts:96`), 엔진이 **주인공 등판 시점까지 시뮬**한 뒤
`entryReached`로 답한다. false면 그 경기엔 안 던진다. **48경기 중 7번만
true였다.**

### ✅ 확인했다 (2026-08-10) — **RP가 맞고, 악순환이 닫혀 있다**

```
              포지션   주포지션   학년   등판   이닝   ERA
시즌 시작       SP        SP        1      —      —     —
시즌1말         RP        SP        1      7     24    8.11
시즌2말         RP        SP        2      5     16   14.90
```

`SP`로 시작해 시즌 도중 `RP`로 내려가고, **`primaryPosition`은 SP로 남아
주포지션과 실제 보직이 어긋난 채 고정된다.**

**승격 경로 자체는 있다.** 포지션은 매 시즌 W1에 다시 배정된다
(`advanceWeek.ts:119`, `assignHighschoolPosition`). 고교는 SP/RP 두 범주만
쓰고 해마다 새로 평가한다 — "한 번 RP면 영구히 RP"가 아니다.

**문제는 매년 다시 겨루는데 매년 진다는 것이다.** OVR 56~62는 또래 하위 1%라
팀 내 투수 경쟁에서 선발을 못 얻는다.

```
또래보다 약함  →  선발 못 맡음  →  경기 XP 없음  →  더 약해짐
       ↑                                              │
       └──────────────────────────────────────────────┘
```

**악순환이 닫혀 있다.** 성장률을 62→80으로 올려도 효과가 안 난 이유다 —
훈련 XP만 늘고 경기 XP는 여전히 0이다.

### 다음 한 걸음 — `assignHighschoolPosition`의 판정 기준

- **OVR만 본다면** → 위 설명이 완결이고, 고칠 곳은 "주인공을 또래 수준으로
  올리는 것" 하나다
- **다른 기준(학년·감독 관계·팀 사정)이 섞여 있다면** → 손댈 지점이 더 있다

이것만 보면 이 갈래가 끝난다.

### 구원·마무리 상 (사용자 질문, 2026-08-10)

**마무리 상은 이미 있다** — `awardRules` 투수 4부문 중 세이브왕(최소 15이닝 ·
3세이브)이라 구원 투수도 충분히 닿는다. 지금 주인공이 못 받는 건 조건이
아니라 **수상 후보 명단에 아예 없어서**다(위 결함 ①).

**빠진 건 홀드왕**(셋업맨)이다. 다만 순서가 있다:
① 주인공을 수상 후보에 넣기 → ② 선발 강등 문제 → ③ 홀드왕 신설 여부

### (참고) 원래 계획 — 주인공 position 확인

가장 유력한 가설: **주인공이 SP가 아니라 RP로 배정돼 있다.**
하네스 `boot`이 포지션을 이렇게 정한다:

```ts
position: await assignHighschoolPosition({ teamId, pitching: PITCHING }, entities)
```

팀 사정에 맞춰 배정하므로 RP가 나올 수 있다. 그러면 전부 설명된다:

| 관측 | RP 가설 |
|---|---|
| 선발 0 | RP는 선발 등판이 없다 |
| 48경기 중 7등판 | 구원은 상황이 맞아야 나간다 |
| 시즌2에 2등판으로 감소 | 성적이 나쁘면 기회가 준다 |
| 이닝 23 → 6 | 구원은 경기당 1~2이닝 |

`DEFAULT_PROTAGONIST`는 `position: "SP"`인데 하네스는 배정 함수를 쓴다 —
**두 경로가 갈린 자리가 또 하나다**(이번 세션 세 번째: 생성값 읽기,
프리셋 베끼기, 그리고 이것).

```
① 하네스가 실제 배정한 position 찍기          ← 한 줄
② 실제 새 게임(NewGamePage)은 어떻게 정하나    ← 핵심
③ 둘이 다르면 → 하네스를 게임에 맞춘다
   둘이 같은데 RP면 → **게임 설계 문제다**
```

**②가 핵심이다.** 실제 게임도 배정 함수를 쓴다면 이건 계측 문제가 아니라
"투수로 시작했는데 선발을 못 맡는다"는 설계 문제이고, 육성 시뮬로서 훨씬
큰 사안이다.

등판 판정은 `advanceWeek.ts:2190` 세 갈래:
`부상 or 컨디션<35 → 회피` / `컨디션<55 → conditionWarning 정지` / `그 외 → 등판`

컨디션으로 걸렸다면 구원 등판은 나와야 하는데 **선발이 0**이라, 그보다
위(스케줄 or 로테이션 배정)가 유력하다.

## 확정된 결함 (아직 안 고침)

### ① 주인공이 수상 후보에 아예 못 오른다

기록이 두 군데로 갈려 있다:

```
주인공   seasonStore.stats[p.id]                   ← 화면 5곳이 여기서 읽는다
NPC      seasonStore.leagueState[리그].stats[id]    ← computeAwards가 여기서 뽑는다
```

`computeAwards(rules, stats)`는 리그 맵만 받는다. `SeasonEndModal`의
`a.playerId === pid` 필터는 **영원히 빈 배열**이다.

파급: `universityUtils`의 진학 점수 `awards.length * 15`도 항상 0. 경력 화면·
인생 기록에도 주인공 수상이 한 번도 안 남았다.

고칠 자리: `computeAwards` 호출 시 `seasonStore.stats[p.id]`를 **주인공 리그 맵에만**
합쳐 넘긴다 (프로 맵에 고교 기록을 섞지 말 것).

### ② 드래프트 산식에 수상 입력이 없다

`ProtagonistDraftParams`에 `peer_ovrs`·`team_ace_rank`·`tournament_score`·
`major_injuries`·`scout_score`는 있는데 **수상만 없다**. 사용자가 원한 요소 중
유일하게 빠진 것.

### ③ 드래프트 라운드 폭이 안 나온다

최신 20회 (프리셋 56 · 새 배선 · 성장률 80):

움직인다 — 지금 맞추면 두 번 한다.
