- **`devRate`는 XP에 정확히 선형**으로 먹는다 (31/62/93/124 → 주당 구속 XP 1.48/2.96/4.43/5.91).
  엔진 격리 호출로 확인. "×1.3이 안 먹는다"는 과소해석이었다
- **주인공 `potentialHidden` = 88**이고 제대로 배선돼 있다. 폴백 75로 안 떨어진다.
  감쇠(`potential_cap_factor`)는 OVR 66부터 걸린다 — 62~66 구간에선 병목이 아니다
- **고교 개인 수상 자격 조건은 문제없다** — 70이닝 이상 29~34명, 60이닝 이상 88~94명이
  매 시즌 나온다. 시스템은 잘 돈다

## 확정된 결함 (아직 안 고침)

### ① 주인공이 수상 후보에 아예 못 오른다

기록이 두 군데로 갈려 있다:

```
주인공   seasonStore.stats[p.id]                   ← 화면 5곳이 여기서 읽는다
NPC      seasonStore.leagueState[리그].stats[id]    ← computeAwards가 여기서 뽑는다
```

`computeAwards(rules, stats)`는 리그 맵만 받는다. `SeasonEndModal`의
`a.playerId === pid` 필터는 **영원히 빈 배열**이다.

파급: `universityUtils`의 진학 점수 `awards.length * 15`도 항상 0. 경력 화면·
인생 기록에도 주인공 수상이 한 번도 안 남았다.

고칠 자리: `computeAwards` 호출 시 `seasonStore.stats[p.id]`를 **주인공 리그 맵에만**
합쳐 넘긴다 (프로 맵에 고교 기록을 섞지 말 것).

### ② 드래프트 산식에 수상 입력이 없다

`ProtagonistDraftParams`에 `peer_ovrs`·`team_ace_rank`·`tournament_score`·
`major_injuries`·`scout_score`는 있는데 **수상만 없다**. 사용자가 원한 요소 중
유일하게 빠진 것.

### ③ 드래프트 라운드 폭이 안 나온다

최신 20회 (프리셋 56 · 새 배선 · 성장률 80):

```
성공 20/20   크래시 0
고교말 OVR   최소 57 · 중앙 62 · 최대 66     (또래 중앙 68)
라운드       7R 1 · 8R 1 · 9R 1
미지명       9회 (75%)
```

**산식 재교정은 아직 하지 말 것.** 등판 문제가 풀리면 입력 분포가 통째로
움직인다 — 지금 맞추면 두 번 한다.

## 사용자가 확정한 방향

- **드래프트**: 상위픽 = 팀 에이스급 + 리그 최상위 / 중간 = 리그 무난 /
  미지명 = 애매하거나 · 큰 부상 · 대회 부진. **OVR도 반영** (잘하는데 팀운 없을 수 있으니)
- **미지명부터 1R까지, 육성 결과도 최상위~하위권까지 다양하게 나와야 한다**
- **시작 프리셋은 배분만 다르고 총합은 같다** — 아키타입은 유불리가 아니라 취향
- 수상·대회활약·에이스 여부·OVR이 전부 드래프트에 반영돼야 한다

## 사용자 요청 중 아직 안 한 것

**NPC 고교 성적 → 어느 팀 몇 순위로 드래프트되는지 대응표.**
등판 문제가 풀린 뒤에 해야 기준선이 의미 있다.

### 계측할 때 반복해서 밟은 함정

- **`g.npcs`가 아니라 `npcLiveStatsStore`를 읽어라.** 생성값은 안 자란다
- **시즌 롤오버 전에 재라.** 넘어가면 그 시즌 리그 기록이 초기화된다
- **코호트를 id로 고정하라.** 은퇴·신인 유입만으로 평균이 움직인다
- **`currentWeek()`는 누적이 아니다** — 시즌마다 리셋된다
- **하네스가 게임 값을 베껴 갖고 있는지 확인하라.** `perfEntry`의 `PITCHING`이
  옛 프리셋이라 "시작 49"를 게임 값으로 착각했다. 지금은 검사가 일치를 못박는다
  (`startPresets.test.ts`)
- **커리어로 레버를 재면 부상이 섞인다.** 엔진을 직접 부르면 격리된다
