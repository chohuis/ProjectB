## ① 삼진 뒤 타자가 바뀌나 — **바뀐다**

실측으로 확인했다.

```
투수: 송세준 / 타자: 김혁환 → 삼진 (5구)
투수: 송세준 / 타자: 서태기 → …
```

앞서 못 본 것은 흘린 게 아니라 **그 증상이 있는 자리를 안 지나갔다.**
내 눈확인 스크린샷은 직선타·땅볼 아웃만 걸렸다.

## ② 문구 — **여기서 새 결함이 나왔다**

```
투수: 송세준 / 타자: 김혁환 → STRIKEOUT_SWING (4구)      ← 실측
```

`apps/desktop/ipc/match.cjs` 의 `AUTO_SIM_AB_LABEL` 이 **좁혀지기 전 코드만**
담고 있었다. 엔진 `match_engine.rs` 의 `code_str` 블록을 긁어 대조했다 —
스물넷 중 **아홉이 비어 있었다**:

```
STRIKEOUT_SWING  STRIKEOUT_LOOK  TRIPLE_PLAY  HIT_BY_PITCH  INTERFERENCE
SAC_BUNT  SAC_FLY  SQUEEZE  GAME_OVER
```

`matchResult.ts` 에는 `SQUEEZE` 하나가 없었고 **타입 유니온에도 빠져 있었다.**

되돌림값이 `?? code` 라 **빠진 것이 조용히 영어로 나갔다.** `[?CODE]` 로
바꿔 다음엔 눈에 걸리게 했다 — `careerEventLabel.ts` 에 적어 둔
"되돌림값이 원문 코드면 안 된다" 와 같은 자리다.

검사는 Rust 를 긁어 두 표를 양방향 대조한다. 손으로 적은 목록이 아니라
**원본을 읽으므로 안 낡는다.**

고친 뒤 다시 띄웠다 — `삼진(루킹) (5구)` · `볼넷 (6구)`, 원문 누출 없다.

### ⚠ 세는 법도 틀려 있었다 (내 파일)

if (isStrike(코드) && count.out > prevOuts)     // 옛것

**간접 판정**이다. 스트라이크와 아웃이 겹치기만 하면 세므로, 그 투구에
**도루 저지**처럼 다른 이유로 아웃이 늘면 삼진이 아닌데도 하나 올라간다.
네가 만든 `isStrikeout` 으로 바꿨다.

## ③ K 칸 — **스코어보드에 안 넣었다. 카드 머리글에 넣었다**

스코어보드는 `1~12 · R · H · E · B` 로 이미 17열이고 1280×720 에서 빠듯하다.

투수 카드에 넣으려고 재 봤더니 **그 자리도 안 보였다.**

```
해상도       카드 패널   머리글   목록에 남는 높이   내용
1280×720       44px     21px         0px          104px
1366×768       92px     21px        39px          104px
1536×864      190px     21px       137px          104px
```

머리글(이름 줄) 21px 은 어디서나 남는다. 거기 `K 0` 표식을 붙였고
세 해상도에서 보이는 것 · 뒤집기 버튼과 안 겹치는 것을 실측했다.

네 짐작이 맞았다 — **종료 화면에 이미 `탈삼진 K` 가 있었다.** 그게 한 시즌
내내 0 이었는데 아무도 못 봤다. 경기 중에 안 보이는 값은 0 이어도 안 걸린다.

## 넘기는 것 ① 🔴 선수 카드가 1280×720 에서 **이름만 남는다**

K 를 재다가 나온 것이다. 이건 K 와 무관하게 **원래 있던 결함**이다.

스크린샷으로 확인했다 — 상대 타자 카드에 컨택·파워가 없고 이름만 있다.
**투구를 고르라고 띄운 능력치다.**

앞서 `overflow: hidden` → `auto` 로 고쳐 **닿게는** 했는데, 닿는 것과
보이는 것이 다르다는 걸 이번에 알았다.

원인은 줄 높이가 아니다(16px · 글자 12px · 여백 0, 이미 최소). 패널 자체가
눌린다 —

```
열 높이        558 (1280×720)
상황 패널      203   (다이아몬드 104 + SBO 146)
가운데 행      285   (존 캔버스 228 · 구종 선택 [머리 31 + 목록 166 + 던지기 44])
간격            24
─────────────────
카드 행         46
```

**안 고쳤다.** 살리려면 가운데 행에서 ~100px 을 뺏어야 하는데 거기 있는 것이
존 캔버스 · 구종 선택 · 던지기 버튼 — 이 화면에서 실제로 누르는 것 전부다.
720p 에서 스트라이크 존을 줄이는 것은 CSS 손질이 아니라 **게임 감각의 결정**이라
혼자 정하지 않는다. 계측은 `docs/TRACK_C_EYECHECK.md` §9.

**묻는다:** 1280×720 을 지원 해상도로 볼 것인가. 본다면 —
① 존을 줄인다 ② 상황 패널(다이아몬드+SBO 203px)을 접는다 ③ 카드를 짧은
높이에서 가로 배치로 바꾼다. 셋 중 어느 쪽이 게임 감각에 덜 걸리나.
