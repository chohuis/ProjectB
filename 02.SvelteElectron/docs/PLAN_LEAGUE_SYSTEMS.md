## 1단계 — 무승부

**뒤 단계가 전부 여기 물린다** — 승률·순위·승률왕·MVP가 다 바뀐다.

```
규칙       연장 12회까지, 그 뒤 동점이면 무승부
현재       should_auto_finish 가 `inning > limit && home != away` 라
           **승부가 날 때까지** 한다 → 무승부가 구조상 안 나온다
바꿀 곳    Rust  should_auto_finish · to_match_result (loser_id → Option<String>)
           TS    updateStandings·decide_pitcher 는 이미 갈래가 있다 (지금 죽어 있음)
전후 실측  무승부 비율 · 홈 승률(지금 65.6%) · 순위표 승/패/무 합
```

⚠ `to_match_result`가 동점이면 `home >= away`로 **홈 승**을 적는다. 지금은
5,000틱 안전장치가 소진돼야 닿지만, 12회 제한을 넣으면 **정상 경로가 된다.**

### 🔴 갈래 B는 이미 절반 구현돼 있다 (실측 2026-08-29)

```
deriveProfileFromBudgetIndex 는 `if (out[t.id]) continue;` 로 막혀 있다
  → **성향이 세이브에 있으면 안 돈다.** 새 게임 때 한 번 채우는 폴백이다
proTeamProfiles 는 SaveGame 에 저장된다
updateProTeamProfiles 는 실제로 `winNowPressure` **하나만** 갱신한다
  (주석은 "성적으로 갱신"이라 적혀 있는데 과장이다 — 나머지 11개는 고정)
```

**즉 예산을 동적으로 만들어도 구단 성향 12개는 안 흔들린다.** 갈래 B의
핵심 요구가 구조상 이미 만족된다.

### 예산이 움직이면 실제로 영향받는 곳 — 셋뿐

| 자리 | 무엇이 바뀌나 |
|---|---|
| `buildSalaryIndex` (`newGameV3.ts:216`) | 신인 계약금 · 외국인 영입 상한 · NPC 생성 연봉 |
| `market.ts:1379` `budgetIndex` | FA 입찰 상한 |
| `seasonRollover` `targetOf` | 감독 성적 기대치 → 경질 |

⚠ **셋 다 `refs.json`을 직접 읽는다.** 동적 예산을 세이브에 두고 이 셋이
그걸 읽게 바꿔야 한다 — **한 곳만 바꾸면 세 값이 갈린다.**

### ⚠ 스태프 급여를 넣으면 딸려오는 것

- 스태프 계약(연봉·연수) — 지금 없다

- 급여 대비 능력 곡선 — 새 밸런스 표
