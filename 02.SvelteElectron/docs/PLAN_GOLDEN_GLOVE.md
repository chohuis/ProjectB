# 골든글러브 — 수비 기록부터 만든다 (2026-08-29)

**사용자 확정**: (C)안 — 수비 기록을 먼저 만들고 그 위에서 뽑는다 ·
자격선은 **높인다** · 포지션은 **고정 판정** · 대학·고교도 **가능하면 준다**.

---

## 왜 (C)인가

골든글러브는 이름이 수비상인데 **선수별 수비 기록이 한 건도 없다.**

```
FielderStats     position · name · fielding · arm · speed · x · y   ← player_id 없음
DefenseStat      errors · assists · throwOuts · throwSafes          ← **팀 단위 하나**
BatterLineAccum  수비 필드 0개
```

게다가 **리그 경기는 수비수가 누구인지 자체를 모른다**:

```
buildFielders             name = 사람 이름      (주인공 경기)  ← 동명이인을 못 가린다
buildFieldersFromLineup   name = 포지션 문자열  (리그 경기)    ← 신원이 아예 없다
                          fielding = 팀 평균 하나              ← 선수별 능력도 아니다
```

(A)안(포지션별 OPS 1위)으로 시작하면 나중에 (C)로 갈 때 판정을 통째로
다시 짜야 한다. 어차피 **수비 기록은 KBO 표에 있는 칸**이라 언젠가 필요하다.

---

## 리그 범위 — 대학·고교도 된다

```
포지션 생성   roster_gen 이 8포지션 + 백업을 **리그 무관하게** 만든다   ✅
팀당 경기     고교 20 · 대학 27 · KBL 144 · ABL 150 · JBL 143
```

⚠ **자격선을 리그별로 따로 줘야 한다.** 지금 `minPa 120`을 고교(20경기)에
그대로 쓰면 **아무도 자격을 못 채운다.**

⚠ **DH 부문은 못 만든다** — `POSITION_PRIORITY`에 있지만 `roster_gen`이 생성을
안 한다. KBO 10부문 중 9부문이다.

# Phase G-1 · 수비수 신원 배선  ✅ 2026-08-29

**이게 전제다.** 누가 수비했는지를 모르면 나머지가 전부 못 선다.

### 무엇을

```
① FielderStats 에 player_id 추가                      (types.rs)
② buildFielders — id 를 함께 싣는다                    (matchLineupBuilder.ts)
③ buildFieldersFromLineup — 포지션 문자열 대신 **실제 선수**  (gameSimulator.ts)
④ FieldingResult 가 그 id 를 물고 나온다                (match_engine.rs)
```

### ✅ 실측 — 밸런스가 거의 안 움직였다

지금 리그 경기의 수비는 **팀 평균 레벨 하나**다(`fielding: lvl`). 선수별로
바꾸면 수비 좋은 팀과 나쁜 팀이 갈린다.

```
실측 (씨앗 555 · 2시즌 · 규정투수 ~60)
  전  ERA 5.621 · 피안타/9 10.60
  후  ERA 5.686 · 피안타/9 10.53      ← ERA +1.2% · 피안타는 오히려 내려갔다

산식으로 보면
  실제 fielding  = ovr − 5 ± 6
  옛 대용값      = (contact+speed)/2 = ovr − 1 ± 4.2
  → 평균 4점 낮고 편차 1.4배인데 ERA는 +1.2%뿐이다
```

⚠ 주인공 경기는 이미 실제 수비수를 넘긴다(`fielders: buildFielders(...)`).
  **두 경로가 지금 서로 다른 수준으로 돌고 있다** — ③은 그걸 맞추는 일이기도 하다.
  (`gameSimulator` 주석에 "수비 50 vs 66이 ERA 3점 차이"라 적혀 있다.)

### 검사
- `FielderStats`에 `player_id`가 있다
- 두 빌더가 **실제 선수 id**를 싣는다 (포지션 문자열·사람 이름이 아니다)
- 변이: id를 다시 포지션 문자열로 → 잡혀야 한다

# Phase G-2 · 선수별 수비 기록 누적

### 무엇을

```
BatterLineAccum 에  errors · assists · putouts 추가        (types.rs)
step_pitch_core 의 fielding_result 를 **그 선수 줄**에 단다  (match_engine.rs)
  지금은 `fr.is_error`가 팀 카운터(DefenseStat)만 올린다
```

⚠ **오늘 삼진·도루와 같은 형태다** — 엔진이 값을 만들어 놓고 누적이 안 받는다.
  같은 실수를 반복하지 않으려면 **누적 직후 실측으로 0이 아닌지 확인**한다.

⚠ `putouts`(자살)는 엔진이 따로 안 만든다 — 아웃을 처리한 `fielder`에서 센다.
  ⚠ 삼진·볼넷은 자살이 아니다. **인플레이 아웃만** 센다.

### 실측
```
규정 수비수의 실책·보살·자살이 0이 아닌가
포지션별 자살 분포가 야구답나  (1루가 제일 많아야 한다)
```

### 검사
- Rust: 실책이 그 선수 줄에 붙는다 · 삼진은 자살이 아니다 · 팀 카운터와 합이 맞는다
- 변이: 누적 줄 제거 → 잡혀야 한다

# Phase G-3 · 시즌 집계 · 저장 · 화면

### 무엇을

```
BatterSeasonStats 에   e(실책) · a(보살) · po(자살) · fpct(수비율)
accumulateStats                        e·a·po 누적
sanitizeStatsRecord                    fpct 파생 (era·whip 과 같은 취급)
                                       fpct = (po + a) / (po + a + e)
history_lb_stats v13                   스키마 · INSERT · seasonRollover · LeaguePage
화면                                   PlayerDetailModal · StatusPage 타자 표
```

### ⚠ **네 층을 다 넓혀야 한다**

v12(2026-08-29)에서 겪은 그대로다 — 하나만 넓히면 **조용히 null**이 되고
시즌이 넘어가는 순간 사라진다.

```
스키마(db.cjs v13) → INSERT(main.cjs) → 저장(seasonRollover) → 복원(LeaguePage)
```

⚠ v13 블록은 **v12 뒤에** 넣는다. v12를 v11 앞에 넣었다가 버전이 덮여
  영원히 다시 도는 걸 실측으로 잡았다.

⚠ 복원에서 `?? 0`으로 채우지 않는다 — v13 이전 세이브엔 값이 없고, 0으로
  채우면 "실책 0인 수비수"가 되어 기록이 거짓이 된다.

### 검사
- 12칸 왕복(저장→조회)을 **실제 마이그레이션·실제 INSERT**로 태워 확인
- 자리표시자 수 = 컬럼 수

# Phase G-5 · 골든글러브 판정

### 부문 9개

```
C · 1B · 2B · 3B · SS · LF · CF · RF · P
⚠ DH 없음 (생성 자체가 안 된다)
```

### ✅ 값 셋 확정 (사용자 2026-08-29)

#### ① 포지션별 지표 — **확정: 포지션별 차등**

| 부문 | 제안 | 근거 |
|---|---|---|
| C 포수 | `수비율 × 0.5 + OPS × 0.5` | 포수는 수비가 본업 |
| 1B | `OPS × 0.7 + 수비율 × 0.3` | 1루는 방망이 |
| 2B · SS | `수비율 × 0.5 + OPS × 0.5` | 키스톤은 수비 |
| 3B | `OPS × 0.6 + 수비율 × 0.4` | |
| LF · RF | `OPS × 0.8 + 수비율 × 0.2` | 코너 외야는 방망이 |
| CF | `OPS × 0.6 + 수비율 × 0.4` | 중견은 수비 |
| P 투수 | `ERA` | 기존 부문 재사용 |

⚠ **OPS와 수비율은 단위가 다르다** — 그대로 더하면 OPS가 지배한다.
  리그 안에서 **정규화한 뒤** 섞는다(FA 예산 지수에서 쓴 방식과 같다).

#### ② 자격선 — **확정: KBO 규정 수준**

| 리그 | 팀당 경기 | 지금 minPa | **제안** |
|---|---|---|---|
| KBL 144 · JBL 143 · ABL 150 | 144~150 | 120 | **400** · minIp **100** |
| 대학 | 27 | 120 | **80** · minIp **20** |
| 고교 | 20 | 120 | **60** · minIp **15** |
| 2군 (99~121) | — | — | **골든글러브 없음** |

투수 `minIp` — KBL 규정이닝 144. 지금 **45**라 훨씬 헐겁다 → **100** 제안.

⚠ 근거: 지금 자격선으로 **규정타자가 103명**이 나왔다(10팀이면 자리가 80개).
  헐거운 게 실측으로 드러난다.

#### ③ MVP 셈 — **확정: 따로**

- (가) 같은 표 — `awardRules.golden`에 9줄. MVP 카운트에도 들어간다
- (나) **따로** — 골든글러브는 MVP 셈에서 뺀다  ← **확정**

⚠ (가)면 골든글러브 수상자가 MVP `minTitles 2`를 쉽게 채워 **MVP가 흔해진다.**
