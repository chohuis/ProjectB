# C · 역대(연혁) 탭 설계 (2026-09-01)

TRACK_C 2주차 ②. **"히스토리 화면이 없다"는 세 번째 오독이었다.**

---

## 1. 먼저 재현했다 — 있는 것과 없는 것

`LeaguePage.svelte`(1,734줄)는 **이미** 연도 선택 + 다섯 탭으로 역대 자료를
다 읽고 다 그리고 있었다.

```
헤더        <select> 현재 · 2025시즌 · …        seasonGetHistoryYears
리그 순위    seasonGetHistoryStandings
스탯 순위    seasonGetHistoryLbStats  +  history_league(kind=awards)
대회        seasonGetHistoryTournaments
포스트시즌   seasonGetHistoryPostseason
```

> **A 회신 §0 이 "없는 것은 히스토리 화면 하나다"라고 했는데 그것도 아니었다.**
> 이 저장소에서 "없다"가 틀린 게 세 번째다 — 엔딩 화면, 히스토리 화면,
> 그 전 A1. `CareerEndScreen` 머리말이 적어 둔 대로 **손대기 전에 재현**이다.

### 진짜로 없던 것

다섯 탭이 전부 **한 해를 골라** 본다. 15~20시즌을 뛰고 나면
*"어느 해에 누가 우승했나"* 를 알려면 **연도 선택을 스무 번 돌려야** 했다.

| 여러 해를 보는 뷰 | 있나 |
|---|---|
| 팀 하나의 연혁 (`TeamDetailModal`) | ✅ |
| 선수 헌액 (`HallOfFamePage`) | ✅ |
| **리그 차원의 연혁** | ❌ |

## 2. 붙인 것 — 역대 탭

**두 절만 둔다.** 사용자 확정 방침(*"복잡하지 않게"*)을 엔딩과 같게 따랐다.

| 절 | 내용 | 재료 |
|---|---|---|
| 우승 계보 | 연도 · 리그/대회 · 우승 · 준우승 | `history_postseason` + `history_tournaments` |
| 통산 수상 | 선수별 수상 합산 (2회 이상만 숫자) | `history_league` kind=awards |

### 결정 셋

**① 안 열린 대회는 계보에서 뺀다.**
대회는 안 열려도 한 줄 온다(우승 빈칸). 넣으면 "미정"이 해마다 쌓여
계보 자체가 안 읽힌다. `champion_id` · `champion_name` 이 둘 다 비면 거른다.

**② 역대 탭에서는 연도 선택을 감춘다.**
여러 해를 가로지르는 화면에 연도 고르개가 같이 뜨면 무엇을 고르라는 건지
모른다.

**③ 빈 상태가 정상이다.**
첫 시즌을 마치기 전에는 원래 아무것도 없다(A 회신 §2). *"아직 지나간 시즌이
없습니다. 시즌을 마치면 여기에 쌓입니다."* — 결함처럼 보이게 쓰지 않는다.

## 3. 조회 — 한 번에 읽는 것과 연도마다 읽는 것

### 수상은 한 번에 읽는다 (C 소유라 고칠 수 있었다)

`slotdb.cjs` 의 `getHistoryLeague` 가 **연도 없이 부르면 깨져 있었다** —

```js
// 전: year 가 없으면 `WHERE league_id = ?` 로 갔다.
//     leagueId 까지 없으면 undefined 를 바인딩해 예외가 났다.
//     타입은 둘 다 선택 인자라 부를 수 있는 모양이었는데 실행이 안 됐다.
```

`year` · `leagueId` · `kind` 를 각각 선택으로 받게 고쳤다.
이제 `{ slotId, kind: "awards" }` 한 번이면 전 연도가 온다.

### 우승 계보는 연도마다 읽는다 (지금은 그대로 둔다)

`season:getHistory*` 핸들러가 `seasonYear` 를 **필수**로 받는다.
`main.cjs` 는 A 소유라 묶은 핸들러를 못 만든다.

⚠ **연도 수 × 2회.** 커리어가 길어야 25시즌이고 탭을 열 때 한 번만 부르므로
그대로 뒀다. 느려지면 A 에게 요청한다 — 인계서 §2 에 적었다.
