# 시스템 연결 감사 — 선수생성 · 예산 · 시장 (2026-08-31)

> 사용자 지시: *"선수생성부터 예산, 트레이드… 등등 서로 연결되어 돌아가는
> 것들에 현재 상황이나 서로 충돌나는 게 없는지 제대로 분석해서, 이 부분을
> 연결하고 원활하게 만든 다음에 밸런스를 잡고 싶어."*
>
> **밸런스는 손대지 않는다.** 여기서는 **배선**만 본다.
> 기준 커밋 `0476a59a2`.

---

## 0. 감사 방법

각 연결마다 셋을 본다:

```
① 배선이 있나        값을 넘기는 코드가 있나
② 실제로 쓰이나      받아서 판정에 넣나 (죽은 갈래가 아닌가)
③ 정본이 하나인가    같은 수를 두 곳에 적어 두지 않았나
```

⚠ **좁은 필터로 세고 단정하지 않는다.** 첫 시도에서 "엔진 export 137개 중
79개가 죽었다"고 나왔는데, preload 가 이름을 바꿔 부르는 걸(예:
`militaryCalcSelection` → `calcSportsUnitSelectionNative`) 못 본 탓이었다.
네이티브 이름으로 다시 세니 **8개**였고 그중 6개는 `packages/core` 가
감싸 쓴다.

## 2. 🔴 끊긴 곳 · 충돌 — 넷

### ① 트레이드가 **예산을 안 본다** (박힌 숫자)

```ts
// market.ts:344 · 477 — 두 곳 다
salaryCap: 300000,                                  // 30억. 전 팀 동일
currentPayroll: …?.currentPayroll ?? 150000,        // 없으면 15억으로 가정
```

`refs.json` 의 팀별 예산(KBL 120~350억)이 **트레이드 판정에 안 들어간다.**
게다가 **30억은 실제 총연봉(60~86억)보다 작다** — 그래서 모든 팀이 늘
"상한 초과" 상태로 판정받는다. 부자 구단이 연봉을 떠안는 트레이드가
구조적으로 안 나온다.

⚠ 엔진 쪽(`EvalTradeValueParams`)은 `salary_cap`·`current_payroll` 을 **제대로
받고 있다.** 넘기는 쪽만 박혀 있다.

### ② `playerEvalContractOffer` 를 아무도 안 부른다

```
엔진        team_engine::base_contract_offer   있다
napi        playerEvalContractOfferNative      있다
타입 선언   projectb.d.ts:284                  있다
호출부      **0건**
```

그래서 그 안에서만 쓰이는 **`ownerSpendingWillingness` 축이 통째로 죽어
있다**(12축 중 유일하게 호출부가 0인 축이다). 재계약 제시액이 구단주
성향을 안 탄다.

### ③ 수준 축(`qualityBias`)이 **능력치 생성에 안 걸린다**

2026-08-31 에 넣었는데 **인원 산출에만 쓰고** OVR 생성에는 안 이었다.
지금 보이는 KBL 평균 OVR 차이(69.1~72.2)는 그 축이 아니라 **원래 있던
`power`(전력★) 효과**다. `roster_gen.rs` 의 `power_shift` 와 **같은 자리에
같이 더하면** 된다 — 둘 다 "이 팀이 얼마나 좋은 선수를 가졌나"라 나눌
이유가 없다.

⚠ 이걸 이으면 **OVR 분포가 벌어져 리그 밸런스가 움직인다.** 사용자 확정:
**기능을 먼저 잇고 밸런스는 맨 뒤에.**

### ④ 유망주가 예산을 안 탄다 (되돌린 자국)

`pot_cap × pot_mult` 에 편향을 곱해 봤더니 **전부 천장(84/74)에 붙어** 차이가
0이었고, 전력★ 보정으로 `core_ovr` 이 천장을 넘으면 `clamp` 가 터졌다
(검사 2건이 잡았다). 편향은 곱셈이 아니라 **`pot_mult` 샘플링 자체**에
넣어야 한다.

## 3. ⚠ 어긋난 값 · 추정 오차 — 셋

| | 무엇 | 크기 |
|---|---|---|
| a | **1인 연봉 추정이 실제보다 7% 낮다** (1,318 vs 실측 1,410) — 원주가 예산의 104%로 넘는 이유다 | 작다 |
| b | `player_engine.rs` 의 리그 배수 표는 **폴백**이다(지도가 비었을 때만). RESUME 가 "표가 둘"이라 적은 건 과했다 — 다만 폴백 값(독립 0.35)이 정본(0.14)과 다르다 | 작다 |
| c | 2군·상무·아마추어는 **예산이 없다**. "전 리그 예산 편성"은 데이터상 **연봉이 있고 예산이 있는 넷**(KBL·ABL·JBL 1군 + 독립)만 가능하다 | 범위 제약 |

## 5. 순서 — 배선을 먼저, 밸런스는 맨 뒤

```
W1  트레이드에 예산을 잇는다            ①  박힌 30억을 걷어낸다
W2  qualityBias 를 능력치 생성에 잇는다  ③  ⚠ 밸런스가 움직인다
W3  유망주 편향을 pot_mult 에 넣는다     ④
W4  playerEvalContractOffer 를 잇거나 지운다  ②  죽은 갈래를 안 남긴다
W5  1인 연봉 추정 오차 보정              3a
──────────────────────────────────────────────
B   밸런스 — 기준선을 다시 재고 타율·ERA·순위 분포를 맞춘다
```

⚠ **W2 를 넣는 순간 지금까지 잰 기준선(타율 .25~.27 · ERA 5.1~5.8)이
무효가 된다.** 그래서 밸런스는 W1~W5 를 다 넣고 **한 번에** 잡는다 —
중간에 잡으면 두 번 잡게 된다.

⚠ W4 는 **잇는 것과 지우는 것 중 하나를 골라야 한다.** 죽은 채로 두면
`ownerSpendingWillingness` 가 계속 아무 일도 안 하는 축으로 남는다.
