## ① 독립 0/12 — 왜 고를 기회 자체가 없나

### 우선순위가 고정돼 있다

`scripts/perf/perfEntry.ts`의 진로 선택 갈래(`case "careerChoice"`, L779-784):

```ts
const ovs = _policy.overseas    ? r?.overseasPassed?.[0]    : undefined;
const uni = _policy.university  ? r?.universityPassed?.[0]  : undefined;
const ind = _policy.independent ? r?.independentPassed?.[0] : undefined;
if (ovs) { ... return overseas }
if (uni) { ... return university }
if (ind) { ... return independent }
```

12판 실측(final)과 이번 3판(quick) 모두 `setCareerPolicy({draft:true, university:true, independent:true})`로 **독립을 대학보다 뒤에 둔다.** 대학이 잡히면 독립은 절대 안 온다.

### 대학 지원이 사실상 항상 합격한다

드라이버는 매번 **전력★이 가장 낮은 대학 3곳**을 고른다(`perfEntry.ts` L686-696, "약팀부터 고른다"). `universityUtils.ts`의 `TIER_REQUIREMENTS`:

```
D(★1): minAcademicGrade 9(=사실상 전원 통과) · minBaseballScore 0(=사실상 전원 통과)
```

즉 드라이버가 고르는 팀은 **입시 자체가 없는 것과 같다.** 미지명 고3은 예외 없이 대학으로 샌다.

### 실측 — 12판 전원이 결국 지명됐다

`resource/logs/d-balance101-final/#NN.json`을 다시 센 결과:

|---|---|---|---|
| 01 | 3 | 3 | military |
| 02 | 2 | 2 | pro_abl |
| 05,03,04,11 | 0 | 0 | (고졸직행) |
| 06,07 | 1 | 1 | pro_kbl |

**미지명해 = 대학년수가 12판 전부 정확히 일치한다** — 미지명될 때마다 예외 없이 대학으로 갔다는 뜻이다. 그리고 **12/12 판 전원이 결국 지명됐다**(`커리어이벤트`에 `draft_picked`가 없는 판이 0개) — 고졸 직행(HS 3학년) 1회 + 대학 4개 학년 재지원까지 **최대 5번의 지명 기회** 안에서 전원이 성공했다. 대학 진로가 "독립을 막는 것"과 별개로, **애초에 독립까지 갈 필요 자체가 거의 없다** — 이건 최근 지명 문턱 완화(`UNDRAFTED_SCORE 78→68`, 09-11 밸런스 ①)의 부수효과로 보인다. 밸런스 축을 여기 얹은 이유다(15% 몫).

### 성향(계측 페르소나)은 이 우선순위에 영향이 없다 — 실측으로 확인

`setPersona("growth"|"safe"|"lazy")`는 군 입대 시점·훈련 선택에만 쓰이고(`perfEntry.ts` L546-551, `militaryDecision` 타이밍), **진로 허브의 정책(`_policy`)은 성향과 무관하게 고정**이다. 코드로 예측되는 결론(성향을 바꿔도 독립은 안 온다)을 **실측으로 확인**했다 —

```
PB_PLAN=quick PB_SEASONS=8 npm run probe:a:simrun   (성장·안전·대충 × 씨앗 20260802 × balanced)
```

**결과 — 3/3 전부 독립 0, 성향 무관하게 예측대로**(`resource/logs/runs/#01~03.json`, 8시즌, 36분):

| # | 성향 | 진로갈래 | 미지명 뒤 갈래 |
|---|---|---|---|
| 1 | growth | pro_kbl | 3년 미지명(HS 1 · 대학 2) → **대학**에서 지명(2031) |
| 2 | safe | pro_kbl | 고졸 직행 지명(2028) — 미지명 구간 없음 |
| 3 | lazy | pro_kbl | 1년 미지명(HS) → **대학**에서 지명(2029) |

세 성향 모두 독립은 한 번도 후보에 오르지 못했다 — 미지명이 나는 즉시 예외 없이 대학으로 샜다(코드 추적과 정확히 일치). **성향은 진로 허브의 우선순위에 관여하지 않는다**는 것이 이제 코드 추적 + 실측 둘 다로 확정됐다.

### 콘텐츠는 이미 있다 — 안 쓰이고 있을 뿐

`resource/data/master/events`를 `career_stage` 조건으로 다시 센 결과, **독립 무대**: 정상 61 · 레어 15 · 유니크 8 · 히든 3 · 알림 3 · (등급 없음, 캘린더/일회성) 14. `tier_rules.json`의 "0종"은 이 콘텐츠가 들어오기(2026-09-08) **전** 기록이다.

### 1단계로 넘기는 일 — 계측 쪽

이건 **B(콘텐츠) 몫이 아니다.** 콘텐츠는 이미 있고 안 쓰인다. 손댈 곳은 계측 드라이버다:
- `check-tiercoverage.cjs`가 이미 「독립행」정책(`{draft:false, university:false, independent:true, overseas:false}`)으로 독립 콘텐츠 자체는 따로 검증하고 있다 — 그쪽은 계속 그 정책으로 커버리지만 본다.
- **12판 계열(실제 플레이 분포를 재는 판)에서 독립을 구조적으로 0으로 만드는 것은 우선순위 고정 그 자체**다. 실제 플레이어라면 "대학 갈래가 이미 나왔는데도 독립을 택하는" 경우가 있을 수 있다(예: 나이 손해를 피하려고) — 지금 드라이버는 그 선택지를 아예 표현 못 한다. 성향별 진로 우선순위를 다양화(예: 최소 한 성향은 대학보다 독립을 앞에 둔다)하는 것은 **A/D의 계측 도구 작업**이지 B의 콘텐츠 작업이 아니다.

## ② 2군 3/12 — 왜 못 밟나 (문턱이 아니라 상대순위)

### 가설이 틀렸다 — ERA/G 고정 문턱이 없다

0단계 가설은 "ERA 5.5+·8G+·연차≤2 문턱에 닿는 판이 몇인가"였다. **그런 문턱은 코드에 없다.** 실제 메커니즘(`packages/engine-native/src/team_engine.rs` `eval_calldown_candidates`):

```rust
rated(pl) = pl.ovr + form_score(pl.perf, is_pitcher, rules) * form_weight(기본 8.0)
form_score: rel = (4.50 − ERA) / 4.50, 이닝 40 미만이면 비례 축소
```

강등은 **팀 로스터 안에서 `rated`가 가장 낮은 선수**를 내리는 **상대평가**다. 그리고 이 계산은 "월간 정기"에만 도는데(월 첫 주, `market.ts` L927-936), **로스터가 이미 하한(minRosterSize) 이하면 아예 안 돈다.** 정원 초과가 아니면 매달 2명씩 내린다 — 주인공도 예외가 아니다("주인공도 강등된다", 2026-07-30 사용자 확정, `market.ts` L1130).

### KBL 드래프트는 항상 1군으로 직행한다

`careerDecision.ts`의 `acceptDraftOffer` → `openProSeason`은 팀을 바로 배정하고, 2군 배치 로직이 없다. **2군에 가는 유일한 길은 이후의 강등**이다(해외 2군 진로만 처음부터 팜에 배정된다 — 이건 "독립" 갈래이지 국내 KBL 2군이 아니다).

### 실측 — 도달한 3판의 패턴

`#02·#08·#10` (2군 도달) 전부 같은 모양이다: 프로 데뷔 시즌(1군, 종종 G=0 무등판) → **이듬해 2군** → 그다음 해 1군 복귀. 예:

```
#02  2031 1군 G=0        2032 2군 G=2 ERA3.38   2033 2군 G=24 ERA6.62   2034 1군 복귀
#08  2030 1군 G=4 ERA7.01 2031 1군 G=0           2032 2군 G=11 ERA3.77  2033 1군 복귀
#10  2031 1군 G=4 ERA10.23 2032 1군 G=2 ERA4.5   2033 2군 G=21 ERA5.38  2034 1군 복귀
```

ERA가 높아서 내려간 것도 있고(#10, ERA 10.23) 아예 안 던지고도 내려간 것도 있다(#02, #08 — G=0인 해 다음에 내려갔다). **공통점은 성적이 아니라 "그 팀 로스터 안에서 가장 약했는가"**다 — 나머지 9판은 협의의 문턱을 못 넘어서가 아니라, **그 시즌 그 팀의 다른 투수들이 주인공보다 더 약했기 때문에** 안 내려갔다.

### 콘텐츠는 이미 있다

2군(팜) 무대: `league_id` 조건(`LEAGUE_KBL_FARM`/`ABL_FARM`/`JBL_FARM`)으로 센 결과 정상 60 · 레어 16 · 유니크 8 · 히든 3 — 역시 2026-09-08 작성분(`_newNote` 동일)이라 독립과 사정이 같다.

### 판정

**밸런스/메커니즘 100% — 콘텐츠 아님.** 도달률은 "그 시즌 그 팀 로스터 구성"이라는 우연에 좌우된다. 이건 성적 문턱을 낮추거나 데이터를 채운다고 오르지 않는다 — 강등 알고리즘 자체(상대순위·월간 정기 주기)를 건드려야 오르는데, **밸런스는 동결**이다(사용자 확정). 1단계에서 콘텐츠로 풀 수 있는 문제가 아니라는 것이 이번 진단의 핵심이다.

## ③ 군 이벤트 노말 24~28 — 종수가 아니라 확률 상한

### military은 다른 무대와 완전히 다른 엔진이다

고교·대학·독립·프로는 전부 `tier_rules.json`의 등급 가중 추첨(노말 87%·레어 7%·유니크 5%·히든 1%, 주마다 후보 중 추첨)을 쓴다. **군(현역)은 이 시스템을 아예 안 탄다.** `apps/ui/src/shared/usecases/militaryLife.ts`(`runMilitaryLifeWeek`)가 별도 루프를 돈다:

```
① 전입·전출·진급 → ② 캘린더(확률 밖) → ③ 선택 → ④ Rust 자원 계산
→ ⑤ 이벤트(캘린더가 떴으면 건너뜀 · 아니면 40% 한 건) → ⑥ 소식 → ⑦ 상태 갱신
```

`resource/data/master/military/rules.json`:

```json
"event": { "weeklyChance": 0.40, "defaultCooldown": 4 }
```

**주당 최대 1건, 확률 40%.** 등급(노말/레어/유니크/히든) 구분 자체가 이 루프에는 없다 — 대신 캘린더(고정 일정) 20건과 무작위 뽑기 풀(생활 46종 + 구현역 20종)이 있을 뿐이다.

### 이론 상한이 목표(30~52) 아래다

`resource/data/master/military/calendar.json`을 실제로 세면 **22건**이고, 복무 100주 전체(1~100주)에 **고르게 퍼져 있다**(1·2·4·5·6·12·12·16·20·28·35·44·46·52·61·64·64·68·70·84·96·100주). 52주 시즌 기준으로 환산하면 캘린더 ≈ `22 × 52/100 ≈ 11.4`건, 비-캘린더 주 ≈ `52 − 11.4 ≈ 40.6`주. 여기에 40% 단일발동을 곱하면 무작위 발동 ≈ `40.6 × 0.40 ≈ 16.2`건. **합계 ≈ 27.6건/시즌** — 실측 28.1(12판 최종)과 거의 정확히 맞아떨어진다.

**종수를 얼마나 늘리든 이 상한은 안 바뀐다.** 후보 풀이 20종이든 100종이든, "주당 40%, 1건"이라는 확률 게이트가 발동 횟수의 위쪽을 막는다. **PLAN_102 §2 1단계의 B-1("군 노말 이벤트 15~25종 추가 — 목표 30~52에 닿게")은 이 진단으로는 성립하지 않는다** — 종수를 늘리면 반복·폴백은 줄지만 **노말 발동 횟수 자체는 30을 크게 못 넘는다.**

### 부수 발견 — `military_common.json`(18종)이 신규 게임에서 통째로 죽어 있다

`runMilitaryLifeWeek`(militaryLife.ts L195-205)가 실제로 후보로 쓰는 것은:

```ts
const legacyGeneral = m.militaryGeneralEvents.map(toLifeEvent).filter(...);   // military_general.json 20종
const candidates = eligibleEvents([...m.militaryLifeEvents, ...legacyGeneral], ctx);
                                    // military_life.json 비-캘린더 46종 + 위 20종 = 66종
```

`m.militaryCommonEvents`(`military_common.json`, 18종)는 **master.ts가 로드는 하지만(L1258) 이 새 경로 어디서도 안 읽는다.** 실제로 쓰이는 곳은 `advanceWeek.ts` L2600대의 **옛 갈래**(`!isSportsUnit && g.protagonist.militaryLife` 조건이 거짓일 때 — 즉 **상무(체육부대)이거나, `militaryLife`가 없는 구 세이브**)뿐이다.

그런데 새 게임의 **일반병 입대는 예외 없이 `militaryLife`를 만든다**(`militaryDecision.ts` L51-54, `unit === "general"`이면 무조건). 그래서 이번에 잰 12판(전부 일반병, `sportsUnit` 정책 미지정=기본값 false)에서 `military_common.json`의 18종(가족 면회·부대 소식·위문·전역 편지 등)은 **한 번도 뜰 수 없었다.** id 교집합도 0/18로 완전히 분리돼 있다(생활 풀과 이름이 하나도 안 겹친다).

### 판정과 1단계로 넘기는 일

**밸런스(확률 상한) ~80% + 배선 버그(콘텐츠 죽음) ~20%.** 콘텐츠 종수 부족이 원인이 아니라는 것이 이번 진단의 핵심이지만, **"66종 중 18종이 애초에 못 뜬다"는 것은 순수 배선 문제**이고 고치면 종수가 66→84로 늘어 폴백·반복은 줄어든다(단, 노말 총 발동 횟수의 위쪽 한계는 안 바뀐다).
