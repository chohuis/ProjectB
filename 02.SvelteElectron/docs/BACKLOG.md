#### B5. 실측이 잡은 것 — **게이트는 통과하는데 실전은 0명**

`npm run measure:devplayer` (2시즌). B4 커밋 직후 재보니 미지명자의 2군
배정이 **여전히 0명**이었다. 게이트가 못 잡은 이유가 둘 있었다.

**(1) 육성선수를 정원 안에 넣고 있었다.**

게이트는 **빈 2군**에 넣어 보므로 자리가 남아돈다. 실제 2군은 정식
로스터로 꽉 차 있다 — 실측 `[32,33,33,33,34,34,34,34,34,34]`, 여유 5자리.

```
farmMax(34) = 정식 정원   ← 이것만 쓰면 로스터가 찬 순간 제도가 없는 것과 같다
intakeMax(10)             ← 정원 밖 인원. 34 위에 얹는다 (KBO도 정식 등록 외)
```

무제한이면 반대로 2군이 육성선수로 채워져 드래프트 가치가 사라지므로
팀당 상한을 둔다.

**(2) 자리가 실력이 아니라 순서로 갈렸다.**

오프시즌 배정은 방출자와 미지명 졸업생을 **한 루프**에서 돌리는데
인덱스 순이었다 — 기존 NPC(방출자)가 앞, 졸업생이 뒤. 육성 슬롯 100개를
방출자가 연 ~95명 먹어서 졸업생은 0명이었다. `apply_draft` 쪽은 원래
능력치 순이고("좋은 선수가 먼저 자리를 잡는다"), **같은 판정이 경로에
따라 기준이 달랐다.** 오프시즌도 능력치 순으로 맞췄다.

**실측 추이** (2시즌, seed 20260803):

⚠ 짧은 미리보기(195px)는 멀쩡했고 **긴 것 하나만** 터졌다.

**③ 화면이 없는 정지 조건이 세이브를 잠갔다.** `preGameBriefing`을 빼자
그게 큐에 든 채 저장된 세이브가 W6에서 멈췄다 — `hasPendingAction`은 true라
"다음 주 진행"이 `onOpenPending()`만 하는데 화면엔 아무것도 안 뜬다.

⚠ ③은 "이전 버전 호환 불필요"와 별개 문제다. **지금 쓰는 세이브가 죽는다.**
