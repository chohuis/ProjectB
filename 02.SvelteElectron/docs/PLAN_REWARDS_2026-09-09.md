## 2. 🔴 구종 보상 — 사용자 확정

**① 유니크부터.** 노말·레어는 구종을 안 준다.
**② 훈련이 주, 이벤트는 가속.** 새 구종은 기본적으로 훈련으로 배운다. 이벤트는 **진행도를 크게 당기거나 등급을 올린다.** 안 뜨면 손해가 아니라 **늦어질 뿐**이라 운에 덜 휘둘린다.
**③ 🔴 배우는 중이냐로 갈린다** (사용자 지적: 「기존에 배우고 있는 것만 경험치로 뜨거나, 새로 배우는 건 기존에 배우는 게 안 뜨거나 하는 게 있어야 하지 않나」)

| 상태 | 뜨는 보상 | 왜 |
|---|---|---|
| **구종을 배우는 중** | 그 구종의 **진행도 점프** 또는 **등급업** | 배우던 것이 헛되지 않는다 |
| **안 배우는 중** | **새 구종 부여** | 줄 자리가 비어 있다 |

⚠ **효과 키로 분기하지 않고 조건으로 후보를 가른다.** 「배우는 중인데 새 구종을 받아 배우던 게 사라진다」가 없어야 하고, 「안 배우는데 진행도 점프를 받아 아무 일도 안 난다」도 없어야 한다.
→ **새 조건 타입 `pitch_learning`**(배우는 중인가)이 필요하다. **A 몫.**

**④ 계측 플레이어의 구종 관리는 성향 셋이 다 같다**(사용자 확정). 지금 규칙 그대로 — 목표 미달이면 난이도 낮은 것부터 배우고, 채우면 등급 낮은 것을 올린다(`runAutoAdvance.ts:298` · NPC 와 같은 규칙).

## 6. 🔴 실측 정정 — 「효과 없는 선택지 182개」는 잰 것이 틀렸다 (B · 2026-09-09)

§0·§3 의 **182** 는 **효과의 두 꼴 중 하나를 못 읽어서 나온 숫자**다. 선택지 효과에는
객체형(`{ "xp": { "command": 2 } }`)과 **배열형**(`["xp.command:+2"]`)이 있는데,
배열형을 「효과 없음」으로 세면 **없는 결함 141건**이 잡힌다.

둘 다 읽고 다시 세면:

| | 잰 값 |
|---|---:|
| 효과 없는 선택지 — 이벤트 | **29** |
| 효과 없는 선택지 — 군 풀 | **12** |
| 갈래 둘 이상인데 **전부 효과 없음** | **0** |
| 갈래들의 효과가 **서로 같음** — 이벤트 | **0** |
| 갈래들의 효과가 **서로 같음** — 군 풀 | **4** ← 실제 일감 |
| 갈래가 **하나뿐**인 것 (효과 없어도 되는 것) | 이벤트 1 · 군 풀 64 |

**고칠 것은 넷이었다** — 선임과 갈등 · 첫 정기휴가 · 정기휴가 2 · 병장 진급.
나머지 29+12 는 **다른 갈래가 효과를 가지고 있어** 고를 뜻이 산다.

⚠ 이 트랙에서 잣대가 먼저 틀린 것이 **일곱 번째**다(등급 축 · 연차 표기 셋 ·
공유 문안 · 학년 게이트 · 합쇼체 어미 · 되풀이 · 효과 두 꼴). **세는 코드는
데이터가 실제로 쓰는 표기를 먼저 훑고 짜야 한다.**

그래서 **「히든의 `pitchGrant` 만 크게」를 지금 스키마로는 못 적는다.** 부여는

### 7.3 A 권장 — **㉡ 이 아니라 ㉠ 의 좁은 꼴**

㉡ 은 히든에서 **새 구종 부여라는 종류 자체를 없앤다**. 그런데 §2 ③ 의 표는
「안 배우는 중 → 새 구종 부여」를 **상태로** 못박았다 — 그 자리를 히든에서만
지우면 히든이 유니크보다 **좁아진다**(거꾸로다).

그래서 제안은 **부여 등급 칸을 열되 「없는 구종」 갈래에만 뜻을 준다**:

```
pitchGrant: { id, grade?: 1 | 2 }        // 기본 1
  없는 구종      → { id, grade: grade ?? 1 }
  이미 있는 구종 → grade +1  (지금 그대로 · `grade` 칸은 **안 본다**)
```

- **「이미 있는 구종」 갈래는 한 줄도 안 건드린다** — ㉠ 의 겹침이 여기서 사라진다.
- 검사 ⑥ 의 짝: **`tier === "hidden"` 이고 `pitchGrant` 가 있으면 `grade === 2`**.
  대조군은 유니크 `pitchGrant` **여섯** — `grade` 없이 초록이어야 한다.
- 「크기가 아니라 종류」와의 충돌은 **남는다.** 다만 히든의 다른 보상도
  `statDelta +3` · `potentialDelta +3` 처럼 **크기로** 갈리고 있어(§1 표),
  구종만 예외로 두는 값이 더 커 보인다.

⚠ **밸런스 값이다 — 건마다 사용자에게 묻는다**(`CLAUDE.md`). 정해지면:
`types/main.ts` · `game.ts` 는 A, 데이터 1 칸과 `_rewardNote` 는 B.
