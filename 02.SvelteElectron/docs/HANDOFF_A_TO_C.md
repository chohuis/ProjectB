## 2. 🔴 계측했다 — **저장은 되고 있다. 0행의 원인은 다른 데 있었다**

### 먼저 고친 것 — 네가 지적한 두 겹의 묻힘

지적이 정확했다. `throw` 가 아니라 `{error}` **반환**이라 `.catch()` 가 안 걸리고
resolve 된 값은 아무도 안 읽었다. 네 곳 전부 고쳤다:

```
seasonRollover.ts   saveHistoryStep() 을 새로 두고 네 호출을 그리로 모았다
                    · rows 0 이면 "0건이라 건너뛴다"
                    · {error} 면 그 문자열을 남긴다
                    · 성공이면 저장 행 수를 남긴다
main.cjs            핸들러가 {ok:true} 만 주던 것을 {ok:true, saved:n} 으로.
                    실제로 쓴 행 수(`stmt.run().changes` 합)를 돌려준다
```

⚠ **처음엔 내 로그도 거짓말을 할 뻔했다.** 핸들러가 `saved` 를 안 주니
내 헬퍼가 `rows.length`(= **보낸** 행)를 대신 찍고 있었다. 보낸 것과 쓴 것이
다를 때 그걸 못 가리는 건 네가 지적한 문제와 같은 형태다 — 그래서 핸들러까지
고쳤다.

### 실측 — 한 시즌 실제로 돌렸다

```
[역대기록] 순위: 238행 저장
[역대기록] 개인기록: 6723행 저장
[역대기록] 포스트시즌: 9행 저장
[역대기록] 대회: 8행 저장
        ↑ 2026 시즌
[역대기록] 순위: 238행 저장
[역대기록] 개인기록: 6873행 저장
[역대기록] 포스트시즌: 9행 저장
[역대기록] 대회: 8행 저장
        ↑ 2027 시즌
```

**네 종류 전부 저장된다.** SQL 실패도, 0행 가드도 아니었다.

### 그럼 네가 본 0행은 왜인가 — **시즌이 한 번도 안 끝났다**

네 인계서 마지막 줄에 답이 있다:

> *"주인공이 고교 1학년 6주차라 첫 시즌도 안 끝났다"*

`saveSeasonHistory` 는 `runWorldSeasonEnd` 에서만 불린다. **시즌 종료를 한 번도
안 거친 세이브에 시즌 기록이 없는 건 결함이 아니라 상황이다.**
`history_standings` 190행만 있던 것도 그래서 맞다 — 그건 새 게임이 심는
가짜 과거 5년이고, 그 시점엔 그것만 있는 게 정상이다.

⚠ **`CLAUDE.md` 의 "결함인가 상황인가" 기준 그대로다** — 시간이 지나면
스스로 채워진다. 다만 **"코드만으로 못 가른다"는 네 지적은 그대로 유효하고**,
그래서 고친 것이다. 다음엔 로그 한 줄로 갈린다.

**히스토리 화면(A2)의 재료는 실제로 쌓인다.** 시즌을 넘긴 세이브로 보면 된다.

## 3. ✅ 문서 셋 다 고쳤다 — 그리고 하나는 네 판단이 반쪽이었다

| # | 네 지적 | 처리 |

| 3 | `newGameV3:600` 주석 "238팀 × 5년 ≈ 1,190행" → 실제 190행 | **맞다.** 아래 |

⚠ **②에 한 줄 더 있다.** `career_history` 는 `slotdb.cjs` 만이 아니라
**`db.cjs` 에도 있다** — 양쪽에 같은 이름이 있다. 문서에 그렇게 적었다.

### ③ — **코드가 아니라 주석이 틀렸다**

`buildPastStandings` 를 읽어 보니 필터가 의도적이다:

```ts
const PAST_LEAGUES = new Set(["LEAGUE_KBL", "LEAGUE_ABL", "LEAGUE_JBL"]);
if (!t.id.endsWith("_1")) continue;      // 2군은 순위표를 안 쓴다
```

프로 3리그 1군 38팀 × 5년 = **190행**. 코드가 맞고 주석이 틀렸다 —
주석을 고쳤고 근거를 적어 뒀다.

**다만 네가 물은 것(연감이 프로만 나오는 게 의도였나)은 아직 안 정해졌다.**
아마추어에 가짜 과거 순위를 넣을지는 **기획 판단**이라 사용자에게 물을
목록에 올렸다. 지금은 프로만 나오는 게 맞다고 보고 진행해라.

## 4. C 에게 — 이어서 갈 방향

**네 판단대로 `protagonist.careerRecords` 로 짜는 게 맞다.** IPC 를 안 타는
것도 맞고, 시즌마다 `applyProtagonistSeasonRecord(now)` 가 채운다
(`runWorldSeasonEnd:128`).

한 가지 보태면 — **주요 사건**에 쓸 `careerEvents` 에 오늘 A 가 하나를 더했다:

```
NPC 트레이드가 경력에 안 남고 있었다 → 남기게 고쳤다 (market.ts)
실측: 3시즌에 KBL 28 · ABL 16 · JBL 16 건이 새로 남는다
```

예전엔 트레이드로 팀이 바뀌어도 **인생 기록엔 한 줄도 안 떴다.**
이제 뜬다 — 엔딩 화면의 "주요 사건"에서 쓸 수 있다.

⚠ 주인공 본인의 `careerEvents` 는 별개 경로다(`game.ts`). 거기 트레이드가
남는지는 아직 안 쟀다 — 엔딩 화면을 짜다 비어 보이면 알려라.
