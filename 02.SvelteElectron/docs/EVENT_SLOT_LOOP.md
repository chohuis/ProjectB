# 칸별 이벤트 점검 루프

> **한 무대(칸)를 끝까지 훑는 절차.** 2026-08-25 · 고교 칸을 돌면서 굳혔다.
>
> 순서가 중요하다. **재는 것 → 결함 → 배분 → 콘텐츠**다. 거꾸로 하면
> 안 뜨는 이벤트에 새 이벤트를 얹게 된다 — 고교에서 실제로 그럴 뻔했다.

---

## 0. 들어가기 전 — 두 가지를 구분한다

```
후보 > 0, 발동 0   조건은 통과했다. 뽑기에서 졌을 뿐  →  **정상**
후보 = 0, 발동 0   조건이 한 번도 안 통과했다        →  **결함**
```

🔴 **이걸 안 가르면 뽑기 운을 결함으로 읽는다.** 고교에서 "51종이 안 뜬다"고
했는데 실제로는 15종이 그냥 안 뽑힌 것이었다. `measure:slotreach`가
`candidateByRule`로 갈라 찍는다.

⚠ **랜덤 갈래는 단일 실행으로 전후를 비교하지 않는다.** 같은 규칙이 실행마다
2↔9로 흔들린다. 조건부 갈래는 훨씬 안정적이다. 구조로 설명되는 변화만
"고쳤다"고 말한다.

---

## 1. 잰다

```bash
node scripts/measure-eventslots.cjs                  # 재고 — 칸에 몇 개 있나
npm run measure:slotreach -- --seasons N             # 소비 — 몇 개나 닿나
npm run measure:eventrules -- EVT_… EVT_…            # 이름을 댄 규칙의 시즌별 증가분
```

⚠ `--seasons`는 **그 무대를 다 덮을 만큼** 잡는다. 고교 3년을 3시즌으로 쟀더니
136주(2.6년)라 3학년 후반이 통째로 "안 닿음"으로 나왔다 — 결함이 아니라
계측 창이 짧았던 것이다.

---

## 2. 결함을 찾는다 — 다섯 형태

이 트랙이 만난 것들이다. **전부 아무도 안 죽고 로그도 안 남는다.**

| # | 형태 | 게이트 |
|---|---|---|
| ① | 매니페스트가 없으면 19건짜리 스텁으로 조용히 폴백 | 로더가 `throw` |
| ② | 조건 **필드 이름**이 어긋나 영원히 false | `check:eventconditions` |
| ③ | 본문이 효과를 약속하는데 실을 자리가 없음 | `eventDataHygiene` |
| ④ | 풀 경로 하드코딩 — 새 풀을 아무도 안 읽음 | `eventPools` |
| ⑤ | 주차를 **누적**으로 매겨 영원히 false | `weekRange` |

칸을 돌 때 이 다섯을 먼저 확인한다:

```bash
npm run check:eventconditions   # 조건 타입·필드
npm run check:effectkeys        # 보상 키
npm run check:playertype        # 투수 전용 선언
npm test                        # 위 검사들 포함
```

**그리고 그 칸에서만 볼 것:**

- 조건이 그 무대에서 **도달 가능한가** — 성실은 오르기만 해서 `diligence_lte 30`이
  영원히 false였다(`diligenceRange.test.ts`). 축마다 실제 범위를 본다
- 규칙 id가 말하는 것과 **템플릿이 띄우는 글**이 같은가 (오배선)
- 무대 전용 조건이 빠지지 않았나 — 고교는 `grade`, 대학은 `school.universityWeek`,
  프로는 `proServiceYears`/`leagueYears`

## 3. 배분을 본다

```
한 풀의 경쟁 종수 × 추첨률 → 종당 기대 발동
```

⚠ **가중치를 아무리 잘 맞춰도 산수는 못 이긴다.** 42종이 35뽑기를 나누면
균등해도 종당 0.84회다. 눈금(가중치)과 총량(추첨률)은 **다른 문제**다.

- **눈금** — 배치마다 자가 다르면 결함이다. 세 풀 다 중앙값 18인데 한 배치만
  5~9였다. 순서는 지키고 눈금만 옮긴다
- **총량** — 밸런스다. **값은 사용자에게 묻는다**
- **갈래** — 한 풀에 100종이 넘으면 주제별로 가른다. 추첨률은 **종수에 비례**시켜
  종당 기회를 맞춘다

⚠ 겹침은 **그룹 수가 아니라 잉여 규칙 수**로 센다. 풀을 가르면 그룹은 늘고
크기는 준다 — 그룹 수로는 나아진 걸 나빠진 걸로 읽는다.

---

## 4. 콘텐츠를 손본다

**순서: 지운다 → 고친다 → 더한다.**

1. **지운다** — 뜰 수 없는 것, 같은 글 중복, 죽은 갈래
2. **고친다** — 오배선 템플릿, 안 쓰는 어휘 물리기(돈·관계·태그)
3. **더한다** — 소재가 **어디에도 없는 것**만

🔴 **더하기 전에 552종 전체를 주제로 스캔한다.** 고교에서 아이디어 30개를
냈는데 22개가 이미 있는 소재였다. 새로 만들면 겹치고 주당 1칸을 서로 뺏는다.

⚠ **밸런스 수치는 사용자에게 묻는다.** 돈 단위는 **만원**이고 고교생 주
순현금이 5.5다 — 눈금을 모르고 값을 쓰면 안 된다.

## 5. 닫는다

```bash
npm run gen:manifest            # 🔴 빠뜨리면 새 규칙이 조용히 안 실린다
npm test
node scripts/measure-eventslots.cjs     # 재고 전후
npm run measure:slotreach -- --seasons N # 소비 전후
```

커밋 메시지에 **전후 숫자**를 적는다. 잡음 안이면 "확인 못 했다"고 적는다 —
구조로 설명되는 것과 계측으로 확인된 것을 섞지 않는다.
