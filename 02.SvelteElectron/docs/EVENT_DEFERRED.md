**(a) 코드 소식으로 옮긴다** — `weekPhases/`에 발행부를 만든다.

**(b) 템플릿에 치환을 넣는다** ← **추천**

```jsonc
// 지금
"body": "4월이 끝났습니다.\n시즌 첫 달의 기록이 정리됐습니다."
// 뒤
"body": "4월이 끝났습니다.\n{{stats.w}}승 {{stats.l}}패 방어율 {{stats.era}} — {{stats.ip}}이닝."
```

- 한 번 만들면 **467개 템플릿이 전부 쓴다.** 결산뿐 아니라 "{{teamName}}과의 경기
  전날"·"{{coachName}} 코치가"도 열린다 — 지금은 **인물 이름조차 못 넣는다**
- 조건 어휘에 이미 **경로 135개**가 있다. **같은 표를 쓰면 된다**
  (`{{stats.era}}` · `{{standing.wins}}` · `{{money}}`) — 새 어휘를 안 만든다

⚠ **값이 없을 때 문장이 깨진다.** 안 던졌거나 타자면 `stats.era`가 `undefined`다.
조건 쪽은 "값 없음 = false"로 넘기는데 치환은 그럴 수 없다 — 기본값이나
대체 문장이 필요하다.

**(c) 이벤트를 지우고 기존 코드 소식이 덮게 한다** — **이미 대체물이 있는
경우만.** 고교 TOP10 3종이 그렇다. ⚠ 발행 시점이 다르다(이벤트 `week_eq 18/34`
· 코드 소식 월간) — 지우기 전에 그 시기를 덮는지 확인해야 한다.

## 7. 실측 갱신 (2026-09-03 · B) — 숫자 둘이 바뀌었고 (c) 는 확인됐다

### 7-1. 「템플릿 467개 중 치환 0개」 → **529개 중 0개**

템플릿이 467 → **529** 로 늘었다(사교 풀 둘 · 보직·계약·투구 문안은 별도 파일).
**치환을 쓰는 건 여전히 0개다** — 전수로 다시 셌다.

### 7-2. 「23종」은 좁게 센 값이다 — id 로 훑으면 **40종**

결산·시상·순위·로스터·평가·리포트·마일스톤 어휘로 이벤트 전수를 훑으면 40종이
나온다. 23종은 그중 프로·대학·고교의 대표만 센 것으로 보인다. **어느 쪽이든
"값을 말해야 하는데 고정 문구"라는 성질은 같다** — 착수할 때 40종으로 세라.

### 7-3. ✅ (c) 고교 TOP10 3종 — **덮인다.** 지우기 전 확인이 끝났다

§4 (c) 가 "발행 시점이 다르다 — 지우기 전에 그 시기를 덮는지 확인해야 한다"고
남겨 둔 건이다. 코드에서 읽었다:

```
코드 소식  advanceWeek.ts:757  weekInYear % 4 === 0 && weekInYear >= 4
           → W4 · W8 · W12 … 시즌 내내 4주마다
이벤트     EVT_HS_Y1/Y2_TOP10_REPORT  week_eq 34
           EVT_HS_Y3_TOP10_REPORT     week_eq 18
```

**W34 는 W32·W36 사이, W18 은 W16·W20 사이다** — 이벤트를 지워도 같은 정보가
**2주 안에** 실제 순위로 뜬다. 게다가 코드 소식은 순위를 말하고 이벤트는
10위 밖이어도 "이름을 올렸습니다"라고 한다(§2).

→ **셋은 (c) 로 닫을 수 있다.** 다만 **콘텐츠를 지우는 일이라 사용자 결정이
필요하다** — B 가 임의로 안 지웠다.
