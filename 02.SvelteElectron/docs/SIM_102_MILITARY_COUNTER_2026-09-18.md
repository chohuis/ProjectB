## 가설

1. **군 이벤트 강도는 `tierCounters`로 못 잰다** — 군 복무 주는 등급
   시스템(`eventFunnel`)을 아예 안 탄다(`advanceWeek.ts` 2636~2699 ·
   `militaryLife.ts`에 그쪽 import 자체가 없음, 야드스틱 문서 실측). 대신
   `runMilitaryLifeWeek`가 캘린더(확률 밖)와 40% 단일발동 뽑기로 돈다 —
   이 둘을 직접 세는 계수기가 있어야 목표(`tier_rules.json
   seasonFreqByStage.군` 24~30)와 비교할 수 있다.
2. **계측 워커의 필러 루프가 `prev`를 안 되돌린다** — 진로가 갈려 해가
   통째로 빠지면(`probe-a-simrun-worker.cjs`의 「못 접은 해」 처리) 빈 줄을
   만들 뿐 등급 카운터 기준점(`prev`)은 그대로 둔다. 그래서 다음 실제
   `isSeasonEnded()`의 델타가 못 접은 구간 전체(주로 직전 무대의 정상 사건)를
   같이 먹고, 그 값이 다음 줄의 이름표(무대)를 달고 찍힌다 — 군 줄에 49~113
   같은 큰 값이 새어 들어온 원인.

## 방법

### ① 군 전용 계수기 — `militaryLifeCounters`

`apps/ui/src/shared/usecases/militaryLife.ts`에 계측 전용 계수기를 심었다:

```ts
export const militaryLifeCounters = { 캘린더: 0, 뽑기: 0 };
export function resetMilitaryLifeCounters(): void { ... }
```

`runMilitaryLifeWeek`의 ⑤ 이벤트 분기 — 캘린더가 떴을 때와 40% 뽑기가
성공했을 때 각각 `isMeasureMode()` 가드 뒤에서만 늘린다:

```ts
if (calEvent && !state.calendarDone.includes(calEvent.id)) {
  state.calendarDone.push(calEvent.id);
  fired = calEvent;
  if (isMeasureMode()) militaryLifeCounters.캘린더++;
} else if (!calEvent && res.eventIndex !== null && candidates[res.eventIndex]) {
  fired = candidates[res.eventIndex];
  state.cooldown[fired.id] = week;
  if (isMeasureMode()) militaryLifeCounters.뽑기++;
}
```

실제 플레이는 `__PB_MEASURE__`가 항상 false라 이 두 줄은 아예 안 돈다 —
`docs/CLAUDE.md`의 결정성 정책(「계측이 재현되는 수준까지」)을 그대로 따른다.
「통지」에 준하는 개념은 군 루프에 없다(4주 부대 소식은 조건 없이 매번
난다 — 확률 게이트가 아니라서 셀 대상이 아니다) — **못 쟀다가 아니라
없다.**

## 가설을 다시 잰 자리 — `prevMil`을 같이 리셋했더니 값을 잃었다

전후 비교를 **같은 판(같은 씨앗·성향·프리셋 — control/safe/20260802)**에서
뽑던 중, `prev`를 리셋하는 자리에서 `prevMil`도 같이 리셋하도록 짰던 1차
구현이 **군 계수기 값을 실제로 줄이는** 걸 발견했다(6판 전부에서 첫 군
줄이 캘린더1·뽑기0으로, 둘째 줄만 정상 크기였다 — `runs_102_military_v1
_undercounted_2026-09-18/`에 그 판이 남아 있다).

원인: `tierCounters`(전 무대 공통 누계)는 다른 무대의 사건이 새어 들어올
위험이 있어 리셋이 맞다. 그런데 `militaryLifeCounters`는 **군 주간 루프
안에서만 늘어나는 군 전용 값**이라 애초에 다른 무대에서 새어 들어올 수가
없다 — 그런데도 리셋을 걸었더니, **입대가 이 스킵과 같은 사이클에서 겹쳐
일어나** 이미 처리된 초반 군 주(실측 캘린더13·뽑기21)가 리셋 시점에
통째로 사라지고 다음 줄엔 자투리(캘린더1·뽑기0)만 남았다.

**대조군으로 확인했다** — 같은 씨앗(control/safe/20260802)을 셋으로 나란히:

| | 노말/레어/유니크/히든(군 줄) | 군캘린더 · 군뽑기(2029) | 군캘린더 · 군뽑기(2030) |

## 결론

- **군 24~30 안인지 — 그렇다.** 새 계수기로 잰 값은 **25.8/시즌**으로
  목표 범위(24~30) 안이며, `SIM_102_STAGE0_2026-09-12.md` 3장의 이론값
  (27.6/시즌)과도 가깝다. 「군 이벤트가 목표를 밑돈다」는 결론은 **없다** —
  애초에 잴 수가 없어서 밑도는 것처럼 보였을 뿐이다.
- **군의 tierCounters 리크는 사라졌다.** 6판 12줄 전부 노말/레어/유니크/히든이
  정확히 0이다(재현 2회 이상 · 확정) — 야드스틱 문서가 지적한 「군 줄에
  49~113이 샌다」는 원인(워커의 `prev` 미갱신)이 실측으로 확인·수정됐다.
- **못 잰 것**:
  - 군 안에서 「노말/레어/유니크/히든」에 준하는 **질적 등급 구분**은 여전히
    없다 — 캘린더·뽑기는 「무엇이 났는가」의 세기지 「얼마나 좋은 사건인가」의
    등급이 아니다. 이건 계수기가 아니라 군 콘텐츠 설계의 몫이라 이번 범위
    밖이다.
  - 표본이 6판(전부 safe 페르소나)이라 growth·lazy나 다른 씨앗에서도 같은
    25점대가 나오는지는 안 쟀다 — 다만 6판 모두(프리셋 4종·씨앗 2개) 편차가
    작다(20~34 사이 · 캘린더는 6판 전부 정확히 20으로 동일).
  - 군 도달 전 무대(고교·프로초반)의 등급 빈도는 참고용으로만 표에 실렸다

### 근거식 — 40% 게이트 하나뿐이다

체육부대는 상무(`week_engine.rs` `calc_military_week`)를 그대로 쓴다 —
계급별 스탯 변화만 다르고, 이벤트 발동 게이트는 **일반병과 같은 상수
40%**다(`calc_military_week` L795 `rng.gen::<f64>() < 0.40`, 일반병 쪽
`calc_military_life_week`의 `event_weekly_chance`도 `military/rules.json`에서
0.40). 다른 것은 **캘린더가 없다는 것 하나뿐**이다 — 일반병은 캘린더(고정
일정) 위에 40% 뽑기가 얹히고, 체육부대는 100주 전부가 40% 뽑기만 돈다.

군 시즌 하나 = 52주(다른 무대와 같은 단위 · STAGE0 3장과 같은 잣대)이므로
이론값 = `52 × 0.40 = 20.8건/시즌`. 실측 평균 **20.3**(6개 표본)이 이론값과
**2.4% 차**로 거의 일치한다 — 일반병 이론값(27.6)과 실측(28.1)이 거의
맞아떨어진 것과 같은 모양이다.

### 제안 — `seasonFreqByStage.군_체육부대.normal` 17~24

이항분포 `B(52, 0.4)`의 표준편차 `√(52×0.4×0.6) ≈ 3.53`을 이론값(20.8)
위아래로 잡았다 — `20.8 − 3.53 ≈ 17.3` · `20.8 + 3.53 ≈ 24.3`, 정수로
17~24. 실측 6개 표본(18~22)이 전부 이 범위 **한가운데**에 든다.

⚠ **제안값이다 — 일반병(24~30)과 근거의 두께가 다르다.** 일반병 범위는
12판·다수 성향(safe 위주)의 실측을 깔고 정했는데, 체육부대는 **성향
하나(growth)·씨앗 하나(20260802)·표본 6개**뿐이다. 이론식 자체는 코드에서
직접 읽은 상수(40%)라 튼튼하지만, 다른 성향·씨앗에서도 같은 폭이
나오는지는 못 쟀다. `tier_rules.json`에는 **넣어 뒀다**(사용자가 "안
움직인다"고 정한 것은 부대를 가르는 구조이지 숫자가 아니라서, 값을
비워 두면 `goalRangeOf`가 도로 전 무대 공통(30~52)으로 떨어져 실측
20.3이 다시 빨갛게 찍힌다 — 그게 이 작업 전 상태다) — 값 자체는
`BALANCE_BACKLOG.md`에도 절을 하나 남겨 사용자가 확정하기 전까지는
**제안**임을 분명히 했다.
