# 화면 붙이기 · 스카우팅 배선 계획 (2026-08-30)

**밸런스 잡기 전에 한다.** 근거 둘:

- **화면 없이 도는 기능은 밸런스를 재도 확인할 방법이 없다.** 이번 세션에
  만든 것 대부분(등록말소·웨이버·의료팀·전지훈련·명예의 전당·영구결번)이
  돌기는 하는데 플레이어가 볼 데가 없다.
- **스카우팅은 드래프트 결과를 바꾼다.** 밸런스 뒤에 넣으면 그 측정이
  통째로 무효가 된다.

점검 근거는 `scripts/audit-career.cjs`(60항목) — 기능 없음 11건 ·
**기능은 있는데 전용 화면 없음 14건**.

## A단계 — 소식으로 보이는 것 (6건)

지금 **로그로만 남고 플레이어에게 안 간다.** `autoLog`는 개발용이다.

| 기능 | 지금 | 넣을 소식 |
|---|---|---|
| 등록말소 기간 | 로그만 | "OOO 2군 등록말소 (2주간 재등록 불가)" |
| 웨이버 공시 | 이벤트만 | "OOO 웨이버 공시 → △△ 구단이 영입" |
| FA 미계약 → 원소속 재계약 | Rust 이벤트 | "OOO 원소속 재계약 · 시장에서 못 구했다" |
| 전역·복귀 | Rust 이벤트 | "OOO 전역 · △△ 복귀" |
| 캠퍼스 이벤트 | 판정만 | 그 해 무슨 일이 있었는지 |
| 프로 올스타 초청 | 판정만 | "대학 OOO, 프로 올스타전 초청" |

**⚠ 소식 id는 유일해야 한다.** 중복이 하나만 생겨도 세이브가 안 열린다.
**이미 관행이 서 있다** — 기존 소식이 `${seasonYear}` 또는 `${Date.now()}`
를 붙인다(실측). 새로 만들 때 그걸 따르면 된다. `weekNum` 만 쓰면 안 되는
이유는 시즌마다 리셋되기 때문이다.

**⚠ 소식함 상한은 500이다** — `MAX_MAILBOX`. 약 83주라 **한 시즌 반**이다.
🔴 처음엔 이 계획서에 "200통 포화"라고 적었는데 **틀렸다.** CLAUDE.md 의
낡은 기록을 그대로 옮겼고, 실제로는 2026-08-24 에 200 → 500 으로 올렸다
(트랙 B · IPC 주당 +38 KB · 화면은 60건씩 점진 렌더링).

그래도 **한 시즌에 몇 통이 오는지는 잰다** — 500 이 여유인지 아닌지는
생산량을 봐야 안다. 늘려서 기존 소식을 밀어내면 안 하느니만 못하다.

**재는 것** 시즌당 소식 수(전후) · 종류별 분포
**검사** 각 소식이 실제로 mailbox에 들어가는가 · id 중복 0

## C단계 — 명예의 전당 화면 (2건)

**유일하게 새로 만드는 화면이다.** 목록·검색이 필요해 패널로 안 된다.

    헌액자 목록      이름 · 헌액 연도 · 점수 · 소속 구단
    선수 상세        수상 이력 · 통산 기록 · 영구결번 여부
    구단별 보기      그 구단 출신 헌액자

재료는 다 있다 — `hallOfFame`(선수 id → 연도·점수·구단·번호) ·
`retiredNumbers`(팀 → 번호) · `careerHistory`(수상 이력).

**⚠ 은퇴 선수는 `npcs`에서 사라지지 않는다**(`careerStatus: "retired"`).
이름·기록을 그때 조회할 수 있다. 다만 **세이브가 커지면 느려질 수 있으니**
목록을 한 번만 만들고 캐시한다.

**어디에 둘까** — `MePage` 하위 탭이 자연스럽다. 업적이 이미 거기 있고,
명예의 전당도 "커리어의 끝"이라는 같은 성격이다.

**검사** 헌액자 0명일 때 안 깨지는가 · 결번 번호가 실제 선수와 맞는가

## D단계 — 스카우팅 잡음 배선

🔴 **`apply_scouting_noise_native`가 Rust·preload·타입까지 다 있는데
TS가 한 번도 안 부른다.** 완성된 죽은 갈래다.

그 엔진이 이미 하는 것:

    base_noise      스카우팅 품질이 낮을수록 크다
    fame_factor     명성이 높으면 정확해진다 (−40%)
    prospect_factor 유망주는 **1.5배** 부정확
    age_factor      28세 이상 0.80 · 22세 이하 1.20
    seed_base       선수 id + 팀 + 연도 해시 — **결정적이다**

### 지금 구조가 막는 것

`runDraftSimulation`이 `candidates`(진짜 값) 하나를 받고 **전 팀이 그
목록을 공유한다.** 팀마다 다른 눈으로 볼 자리가 없다.

### 어떻게 바꾸나

1. 드래프트 순번마다 **그 팀의 스카우팅 뷰**로 후보를 평가한다
2. 뷰는 `applyScoutingNoise(팀 성향, 후보)` 한 번으로 만든다 —
   결정적 해시라 같은 팀·같은 해면 늘 같다
3. **지명은 뷰로, 실제 능력은 진짜 값으로** 들어간다 — 그게 이 기능의 요점이다

**⚠ 성능**: 팀 10 × 후보 200 = 2,000건을 드래프트마다 만든다.
한 번에 한 팀씩 만들고 버린다 — 전부 들고 있으면 메모리가 는다.

**⚠ 밸런스 파급**: 지명 순서가 바뀐다. 상위 지명자의 평균 OVR이 내려가고
하위에서 대박이 나온다. **전후를 반드시 잰다** — 그게 이 기능의 목적이다.

**재는 것** 라운드별 지명자 OVR 분포(전후) · 팀별 스카우팅 품질과 지명 성공률
**검사** 같은 씨앗·같은 팀이면 같은 뷰가 나오는가(결정성) ·
스카우팅 95인 팀이 5인 팀보다 잘 뽑는가
