# 이주 작업 큐

**위에서부터 하나씩.** 모듈 하나를 끝낼 때마다 여기 체크하고 커밋한다.

⚠ **이 파일이 이어달리기의 바통이다.** 세션이 끊기거나 컨텍스트가 요약돼도
여기만 읽으면 정확히 이어진다. `RESUME.md`는 **왜 그렇게 했는지**를 적고
여기는 **무엇이 남았는지**만 적는다.

## 모듈 하나의 리듬 (건너뛰지 않는다)

```
① 02 원본을 읽는다        — 값과 근거를 그대로 옮긴다. 밸런스 동결
② 검사를 먼저 쓴다
③ 빨간불 확인            ← 통과하면 그 검사가 아무것도 안 보는 것이다
④ 로직을 옮긴다
⑤ 배선한다               — 안 부르면 없는 것과 같다 (02가 그 결함투성이)
⑥ 실측한다               — measure:*  세계로 굴려 본다
⑦ 변이 검증              — 100% 아니면 검사를 보강한다
⑧ 전체 검사 · 고아 0
⑨ 화면을 바꿨으면 띄워서 본다
⑩ 커밋 · 이 파일 갱신
```

## 막혔을 때 — **멈추지 않는다. 적어 두고 다음으로 간다**

**02가 완제품이라 답은 거의 다 거기 있다.** 값·순서·근거가 커밋 메시지와
주석에 적혀 있으니 물을 게 없다. 그대로 옮긴다.

### **02를 실제로 돌려서 물어본다** — 문서에 없어도 답이 나온다

**02는 죽은 코드가 아니라 살아 있는 대조 장치다.** Rust 엔진이 이미 빌드돼
있고(`engine-native.win32-x64-msvc.node`) `node_modules`도 있어서, Electron
없이 `npm run ...`이 그대로 돈다:

```bash
cd 02.SvelteElectron
npm run test:fa · test:growth · test:draft · test:promotion · test:career
npm run measure:draft · measure:devplayer · measure:training · measure:relations
npm run test:rosterbalance · test:npclifecycle · test:careerpaths
node -e "const d=require('./resource/data/master/players/generation_rules.json'); ..."
```

⚠ **읽기만 한다.** 돌리는 건 소스를 안 바꾼다 — 로그·임시 DB만 쓴다.
02 파일을 **고치지는 않는다.**

실제로 이렇게 값 셋을 추측에서 실측으로 바꿨다:
`developmentPlayerRules.intakeMax` 10 · `salary` 2000 ·
대학 한 해 정원 = `rosterSize / gradeMax` = 8.

02를 돌려도 답이 안 나올 때만 아래에 ❓로 적고, 제일 그럴듯한 값을 골라
**근거를 주석에 남긴 뒤 계속 간다.** 멈추면 루프가 죽는다.

02에 답이 없는 부류는 셋뿐이다:

1. **04가 02와 다르게 정한 것의 파생** — 일 단위 진행 · 해외 풀 시뮬 ·
   1440×900 가로. 02엔 대응물이 없다
2. **02의 명백한 결함** — 그대로 옮길지 고칠지는 밸런스 판단이다.
   **기본은 그대로 옮기고 검사로 못 박는다**(대조가 깨지면 안 되니까)
3. **성능 게이트** — 02는 Electron이라 기준 자체가 다르다

### 묻어 둔 질문

- ❓ **관계 기억(`memories`)을 각인하는 곳이 아무 데도 없다 — 02에도 없었다.**
  02의 `addRelationMemory`는 호출자가 **0개**이고, 그런데도 `PeoplePage`는
  기억 목록을 그렸다(영원히 빈 목록이었다). 04도 `RelationshipRunner.add_memory`
  를 검사만 부른다. **인물 화면에서 뺐다** — 아무도 안 쓰는 데이터를 그리는
  자리를 만들면 죽은 갈래가 된다. 각인 시점(데뷔전·완봉·방출·배신)을 정하는
  건 설계 결정이라 이주 중에 만들지 않는다. 정하면 그때 화면에 붙인다

- ❓ **해외 팜 리그 연봉 배수**가 02에 없다. 국내 1군:2군 비(0.3배)로
  파생했다 — `data/salary_rules.json`. **02는 해외 팜 연봉을 아예 안 만든다**
  (`leagueMult`에 항목이 없다). 돌려도 답이 안 나오는 부류다

- ❓ **수비 훈련(`defense`)에 대응하는 코치 영역이 없다.** 02
  `relationship_rules.json`의 `training_area`가 11종을 잇는데 `defense`만
  빠져 있다 — 수비 훈련을 짠 주는 **어느 코치도 안 오른다.** 02 그대로
  옮겼다. 스태프(B-2b)에 수비 코치가 있는지 보고 다시 판단한다

- ❓ **02의 독립리그 지망 순서가 주석과 코드가 어긋난다.** 주석은 "위로
  지원할수록 조금 어렵다"인데 코드(`cut = min_ovr - penalty`, `penalty =
  [0, -2, -4]`)는 **뒤 지망이 더 어렵다.** 밸런스 동결이라 코드 쪽을 옮기고
  검사로 못 박았다(`career_path_test.test_a_later_choice_is_a_little_harder`)

- ❓ **04 학사엔 석차백분율이 없다.** 02는 석차→9등급과 석차→학점 두 표를
  따로 뒀는데 04는 학점만 만든다. 두 표를 합쳐 **학점→등급** 하나로 뒀다 —
  값은 02 그대로다(4.5→1 · 4.2→2 · … · 1.5→8). 석차 표를 그대로 옮기면
  아무도 안 먹이는 죽은 코드가 된다

- ❓ **주인공 지명률이 NPC 실측보다 높다.** 02 앵커는 "고교 3학년 투수
  4,805명 중 고졸 지명 327명 = 6.81%"인데 `measure:career` 60커리어에서
  **17%**가 나왔다. 주인공은 `World.new_game`이 만드는 사람이라 또래
  분포의 가운데가 아니다 — 산식은 NPC와 같은 것을 쓰므로 **밸런스가 아니라
  생성 분포의 문제로 본다.** 이주 후에 주인공 생성 분포를 잴 때 다시 본다

- ❓ **해외 리그 선수 이름이 한국식이다.** 02는 용병 이름을 서양식 풀
  (`namePool.western`)로 만들었는데 04의 `NameGen`엔 그 갈래가 없다 —
  ABL·JBL 선수도 한국 이름을 달고 있고, 영입하면 KBL에 한국 이름의
  "외국인"이 생긴다. 국적·출신은 기록에 남으니 판정은 맞지만 **화면에서
  어색하다.** 이름은 C(화면)에서 같이 본다

- ❓ **라이벌을 누가 지정하나.** 관계 엔진에 라이벌 갈래가 다 있는데
  (성향이 부호를 가르는 것까지) **04에 라이벌을 정하는 경로가 없다** —
  `faced_rivals`가 늘 빈 목록이다. 02는 `named_npc_registry.json`과 대회
  맞대결에서 왔다. B-4(대회)에서 붙는다
