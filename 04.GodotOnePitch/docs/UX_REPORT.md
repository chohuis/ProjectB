## 제안 — **쪼개지 말고 틀을 넓힌다**

합치기 자체는 옳았다. 네 갈래가 합쳐서 좋아졌다. **예/아니오 틀이 협상
한 종류에만 안 맞는 것**이다.

```
지금:  {type, title, body, choices[], kind: "one"|"many", submit_label}
제안:  kind에 "negotiate"를 하나 더한다
       → 슬라이더 하나 · 토글 몇 개 · 실시간으로 갱신되는 요약 줄
       → 제출할 때 고른 값을 id에 담아 올린다 ("many"가 이미 그렇게 한다)
```

`decision_screen.gd:63-65`가 이미 그 길을 열어 뒀다:
> 여러 개를 켜고 한 번에 낸다. **고른 것을 id에 담아 올린다** — 화면이 상태를
> 들고 있지 않게 하려는 것이다

- **분류**: **동결 해제 후**
- **왜**: 슬라이더가 움직이는 범위(±20%)와 수락 임계값이 **밸런스 수치**다.
  02는 `effectiveOffer * 1.15`에 옵션마다 ±3~10%를 곱한다
  (`ContractNegotiationModal.svelte:67-75`). 그 표를 04로 옮기는 순간 동결을
  건드린다
- **손질 범위**: `decision_vm.gd`에 `_salary` 확장(+40줄) ·
  `decision_screen.gd`에 `_build_negotiate`(+50줄) · 임계값 규칙 파일 하나 ·
  `sim/`에 수락 판정
