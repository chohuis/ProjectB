# 변이 검증

로직을 일부러 깨뜨려 **검사가 그걸 보는지** 확인한다.
"검사가 통과한다"와 "검사가 그걸 본다"는 다르다.

```bash
node tools/mutation/mutate.cjs sim/<모듈>.gd test/<모듈>_test.gd tools/mutation/mut_<모듈>.json
```

변이 목록은 `["설명", "원래 문자열", "바꿀 문자열"]` 셋으로 된 JSON이다.
모듈을 고치면 **목록도 같이 고친다** — 안 붙은 변이가 있으면 스크립트가
크게 알리고 종료 코드 1을 낸다.

## 이 도구가 네 번 거짓말했다

넷 다 "전부 검출"이라고 보고했는데 실제로는 아무것도 안 보고 있었다.
고칠 때마다 그때까지의 결과를 **전부 다시 돌렸다.**

**① ANSI 색** — Godot이 요약에 색 코드를 섞어 낸다. 안 벗기면 정규식이
안 맞아 "파싱 실패"가 되고, 그게 전부 "잡힘"으로 세어졌다. 첫 실행의
7/7이 가짜였다.

**② 쓰기→실행 경합** — 파일을 쓰자마자 Godot을 돌리면 옛 내용을 읽는
때가 있었다. 같은 변이가 실행마다 잡히기도 안 잡히기도 했다. 손으로 넣고
4번 돌리면 4번 다 잡히므로 Godot이 아니라 이쪽이었다. 지금은 mtime을 밀고
내용을 되읽어 확인하며, "못 잡음"은 검사를 약하게 만드는 방향이라 한 번 더
돌려 굳힌다.

**③ CRLF** — `git checkout`이 파일을 CRLF로 되돌리자 여러 줄짜리 변이가
전부 안 붙었다. 28건 중 20건이 건너뛰어졌는데 요약은 "8/8 검출"이었다.
지금은 LF로 정규화해 맞추고, 안 붙은 건수를 요약에 크게 적는다.

**④ 고정 상한** — 상한이 90초 고정이었는데 `app_root_test`가 **6분 19초**였다.
원본조차 상한을 넘으니 **모든 변이가 "잡힘(멈춤)"으로 세어졌다** — 배선
변이 6건이 전부 가짜였고, 검사를 보강하고 다시 재니 실제로는 4/6이었다.
검출률이 높게 나올수록 의심할 이유가 없어져서 그냥 넘어가게 되는, 제일
나쁜 형태다. 지금은 **원본을 먼저 재고** 상한을 그 세 배로 잡는다.
원본이 실패하거나 20분을 넘으면 아무 판정도 하지 않고 종료 코드 2를 낸다.

## 무한 루프를 만드는 변이가 있다

순환 참조 가드를 빼면 검사가 **실패하는 게 아니라 안 끝난다.**
멈춤도 검출로 세되, 상한은 원본 실행 시간에서 정한다(위 ④).

## 변이가 안 잡히면 셋 중 하나다

1. **검사 표본이 그 분기를 안 건드린다** — 제일 흔하다. 능력치를 묶어서
   보거나, 문턱보다 한참 아래 표본을 쓰거나, 이미 다른 항으로 문턱을
   넘고 있거나
2. **동등 변이** — 고쳐도 동작이 진짜 같다. 변이 쪽을 바꾼다
3. **진짜 구멍** — 검사를 더한다
