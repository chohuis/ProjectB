## 절대 금지

### 화면이 계산을 갖지 않는다

화면은 **`ViewModel` 사전 하나**만 받고 표시만 한다. 스토어를 직접 읽지 않는다.

⚠ 이전 프로젝트 결함 상당수가 여기서 나왔다 — 수상 집계가 결산 모달에만
있었고, 드래프트 보드가 자기 후보 풀을 따로 만들었고, 경력 기록 조립이
모달 안에만 있었다. **전부 "화면이 계산을 갖고 있어서"** 생겼다.

부수 효과로 화면이 게임 상태 없이 뜬다 — 검사가 가짜 사전으로 띄우니 싸다.
`status_screen_test.gd`가 소스에서 `sort_custom`·`filter(`를 막는다.

### 골격은 씬(.tscn)이 정본이다

배경·스크롤·탭 컨테이너는 `.tscn`에 있다. 스크립트는 **카드만 만들어 붙인다.**
레이아웃을 코드로 다시 짜면 씬을 만든 의미가 없고 에디터에서 빈 화면이 된다.

부품(`ui/parts/*.tscn`)은 `preload(...).instantiate()`로 쓰고 값은 `setup()`으로
넣는다 — 화면이 색을 직접 고르지 않게 하려는 것이다.

### 난수는 `Rng`를 거친다

`randf()`를 직접 부르지 않는다.

```gdscript
r.value_for(["player", id, "potential"])   # 해시 기반 — 호출 순서와 무관
r.stream(["game", game_id])                # 흐름 기반 — 경기 하나가 한 덩어리
```

⚠ **이전 프로젝트는 재현이 안 됐다.** Rust 엔진이 `thread_rng()`를 30곳에서
썼고 시드 기반은 26곳뿐이었다. 경기 엔진이 전자라 **같은 세이브·같은 시드라도
결과가 매번 달랐다.** 시드 기반 조사를 한다면서 절반만 그랬다.

**전역 흐름 하나만 두지 않는다.** 난수 호출을 하나 추가하는 순간 그 뒤가 전부
밀린다 — 이주 내내 코드를 고칠 텐데 그러면 회귀를 못 잡는다.

### 색·여백을 화면에 직접 적지 않는다

`AppTheme`에서만 가져온다. 화면 55개에 색을 흩으면 톤을 바꿀 때 다 찾아다녀야
하고 반드시 몇 개는 빠진다.

## 성능 규칙 (P0에서 실측으로 정함)

시즌 시뮬 2,124경기가 0.659초다. 그 여유는 이 규칙들 위에 있다.

- **가변 상태로 쓴다.** 원본 Rust는 투구마다 `state.clone()`을 하는 불변
  방식인데 GDScript에서 그대로 하면 그것만으로 죽는다
- **정적 타입 전면** (`var x: int`) — 타입을 적으면 실측으로 빨라진다
- **루프에서 객체를 만들지 않는다.** 선수는 `PackedFloat32Array`, 주자는 bool
  셋. `RefCounted` 할당이 GDScript의 주 병목이다
- 결과 코드는 enum이 아니라 int — 비교가 잦은 자리다

## NPC 상태는 열 배열이다

`NpcStore`가 능력치를 **열마다 배열 하나**로 갖는다. 실측(NPC 9,603명):

```
사전 배열 + store_var   저장 0.059초 · 6.3MB
열 배열 + zstd          저장 0.007초 · 1.1MB
이전 Electron           저장 1.1~1.65초 · 18MB
```

저장만의 이야기가 아니다 — 매주 9,603명을 순회하는 코드가 많은데 그쪽도 같이
빨라진다.

⚠ **열 배열의 위험은 성능이 아니라 실수다.** 열 하나를 빠뜨리거나 길이가
어긋나도 오류가 안 나고 조용히 틀린 값을 준다.

- 열 목록(`FLOAT_FIELDS`/`INT_FIELDS`)이 **정본**이다. 열 추가는 거기만 고친다
- 열 순서를 바꾸지 않는다. **뒤에만 추가한다** — 옛 세이브가 깨진다
- 헤더에 **저장 당시 열 개수**를 적는다. 그래야 열이 늘어도 옛 세이브가 안 밀린다
- `verify()`가 길이 어긋남을 잡는다

## Godot 함정 (겪은 것)

- **`Control`을 `Window`에 직접 붙이면 앵커가 자동으로 안 먹는다.** 루트가
  0×0으로 남아 회색 판만 찍힌다 — 안쪽 컨테이너는 멀쩡해서 더 헷갈린다.
  씬으로 만들면 안 겪는다
- **스크린샷은 헤드리스로 못 찍는다.** 창을 띄우고 프레임을 돌린 뒤
  `RenderingServer.force_draw()`를 불러야 한다
- **정수 리터럴이 2⁶³을 넘으면 파싱이 실패한다.** FNV-1a의 표준 상수
  `0xcbf29ce484222325`가 그렇다. 오류가 콘솔에만 나고 값은 나와서 조용히 넘어간다
- **`PackedStringArray`엔 `filter()`가 없다.** `Array`와 다르다
- 새 `class_name`을 만들면 `--import`를 한 번 돌려야 다른 스크립트가 찾는다

## 검사

- 프레임워크는 **GdUnit4** (`addons/gdUnit4/`). Godot 4.5~4.7 지원
- **변이 검증을 한다.** 검사를 만들면 일부러 깨뜨려 잡히는지 본다 —
  이 저장소에서 "통과하는데 아무것도 안 보는 검사"가 실제로 여러 번 나왔다
- **소스 문자열 검사로는 못 잡는 게 있다.** 로테이션 인덱스가 `teamGameCount`
  자리로 들어가 버려진 결함은 인자 자리가 바뀐 것이라 문자열은 그대로였다.
  그런 건 **실제로 함수를 불러서** 본다

## 폰트

Pretendard 1.3.9 · OFL 1.1 (`fonts/OFL.txt`). Regular + SemiBold.

⚠ **OFL은 라이선스 전문을 같이 배포하는 게 조건이다.** 파일이 빠지면 위반이다.
검사가 그것과 "시스템 폰트로 안 떨어졌는지"를 본다.

서브셋을 안 했다 — 선수 이름을 무작위로 만드는 게임이라 드문 글자가 나올 수
있다. 3MB는 Steam 배포에서 문제가 안 된다.

## 이주 원칙

- **검사를 로직보다 먼저 옮긴다.** 검사 53개에 비싸게 배운 게 박혀 있다.
  안 옮기고 로직부터 쓰면 같은 결함을 다시 만든다
- **화면은 지금 구조 그대로.** 픽셀이 아니라 구조를 맞춘다
- **막히면 멈추고 묻는다** — 설계 결정·밸런스 수치·화면 구조 변경·게이트 실패
- 이주 중 **기능 추가 없음.** 움직이는 목표를 따라가면 안 끝난다
